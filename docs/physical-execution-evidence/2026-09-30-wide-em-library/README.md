# 宽矩阵 EM：复用 Eigen 的保序特征更新

2026-09-30，本地未提交实现。基线 `02aa13cbd8bfd0b881814a36af11304be8288261efc6e6e1d0a9bcb493c0f8f1`，最终构建 `146cd294a29a431e6ef82be35f549ba89e3573a68753a686c25407bdac288e84`。这批宽矩阵有实测收益，**不代表全引擎时间与内存验收完成**。

## 实现与审核

将已有 GMM/HMM M 步的固定 Eigen Map 扩展到32/64/128/256维。准入仍为 macOS15+ arm64、Eigen3.4、非scalar、至少32行、特征stride=1。复用已有模型输出作累加器，逐观察的累加顺序和 `(weight*delta)*delta` 保持不变；没有新算子、输入打包、数值堆、线程或跨请求缓存。其他宽度与布局保留原路径。

首版直接内联令公共latent栈帧增加112B，因而没有作为最终版本。最终版单独承载宽矩阵分支，公共帧恢复1088B，新均值/方差函数为224/160B；既有density函数已占224B，所检查数值链的自有帧峰仍为1312B。正式对象与临时审核对象逐字节相同，新函数有NEON双精度乘加指令、无FMA。系统数学库、异常与外层栈未完整定界，不能将该数字称为全请求栈峰。详见[设计](production-design.md)、[对象审核](object-review.md)。

签名、数学策略、AST/DAG、Planner、错误隔离、IPC、输出所有权及Excel公式/预算不变。使用说明仅更新执行指南和物理优化状态；算子参考、发布协议与AGENTS不需要改写，因为没有公开契约、依赖、平台范围或纪律变更。

- 185原语回放通过；源码、wheel、安装扩展/worker身份一致。469组/3056值与历史真实Microsoft Excel16.89.1快照一致，**没有新的Excel重算**，该历史小尺寸快照不单独证明宽矩阵路径。
- 原phase2严格门禁 **4/4**，未改阈值：500/1000产品比值0.7524/0.7548；63/252点ordinary比值0.9644/0.9692。前轮失败仍保留。

## 内存与剩余事项

固定8项大矩阵ordinary、48独立heap/RSS子进程，六阶段七个跟踪heap字段新旧逐项相同。冷/暖堆峰较NJIT低约20%–48%；所有样本请求RSS增量及总RSS峰也低于NJIT。**相对旧C++的完整内存不增仍未通过**：请求RSS7/8未增，HMM8192×256增加65,536B；总RSS5/8为正，最大+8,519,680B，测量前RSS基线亦不同，不能混用两种口径。堆持平与自有栈峰持平不替代RSS结论。

普通探针每个C++子进程有5次表外释放、无表溢出。另4个诊断子进程覆盖GMM/HMM的新旧版：全部为测量前epoch0的4×16B+1×32B，未见未知来源；分配PC为实际NumPy二进制偏移`0xdd3fc/0xdf748`，释放PC为`0xc5abc`，与维度/stride缓存的本地反汇编对应。它解释96B计数，不解释MiB级RSS差；诊断探针有大型静态表，数据不得用于时间/RSS验收。并非所有Python/NumPy子分配都由malloc探针覆盖。

全引擎目标、F布局稳定性、完整RSS不增及此前矩阵分解等欠项继续开放；没有提交、推送或修改研究平台。

- 宽矩阵首版148条常规、204条停止记录逐位一致且有明显收益；正式V1虽通过回归/门禁，仍因公共栈增量转为V2。两版与全部失败证据保留。
