# Jacobi候选自审核与后续边界

本轮是隔离候选筛选，没有更改生产C++/Python、公开签名、Planner或Excel。开始时1703个既有文件的SHA保持不变，新的候选只存在归档与临时实验目录。核对AGENTS、D1-D8、X1-X10并先使用CodeGraph导航；CodeGraph未命中新helper时才读取具体源码。

## 已验证

- 第一族将同一i下特征向量旋转延迟到矩阵更新之后。旋转参数不依赖特征向量；每个特征向量元素仍按原j顺序使用同一公开Eigen JacobiRotation。三种固定宽度8/16/32，真实c/s工作区为2N doubles。
- 第二族将私有上三角工作区按4/8/16/32阶块存放。每个矩阵位置唯一映射；prefix/middle/tail三个区段仍覆盖原k范围，局部两行块先完整读取再写回，解决不同stride间的别名风险。对角padding不作为数学数据读取。
- 两族各59组完整输出/失败内容逐位对照通过，覆盖原packed与未准入尺寸、C/F/补边/负stride、退化/重根、巨大/极小尺度、NaN/Inf/非对称、1或32 sweeps及阈值邻域。两族分别236/295次原生调用（含各自基线）；并非同等数量独立数据集。只读输入哈希、输出边界哨兵、实际工作区与缩放复制数同时检查。
- 数值原型通过真实prepare/execute ABI，基线链接最新生产static archive，候选只覆盖matrix_foundation TU。编译采用现有Eigen3.4、O3、no-fast-math、ffp-contract=off；没有私有线程、Python数学回调或请求期编译。
- 旋转audit计数记录实际库调用：分块会增加调用次数，不能强制与旧版相同；缩放复制仍按实际N(N+1)/2计算，不包含c/s写入或块padding。
- 第一轮构建的Map临时写法触发C++ vexing parse，改为具名Map后编译。原错误日志与初始候选源码保留。这是实验构建错误，未进入生产。

## 不采用的依据

完整ABI输出的128/256/512/768/1024阶全部计时配置保留。第一族4轮轮换，第二族5轮轮换；相同单CPU预算、相同输入、预热一次、输出预分配且每次写完整结果，时间与构建/其他数值测试串行。128是未准入控制，不计为库收益。不能把该ABI时间冒称普通Scheduler或NJIT验收。

1024阶第一族最好的32列块仍约5.448秒，基线5.178秒；第二族最好的4阶块约6.336秒，基线5.237秒。其余大规模同样没有明显收益。拒绝依据是未取得大负载收益和部分显著时间退化，不是几KB工作区增加或微小时间差。

因没有候选值得采用，未继续运行全量Python、ASan或完整Scheduler/NJIT/冷暖heap/RSS。工作区和哨兵不能冒充完整内存验收；既有生产回归属于上一EM阶段。Excel算法、预算和公式均不变，本轮未运行新重算或历史快照复比。

## 下一步：完整计算链的大矩阵缓冲

已定位graph.cpp的deferred_to/fused_from、plan_array_arena、独立root输出，以及现有covariance和cholesky核。考虑只消费一次、非公开根、输入保持有效的covariance→cholesky，把协方差直接写入消费方独占C缓冲并在其中完成分解。4096² float64的一份矩阵为128MiB；这是按shape计算的潜在节约，不是测量结果，也不代表已实现。

采用前必须解决：

1. 只处理可证明独占的临时值，排除共享消费者、观察器和不兼容错误模式；逻辑DAG及Excel步骤保留，不新增业务黑盒。
2. 现有Cholesky行面板在失败时会从原输入重放。原地覆盖会破坏原输入，不能直接开启别名。必须设计保持同一错误优先级的恢复路径，例如重新计算纯生产者并执行原canonical顺序，且不得吞资源/结构异常。
3. 检查普通、prepared借用/独立快照、线程/进程/共享、显式C/F输出及内部scope；确认失败时哪些缓冲可被观察，不能以结果最终抛错为由静默修改已有所有权或失败契约。
4. Arena消除、Planner预算与容量释放必须一致；输入、公开协方差根、旧独立结果不得被改写。原生库内核继续复用，不能为了复用缓冲退回显著更慢的计算路径。
5. 先做完整链位模式、错误与所有权对照，再测完整Scheduler时间和冷暖heap/RSS；不预先宣布128MiB已经省下。

整体所有算子目标仍开放，后续不是继续围绕无收益的Jacobi块宽微调。
