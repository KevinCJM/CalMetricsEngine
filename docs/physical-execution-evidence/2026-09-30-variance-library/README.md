## 完整请求时间

同CPU预算1，旧/新/NJIT各独立进程，6种执行次序重复2遍；调用内物化全部输出并保留上一份结果。标准化包括标准化矩阵、均值和尺度三个输出。34个初始用例完整保留，不删除控制项；统计以配对轮次bootstrap。见 [完整数据](public-summary.json) 和 [表格](public-summary.md)。

9项中大型C布局普通入口方差，配对耗时比旧版减少 **6.3%–39.6%**，比NJIT减少 **35.9%–77.9%**；每项的单侧95%上界小于1。32768×128方差：旧版 **7.054ms**、新版 **5.351ms**、NJIT **20.408ms**。

完整标准化32768×128：**16.508→14.901ms**，NJIT **45.342ms**。但其他标准化用例并未全部改善：初轮2048×64/2048×9的总体中位数回退，部分小中型仍慢于NJIT；不能把内核收益视为整图全通过。

F布局标准化初轮 **10.007→13.323ms（约+33%）**，该布局未准入新库。3轮新进程完整复测的新/旧比依次约 **1.202、0.885、1.118**，两轮仍较慢；控制退化及其原因**未关闭**。2048×64的3轮复测均改善，2048×9仍有1轮回退，保留所有初始与追加记录，见 [追加复测](followup-summary.json)。不将未进入新内核的波动归因于已证明的库收益或缓存原因。

原phase2严格门禁 **3/4**：63点普通Scheduler **4.500µs / NJIT 4.458µs = 1.009**，比原门槛1.000高，保留失败。绝对差约0.042µs符合用户允许的小任务微小劣化，未修改严格门槛。

## 内存与未闭环事项

6用例/36新进程的6阶段、7字段跟踪堆数据旧/新全部相同；没有表溢出。方差的冷/暖堆峰仍分别比NJIT多13,510/13,856B；标准化也仍有框架固定开销，因此不声称内存优于NJIT。

4个独立诊断进程定位代表性表外释放：方差2×16B，标准化5×16B，均为测量前已记录的NumPy分配；未见未追踪来源，分配/释放PC位于NumPy维度与数组释放例程。该诊断只解释这些计数，不解释MiB级RSS差；诊断探针不参与正式时间/RSS结论。

本轮只是局部算子优化，全引擎性能目标、F控制稳定性、RSS与NJIT框架开销仍开放。变更仅本地，未提交/推送。
