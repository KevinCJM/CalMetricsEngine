# 独立协方差 F 根直写

## 设计与准入

对照为上一轮正式 wheel：构建 `ac5da987ed48dcf6647098345618c02cf7d2fa1a82abedfcf90c721ecf9e5021`，身份及原始证据保留在 [DSYRK 集成验收](../2026-10-01-covariance-syrk-integration/README.md)。本轮只处理明确要求 F 的独立协方差根，消除一份 D×D C arena 和最终整矩阵转换；4096 维对应 128 MiB。

- 数学依据 D1/D2：单参数矩阵 covariance 的唯一 canonical 实现计算上三角，最后逐值镜像到下三角；DSYRK 准入成功、局部重放、全量 canonical 重放及全正零分支同样完成镜像。成功结果两侧 double 位模式完全相同，包括 NaN 载荷与有符号零。相同方阵的 C 物理字节因此已经是同一逻辑矩阵的 F 物理字节。
- 执行边界 D5/D6：typed、float64、rank2、仅一个根、该根为单参数 covariance、无消费者、无 apply/rolling scope、非错误隔离。沿用原有独立协方差准入谓词。自动布局仍为 C；不改变 direct API，也不扩展到 correlation 或其他方阵。
- 原生写入：Program finalize 保留 F 根的独立结果目标；Planner 与 Scratch 从同一 metadata 排除其 arena。算子仍收到 C Output，写入本次独立 F 结果的实际所有者，完成后才公开 F strides。结果未发布前的 C 描述不供其他节点消费；失败保留原异常，不发布半写入结果。
- 不新增算子、数学实现、序列化字段或进程协议。原生解码/pickle 重建 metadata；既有 F order、byte strides、结果所有权与 IPC 17 承载同一公开结果。observer 继续执行原 canonical 内核，读完成镜像后的实际 F 描述；不改变被观察的逻辑值或 Excel 展开步骤。
- 输入、区间、参数绑定和 prepared 快照行为不变。中间算子的真实 arena、必要候选 panel 与原生库保守预留不消失；只排除独立协方差根的冗余矩阵。多输出、下游比较、错误隔离与作用域继续原有预算和物化路径。

## 验收计划

先核验 canonical/DSYRK 分支、C/F 输入、NaN/Inf/溢出/负零/负 stride、空列/单列/样本不足、pickle、线程及两种进程传输、prepared 重执行与结果独立寿命。额外检查 root_copy_bytes=0、numeric_arena_bytes=0、direct_output_bytes 与输出容量一致，并保留非准入路径的预算回归。

按 D8 对照原正式 wheel、新正式 wheel 和 warmed 单核 NJIT，均返回独立 F 输出；NJIT 参考函数真实调用 `np.asfortranarray(np.cov(x.T))`，不靠错误改标签规避必要成本。普通入口、prepared 快照分别计时，保留上一结果；输入布局 C/F、正常/正零/放大/高相关失败样本和微小任务均保留。malloc 追踪与 RSS 分别在新子进程测量，并记录导入/JIT/vendor cache 等盲区。

X1/X9/X10：本轮仅改变已证明对称方阵的物理目标和结果描述，不改变数学 DAG、公式或预算展开；仍复核 Excel 观察器、历史重算快照与本构建输出的一致性。历史快照比较不称为新的 Microsoft Excel 实际重算。

4096 阶普通入口比上一轮再少约 22%–23% 时间，比同核数 NJIT 少约 33%–37%。prepared C/F 为 **534.106/510.231 ms**，对应上一轮 **684.261/677.297 ms**。不能把收益外推到其他算法、更多 CPU 或默认 C 输出。

## 内存与采用结论

正常数据 40 个 fresh child 分别测两个规模、两种输入布局、五个后端及 heap/RSS。分配 epoch 内的冷/暖申请堆峰值如下；普通与 prepared、C/F 输入结果只差少量框架字节，单位 MiB。

| 规模 | 上一轮 C++ 冷 / 暖 | 本轮 C++ 冷 / 暖 | NJIT 冷 / 暖 |
| --- | ---: | ---: | ---: |
| 2048 | 108.054 / 140.055 | 76.054 / 108.055 | 102.000 / 134.000 |
| 4096 | 278.101 / 406.101 | 150.101 / 278.101 | 390.000 / 518.000 |

2048/4096 的冷暖峰各减少约 **32/128 MiB**，对应全部冗余根矩阵，而非数 KB 的微调；4096 比 NJIT 申请堆峰值少约 **240 MiB**。必要输出、候选 panel 和框架均保留在 epoch；输入/导入/JIT 在 epoch 前，vendor 已存缓存、mmap、栈和 pymalloc 内部不完整覆盖，不把它称为全部物理内存。

另有 20 个全正零2048阶 fresh child：旧包冷/暖约 **64.008/96.008 → 32.008/64.008 MiB**，NJIT **102.000/134.000 MiB**；普通/prepared、C/F均保留。合计60个子进程，无探针表溢出；[正常数据](memory/memory.json)和[全正零](memory-zero/memory.json)同时归档，不用良态 panel 结果代替无 panel 路径。

4096 普通 C/F 的 RSS 总峰值 **598.891/592.766 → 470.547/464.453 MiB**，prepared **599.203/599.484 → 469.953/471.266 MiB**；与删去一份矩阵一致。但普通 C 的暖请求 RSS 增量 **134.219 → 146.094 MiB**，NJIT **128.016 MiB**，该维度仍未领先；普通 F 增量 **128.031 → 134.125 MiB**，也保留退步。不同运行时的总 RSS 含不同导入/JIT 基线，不能用其较低值代替公平的数值增量优势。

[内存汇总](memory-summary.json)及 fresh child 原始数据分别保存探针、RSS 基线/总峰/增量与 idle 对照。探针控制测试通过，哈希记录在 [工具身份](memory-tool-identity.json)。本轮可采用有实测大额收益的 F 根直写；放大/高相关时间、请求 RSS 增量及其他矩阵算子仍有欠项，**全引擎性能目标未完成**。
