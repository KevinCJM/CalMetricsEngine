## 设计与采用范围

仅优化既有 macOS15+ arm64、Eigen、至少32行/8列、F连续或补边非重叠列、有限且在原溢出界限内的一参数协方差/相关矩阵。固定8列公共 Eigen Array 并行计算 Welford 均值；固定2×2列对共享4观测包的加载/中心化，使用公共 head/tail/sum 保留原 Eigen3.4 两包归约分组。没有调用私有 Eigen API、手写 ISA、FMA 或倒数替换。

均值复用独立输出最后一行；上三角完成后仍由原逻辑归一化/镜像。小样本、特殊stride、非有限、极值、scalar、其他平台及Eigen-OFF保持原路径。未增加数值heap、打包矩阵、私有线程、跨请求缓存或隐藏Python计算。公开算子、AST/DAG、Planner、IPC、结果所有权及Excel公式/预算不变。规划与实现依据见[设计](production-design.md)。

## 内存边界

36项覆盖、216独立heap/RSS子进程。六个跟踪阶段的七项heap字段，旧/新逐项相同；24项中大型冷/暖heap峰低于NJIT，12项微型高于NJIT。12个联合请求仍存在相同的epoch表外释放计数 `[0,0,1,4,5,5]`，计数相同不证明未知字节相同；不能称完整分配审计无遗漏。

实际arm64对象已知数值调用链：F快路径 **672→624B**，F回退 **768→736B**，C保持 **656B**。均值有真实向量除法，列对观察循环无栈访问/调用/FMA；32B浮点ABI保存不是数值workspace。该口径排除系统/异常路径及绑定等上游栈，不是整个请求峰。[对象证据](production-object-evidence.json)。

对旧版RSS总峰19/36正向，最大+3,604,480B；请求增量19/36正向，最大 **+3,342,336B（3.1875MiB）**，发生于未改数学路径的512×256补边C联合请求。不能据此直接认定代码泄漏，也不能把正差一概抹为噪声；完整RSS不增仍未证实。对NJIT总RSS峰36项均低，但请求增量仍有12项高，两种口径不可混用。

另有42子进程诊断针对**前一轮6ff48→63090**原+4MiB问题，非本轮最终构建的验收。分配器区/VM/外部RSS对齐，但只能支持驻留/分配器状态相关假说，未定位因果或unknown-free分配站点。[诊断边界](rss-diagnosis-summary.md)。
