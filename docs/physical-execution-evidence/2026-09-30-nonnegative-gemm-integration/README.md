# 非负域 MatMul 原生库接入：设计、自审核与本机验收

2026-09-30。本轮在既有[筛选证据](../2026-09-30-nonnegative-gemm/README.md)之后接入，不改变canonical算子、逻辑AST/DAG、输出dtype/shape或Excel公式。基线为上一结果直写wheel `f8509c481644af890b14c20936092d781d8f3dda388f02c203436a47e3a98264`；本轮源码/正式wheel身份为 `4df196c9a2c64c984bb940754de488099b9ab2ce1c51253b5d3a8dfdce476f1e`，扩展和worker逐文件与安装包一致，见[清单](build-identity.json)。仅修改本地工作树，未提交或推送。

设计遵守D1/D2/D5/D6/D8：仅typed单一float64矩阵根，根本身为matmul或唯一消费者transpose；无子作用域、isolate或观察器。运行时还排除捕获/预绑定的子图执行，避免改变迭代停止等离散行为。M/N限定512–4096，K限定256–4096，正向C/F leading dimension。逐请求扫描两输入，拒绝负零、负数、NaN/Inf和非零指数越界[2^-128,2^128]；拒绝不写结果，然后沿原路径执行。prepared绑定内容变化不复用旧准入结果。

复用系统Accelerate单次DGEMM，借用原C/F输入，不整块转换/复制；直接写已规划C字节结果。私有transpose仍由原结果布局选择F连续视图，显式F普通MatMul沿既有最终物化。设置/核对/恢复调用线程的BLAS策略，恢复失败明确报错，不能静默污染持久线程。双库关闭及非目标平台沿用原路径。若两个已检查输入之一全零，用标准库fill生成与原升序乘加逐位相同的+0结果，避免无效GEMM；此路径单独计数，不冒称调用BLAS。

复用一个Workspace，成功准入后释放旧面板容量；拒绝由ops::execute按原需求建立有界Eigen面板。Planner为潜在库根采用 `8MiB + 512*K*8` 的库工作区估算，与原算子scratch取最大，不提前分配此估算量。该估算包含比筛选峰值更大的余量，**不是Apple公开保证的硬上界**；预算准入和本机实测需分别验证，其他OS/库版本未验收。库内部实际分配由fresh进程探针测量，不记为零；审计的reserve字段只表示估算，不表示已经分配或实际峰值。

新增成功DGEMM、全零fill及库reserve审计，贯通graph/worker/PyBind；worker审计协议版本升为15。输入所有者、独立结果、线程/进程/共享内存生命周期沿既有路径。Excel按逻辑数学生成，观察器继续原路径，不为普通C++请求执行Excel。本轮纯物理实现变化，按原浮点容差验证，不要求合法域任意结果逐位一致。

## 自审核及正确性

正式wheel[Python全量回归](python-full.log) **9368项通过**，其中新增122项覆盖四输入布局、C/F/auto输出、普通/prepared、single/thread/process-inline/process-shared、结果独立、输入修改重读、两输入的负控制、负/间隔/广播stride、NaN padding、离散/多根/子图/isolate不准入、预算拒绝与上下界尺度。native、ASan/UBSan、双库关闭构建各 **9/9**；新增原生哨兵覆盖真实DGEMM、越界保护、不写入的拒绝、精确零符号和旧面板释放。双库关闭Python另有19项通过、103项按库平台标记跳过；[185算子固定夹具](all-operators.json)全部通过。macOS未启用LeakSanitizer，不能将ASan通过称为完整泄漏证明。

首轮三套native回归均因结果运输测试仍断言IPC14而失败；已改为实际IPC15并重跑全部9项。`*-pre-repair.log`保留该失败证据，未修改生产协议以迎合旧测试。自审核确认准入失败不写结果、不缓存输入域、共享/内部离散消费者及迭代子图不采用重排，Planner和实际执行共用几何准入函数。Apple SDK的thread API明确是线程局部设置；代码保存、设置/核对并恢复/核对，恢复失败明确报错。库C入口没有C++抛出路径；未新增私有线程池。源码数学/Excel生成及符号预算不变，观察器仍按原顺序执行；本轮没有新的Microsoft Excel重算。

## 内存、诊断与采用边界

普通正域较旧C++增加约1–1.75MiB工作区，较NJIT仅约9–10KiB框架增量；不能写成内存没有增加。新/旧RSS请求增量在正域单次观察中约多4.7–7.0MiB，全部原始正负记录保留，不把它直接称为噪声或更优。实际输出与结果保留占主要容量；按当前政策，显著时间收益和这一有限工作区取舍可分阶段保留本地路径，9–10KiB差值不作性能否决。全零冷/暖堆各少约5MiB（相对NJIT约6MiB）；混合符号只增加24/48B审计开销，不继续抠该差值。

引擎`algorithm_copy_bytes=0`仅说明本路径没有打包/复制输入，不表示厂商内部没有打包。`operator_workspace_capacity_bytes=0`也仅指已释放的引擎Workspace；库实际分配由上述探针记录。显式F普通MatMul仍有32MiB arena及根复制；transpose auto/F直接根两项为0。Planner库reserve是估算，不是内存实测或厂商硬保证；不同OS/库版本及未测尺寸仍不能外推。

[历史Phase-2严格诊断](phase2/gate-summary.json)为 **3/4**：63点普通入口4.750µs、独立配对比1.009超过原1.00；该绝对量级不按当前政策作为采用阻断，原阈值/失败记录未改。500/1000产品的完整指标负载为214.730/430.622ms，对NJIT285.975/570.734ms。首两次诊断分别遇到外部项目Numba缓存不可写、POSIX共享内存权限不足；缓存重定向到`/private/tmp`并在允许共享内存的环境重跑，保留相应环境失败日志，没有修改外部项目。

当前范围是独立正域最终矩阵根的原生物理优化；混合符号、其他重型算法以及全算子中大型时间/内存优势目标仍开放。专项回归、Ruff、wheel检查和diff检查通过不等于全引擎性能已全面通过；未提交或推送。
