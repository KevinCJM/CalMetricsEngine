本轮只验证隔离原型。生产矩阵内核未变，尚未完成 Planner/Workspace/worker 接入、公开 Scheduler 性能或全引擎验收。

## 方法与数值边界

基线为当前 `d6c399a4d200334b20fee44de176aa7ce31faaae77d8a4858c35fe75db8a06e3` 构建。复用固定 Eigen 3.4.0 的 pack/gebp，通过升序 K、独立乘加和赋值适配保持原计算顺序；单独分配有界 full-K 面板，避免旧原型借用输出尾区后大量回算。保留 C/F 输入步长，打包计入调用，当前原型返回独立 C 输出。没有据此宣称 C 是全链最优布局。

三个配置48×32、96×64、192×128全部保留；下表统一展示192×128，不按单例选择获胜配置。802夹具/4812调用中3648支持调用全部通过数值、IEEE、零比较、canary和只读检查；不支持调用验证拒绝不写。额外ASan/UBSan原型1296调用通过（未启用LeakSanitizer），不等于生产全套回归。

## 接入结论与复现

有秒级收益，建议继续做固定192×128方案的受预算接入；当前还未采用。必须把面板上界贯通registry、Workspace、Planner、子作用域与worker，验证不足预算拒绝、所有权、可移植路径、链接后ODR与指令，再做完整请求回归。原型裸new[]不能直接搬入正式执行内核。固定Eigen内部模板不是公开稳定API，升级必须复核。
