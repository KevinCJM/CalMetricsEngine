# 四行 Cholesky 与顺序统计打包：当前设计

范围仅两个已有物理内核。原型 DESIGN.md/manifest.json 保留筛选时状态；正式源码与 wheel 为 identity.json，基线为2ebc5d22，新构建850871eb。两项都没有新增公开算子、算法版本、缓存、线程或Python生产计算。

## 依赖、等价与存储

- Cholesky 保持原16行/8因子面板。因子完成后，四个独立行共享固定8列Eigen源数组；每个元素仍沿u升序分别乘减，共同前缀外继续原尾部。全消费校验、失败canonical重放、C/F清零、covariance原地恢复及root资格不变。保守数值scratch仍为(16*(n+17)+128)*8，最大不新增数值堆；实际Release update_group函数帧720B，非完整调用链峰值。
- 顺序统计只在非标量逻辑C连续的source与mask上使用原始指针；先判断mask，再读被消费值。其余rank/strides保留Value逻辑访问。分类、nth/max/sort、概率/中位数表达式与多根共享排序不变；审计复用打包时消费数，省去重复mask扫描。仍保留源N doubles工作区上界，稀疏mask可能显著多于NJIT压缩样本，这一风险必须实测，不能用55%密度掩盖。
- 输入只读、独立结果与prepared本次读取契约不变；无新增数值结果重用。Planner和worker协议不变。公式与数学版本不变，只需适用数值/状态复核；历史Microsoft Excel快照对比不算新Excel重算。

复用现有AOT API、工作区、原生库及正式全请求工具；新测试只覆盖新增分支及保留可观察行为。正确性先行，再按真实新旧wheel、预热NJIT和实际查询的一CPU预算执行35类9轮轮换计时；13类分开fresh malloc/RSS，共78进程。准备/冷执行/释放/暖态与留旧输出都计入；RSS只作单fresh样本的页级观察。
