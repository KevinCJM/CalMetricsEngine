## 数学、存储与调度

[开发设计及误差推导](DESIGN.md)。沿用独立单根、typed float64矩阵、无内部消费者/作用域/isolate/观察器的准入；平台、形状、正向C/F兼容输入、标准舍入及原有限源幅度≤1e4检查保留。源数据不缓存，prepared每次重读。库只占一个Scheduler CPU token，恢复当前线程BLAS策略后才完成或重放。

canonical均值、对角、局部重放和最后归一化均复用原实现。用精确相同的canonical标准差乘积p，把已有协方差误差E转换成归一化误差上界，再检查原1e-12容差；保留正负/零分类重放，不强设对角为1，不截断相关系数。已失效的块范数向量保存标准差，不新增D向量。零方差和无效分母仍回到原错误处理，全零相关矩阵不使用协方差的零成功特例。

相关系数的误差检查已归一化，因此不沿用协方差“中心值幅度>8就提前回退”的绝对尺度启发式。原源幅度、行数上限及非零中心值下界保证平方范数/除法范围安全；真实误差检查或符号不确定仍触发重放。源幅度超过1e4仍执行canonical，不能把这项私有派发条件误解为公共输入限制。

复用原中心化面板、原结果下三角存储界/标记、原32MiB库工作区估算及现有审计字段；计数描述相关矩阵共享的协方差阶段。面板实际为 `(B+3)*D*8`，原shape-only预算覆盖非单调区间面板选择；供应商工作区是已测估算，不是硬内存上界。没有新增完整数学实现。

单一独立F根在最终缓冲的C描述中完成归一化和逐位镜像，然后按实际F strides发布，同一对称矩阵的逻辑值不变。finalize、容量、执行及worker重建共用资格，省去D² arena与根复制；直接算子和多根/隔离/作用域继续原布局契约。观察器使用canonical数学，并可看到完成后的真实F描述。

## 内存与真实代价

两组×三个后端×heap/RSS，共12个fresh子进程。输入按≤64KiB块生成，非C输入逐行哈希，避免测量前大临时矩阵影响RSS。连续heap epoch包含setup、cold、释放首结果、warmup及保留前次结果的warm调用；峰值不相加。内存使用最终紧凑NJIT参考，没有先执行数值求解再开始测量。[原始记录](memory/memory.json)。

| 输入/输出 | 旧 cold / warm MiB | 新 cold / warm MiB | NJIT cold / warm MiB |
| --- | ---: | ---: | ---: |
| 2048 C/C | 32.008 / 64.008 | 76.054 / 108.055 | 102.000 / 134.001 |
| 4096 F/F | 256.008 / 384.008 | 150.101 / 278.102 | 390.000 / 518.001 |

4096 F冷暖申请峰各减少约105.907MiB，且比NJIT少约239.900MiB。2048 C为了库计算新增约44.046MiB，**是实质面板/库成本**；仍比NJIT少约25.946MiB，结合约6.4倍旧版提速分阶段采用，不把这项增长包装成几KB或零增加。

RSS请求增量：2048旧/新/NI为64.656/108.766/140.125MiB；4096为384.750/308.875/530.125MiB。每组每后端仅一个fresh监控样本。36个heap阶段无表溢出或untracked free；探针不覆盖全部Python arena、mmap、调用栈和进程树，RSS也不是完整分配计数。不能外推所有负载、布局或并发的内存结论。

另以6个fresh子进程补测[512×256 C/C](memory-small/memory.json)：旧/新/NI冷态申请峰为0.508/1.514/3.500MiB，暖态为1.008/2.014/4.001MiB，RSS增量为1.688/2.703/4.625MiB。新版本比旧版多约1.006MiB面板成本，仍低于NJIT；不把32MiB库预算估算写成每次实际分配。两批合计18个子进程、54个heap阶段均无追踪错误；小批数据与最终计时的输入、输出、构建身份匹配。
