## 设计与查重

原 FF Column4 全 K 方案已有历史实验，本轮没有把它称作新数学方向。新增 Column8×4 与精简 Column4 控制，复用 Eigen3.4 公共 Array/Map；只接收 M/K/N≥32、A/B row stride=1、合法正 leading dimension 的 F/F 输入。每格仍由 +0 开始按升序 K 分别乘、加，输入借用、结果独立，无 packing、私有池或持久状态。CF/其他布局明确拒绝且不修改输出。

V1 对象发现 Column4 不可达 K=0 写零路径使局部帧增至688 B。V2只在内部bulk显式早返 K=0（外层已强制K≥32），移除该不可达编译分支；未缩小测试范围或改变数学准入。V1数据完整保留，V2为新构建复测。

## 正确性、速度与内存

- V1、V2分别258夹具×3实现×2输出初态，共1548记录。每个候选78夹具准入、180拒绝；原浮点容差、IEEE分类、投影bool、可用fsum参照、只读输入/输出canary和所有权检查全部通过。有限逐位也一致，但不是新增全域逐位契约；投影bool不等于真实DAG测试。
- 每版固定12个FF/补边FF形状、12轮四后端平衡顺序，包含独立输出分配、ABI、完整内核和保留前次结果。每后端占各顺序位置3次。NJIT预热，Accelerate线程局部策略在各次调用前统一设置单线程并核验恢复；策略设置在计时外。不是Scheduler、同核绑定或多独立进程统计。
- V1 Column8比当前路径快11/12项，配对比0.6681–1.1167；512补边FF回退11.67%，10/12轮更慢。V2 Column8仍快11/12项，配对比0.6821–1.0093；同一补边例仍回退0.93%。不能用不同进程的绝对耗时或总体中位数替代同轮配对结论。
- V2 Column4稳定快12/12项，配对比0.8297–0.9668，即约3.3%–17.0%改善；仍比NJIT慢4.40–21.71倍。Column8仍慢4.27–16.69倍。两版1024 FF/补边FF的NJIT与当前实现有原容差差异，原始检查保留；没有把任一实现自动视作数学真值或放宽容差。
- V1的36个独立heap子进程（12形状×3原生实现）中，冷/暖额外堆峰均0，216阶段快照未见分配、释放、未跟踪释放或溢出；输出预分配在epoch外，首次内核执行在cold内。**不是完整输出/请求内存，未测NJIT heap或RSS；V2没有heap复测。**
- 对象审核：V2 Column4/Column8 bulk分别32/64 B，无边缘完整原型链48/80 B，有边缘均192 B；热循环无FMA、无数值spill，实际跨连续行NEON，输出直接scalar/lane写回。实际18977 F helper为416 B；原型不是生产调用链，不能据此宣称完整内存不增。

没有接入Column8，因为固定支持范围仍有回退；Column4收益有限且完整公开请求/内存未验收，优先研究可移除整次扫描的共享计算。不按测试个案挑选宽度或继续缩小布局来隐藏失败。原型、失败、未运行的测试草稿和下一步静态设计均保留；草稿不计入已通过测试。
