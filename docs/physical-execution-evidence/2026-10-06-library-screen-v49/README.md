# V49：否决小收益候选，并完成 ArmPL 隔离筛选

2026-10-06，本机 M1 Max、macOS 15.6.1、CPU1。实际引擎保持 V48（build ID `30722fb25c692505f924aec6755d8f3c5a6113507b9b54552fb22a895d8ab365`），93 份数值源、168 份现有测试及294份其他既存文件在收尾核对时保持不变。本轮只更新实验与决策文档；没有提交、推送或部署。

## 均值复用候选：不采用

7个隔离 C++ 文件复用已存活、同输入/同轴的短均值快照，仍走原有序两遍方差。新93项与相关总计1328项 Python、native9/9通过；这些是候选资格，未进入实际测试目录。

72次完整请求计入输入独立只读准备、普通 Scheduler /预热 NJIT、两代独立只读结果。1GiB C矩阵全六轮中位为原0.50750、候选0.49846、NJIT0.42579秒，仅约9ms改善。审核发现最后一轮可能与其他worker的终末NumPy核验重叠，所有原始样本保留，性能不作为完整资格；前五轮无该重叠的中位为原0.508485、候选0.503413、NJIT0.411295秒，候选仅约5ms改善。F路径未复用均值，不将其波动解释为优化收益。

按用户强调的实质收益拒绝采用：没有用几KB/几ms构造门禁，也没有继续完整回归、SAN/OFF或fresh峰值试验。候选构建失败、未启用融合时元数据访问的自审修复、一个违反轴契约的新测试及修正版原始记录均保留。

## ArmPL 26.07：当前 GEMM 路线不采用

参考 [Arm 官方安装说明](https://learn.arm.com/install-guides/armpl/)与 [Eigen 惰性求值方法](https://eigen.tuxfamily.org/dox/TopicLazyEvaluation.html)，使用官方安装器的替代目录选项将 ArmPL 放入本轮临时目录，系统库未改。下载包内动态库签名核验失败，保留日志，未执行或重签；改用官方 serial LP64 静态库和所需 Fortran runtime 静态链接试验 C++ wrapper，所得 wrapper严格签名核验通过，依赖不含OpenMP。镜像已卸载。没有将 ArmPL 二进制、安装器或完整包加入项目。

48组float32/float64、四种C/F输入组合、正长度几何、长精度参考及独立输出检查通过；这不是引擎的异常/SAN/Planner/worker/Excel资格。

后续4组/72次计时在各后端单独进程中预热、均衡轮换，加入核验屏障，确保测量时不与其他后端末尾核验重叠。所有请求都计入两个输入独立只读准备、计算与独立F结果，两代结果同时保留；NI编译不计，Accelerate线程局部单核设置及恢复逐调用核验，ArmPL使用serial静态库。ArmPL为试验wrapper调用，未集成Graph，其较少入口开销也未能带来收益。
