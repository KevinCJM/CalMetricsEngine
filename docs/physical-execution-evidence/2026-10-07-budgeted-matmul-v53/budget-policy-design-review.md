# V53：可选 MatMul 后端与既有紧预算相容

2026-10-07。该设计只改变物理后端选择；数学算子、AST/DAG、公开 Python 接口、dtype、形状、C/F 输出及 Excel 公式均保持原契约。源码位于隔离构建，尚未接入实际目录。

## 问题及选择

V52 扩大成熟 Accelerate 根路径的矩形几何，产生约 10MB 的保守库/分块预留。8193×256 乘 256×32 的旧请求在 18,943,278 bytes 预算可运行，而 V52 即便降低至一 worker 仍误拒绝。不能通过低估预留、提高用户预算或跳过数值检查解决。

复用一份 Plan、输入几何和结果布局，先按扩展库几何执行既有 worker/运输准入。只有明确超预算、已降至单 worker，且原几何工作区确实更小时，才切换该请求为原几何并重新选择 worker/运输。不是捕获任意 bad_alloc 后重试；原几何仍无法准入则保留 MemoryError。布尔标志最多改变一次，循环最多两轮；旧库支持的原几何仍保留旧库工作区和执行路径。

## 贯通与所有权

- 标志只存在 per-request Plan 与本次 graph scratch，不能修改共享 CompiledGraph、逻辑 DAG 或 cached worker program。
- single、thread、row range 与 worker graph 调用均显式传递；执行期间通过 RAII 恢复 scratch 原策略，包括异常路径。工作区容量改变走既有缓冲释放/重建机制。
- 重选时清理 lane、worker 数、分块、运输状态和本轮原因码；重建既有运输大小和资源检查，不重复分配整套结果几何元数据。
- IPC v24 在既有 mode word 中编码 shared bit 与原几何 bit，不改变帧长度。未知位和 v23 帧显式拒绝；同一逻辑图的 worker 缓存不能缓存该请求策略。
- 仍直接写独立结果；输入不可变、旧本地/共享输出及 prepared snapshot 在后续请求后保持独立。

## 审核与验证边界

- Planner 与 graph reserve 使用同一几何开关，没有删去库预留或减小原始 worker 必需工作区。
- 仅独立根的可选扩展库几何可能产生两种不同 reserve；scope、isolate、多根、内部消费者仍遵守原资格与原错误检查。
- 原数值证明、IEEE/负零/nonfinite、LP64/K 边界、取消检查和 canonical 回放保持不变，Excel 数学展开无须变化。
- 原反例的精确旧预算已在正式 AOT 安装包执行成功，并且估算与原版相同；这不是整个进程 RSS 的硬上限证明。
- 新回归覆盖四 lane、C/F 输入与输出、同 worker 高低预算交替、prepared、异步并发、原共享输入、共享结果、窗口混合几何、低于必需工作区的拒绝及恢复。预算夹具来自独立 V51 公共 Planner，避免以新实现推导自身期望。
- 初轮 12 个失败来自错误地给 prepare_execution/execute 传入不存在的参数；随后新增共享测试的 4 个失败来自读取未公开 Plan 属性。修正测试以使用既有公开接口，不为测试扩展产品 API。失败与复验证据均保留。
- 原生测试通过；全量 normal、完整引擎 ASan/UBSan 与三库 OFF 状态以最终 XML/终态文件为准，不能凭构建成功宣称回归通过。
- 本轮尚未进行新的完整时间/峰值测量。V52 的旧性能收益不能直接作为 V53 采用证据；原方阵控制与新的隐藏库分配、fresh RSS 仍须闭环。没有提交、推送、系统安装或部署。
