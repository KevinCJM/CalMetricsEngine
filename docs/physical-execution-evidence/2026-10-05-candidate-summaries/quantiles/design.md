## 真实依赖与收益来源

平台 `backend/optimizer.py` 的 `portfolio_returns_kernel` 计算每个候选的历史收益，
`calculate_return_kernel` 与 `calculate_risk_kernel` 消费该轨迹。风险编号 4 使用
线性插值分位数的相反数。既有算子可表达以下完整给定候选数学请求：

```text
Y = matmul(W, transpose(R))
mean_axis(Y, 1) * 252
sqrt(variance_axis(Y, 1, 1) * 252)
-quantiles_axis(Y, probabilities, 1)
```

252 和 probabilities 是冻结验收图的调用方参数，不是引擎全局金融契约。
原 c605 优化只接受均值/方差；加入分位数后恢复完整 Y。N=100000、T=2520、
K=30 时，Y 自身占 2.016 GB，排序还逐行复制约 2.016 GB 数据。

分位数需要实际轨迹，不能以公共均值/协方差代替。候选方案按最多 64 个候选
计算一批轨迹，使用 Accelerate GEMM，再按原顺序完成均值/两遍中心化方差，
每条轨迹使用已有 Highway/标准排序一次，供全部分位数消费者共享。消费完成
即复用批次缓冲；不产生 N×T 矩阵，也不为每个概率重复排序。

这是给定候选的完整风险计算请求，不包括随机采样、约束修复、Pareto、前沿、
CVaR/下行风险/回撤或平台 HTTP 服务。数据是代表性合成夹具，不能表述为
真实产品数据或平台业务迁移验收。

## 物理准入与数学

- 沿用 c605 的输入支持、无作用域、非公开 matmul，以及共享 N/T/K 几何限制。
  全部直接消费者只能是 axis=1 的 sum/mean/variance/quantiles。
- 统计输出仍限 float64 向量、正有限常量缩放、至多一次 sqrt。分位数输出限
  float64 矩阵、正有限常量缩放与 negate；比较、索引、任意未证明表达式和
  明细输出使整组恢复 canonical 矩阵执行。
- 概率来自已检查的 input-backed 视图，或静态输入。普通 AST 可能先构建 Y，
  后创建概率输入节点：后者可直接读取绑定的静态输入，不提前执行任何 view
  或区间检查。其他晚到依赖不准入。每个概率向量最多 128 项。
- GEMM 仅在 macOS 15+、库开启、已证明的右矩阵正 C/F leading dimension、
  有限且绝对值不超过 1e50、FE_TONEAREST 下使用；权重只打包当前小批次。
  当前调用线程限制单线程并恢复，服从 Scheduler CPU 预算。
- 使用 c605 的保守 FP64 工程包络，传递统计/缩放/sqrt 误差，准入上限 4e-5。
  排序和凸插值在最大范数下不放大输入扰动。该工程包络不是厂商库的形式精度
  证明；另验独立长双精度公式、方差非负性及分位数单调性。
- v4 对 sqrt 消费者逐行检查：若统计值 v 的误差上界为 e 且 v>e，
  使用 `e/(sqrt(v)+sqrt(v-e))` 作为开方误差上界，再传播消费者缩放。
  最大 ddof 给出方差消费者的最坏分母；不确定符号、近零或证书不足时回放
  canonical 行。避免用全局 `sqrt(e)` 把正常的长历史请求全部拒绝。
- 大偏移、超大缩放、动态/非法 ddof、不合格域/布局/库选择有界 canonical
  回放。零值、不确定 mean→sqrt 零边界及非有限统计逐行回放，保持可观察错误。
  不截负方差、不加扰动、不改变排序/插值定义。

## 缓冲、预算、错误与所有权

当前每组缓存容量为 `N*(2 + sum(Q_nonroot))` doubles：直接公开分位数根
写入本次独立结果，非根分位数仍缓存；没有复制/转置完整N×Q结果。
v2–v4的历史容量为 `N*(2 + sum(Q))`。v3 不准入缓存列数达到 T 的组，
避免大 Q、小 T 时缓存反比完整轨迹更大。
v4 运行批宽为 `min(64,N,max(1,163840/T))`；至少容纳一条完整轨迹。
规划辅助上界为 `min(min(64,N)*T,max(163840,T))+min(64,N)*K` doubles。
上界按规划最大几何计算，同时覆盖所有较短实际区间，不能直接用
`batch(upper_T)*upper_T`：取整后的批宽在短区间增大，后者可能不足。
百万时点的轨迹工作区由最多 64 条（512 MB）降为一条（8 MB）。
Planner 与运行时沿用同一共享几何和 checked 加法。
每个分位数消费者的缓存按规划上界定位，实际结果按当前形状写出。缩小几何
或换图后释放不属于本次计划的容量。厂商工作区和既有排序 reserve 继续计入。
数值拒绝后的回放仍保持有界，不能用小计划临时分配完整 Y。

共享只限本次相同逻辑 producer；跨请求没有数值缓存。输入只读，物理缓存
归本次 worker Scratch，最终结果归独立 result owner；旧结果不作为工作区。
概率不合法时不在 producer 抛错，消费者仍先执行原 prepare，再读取缓存。
短样本、variance 有限值检查和独立错误优先顺序保留在原节点。
Observer、isolate、延迟故障及 prebound 保持 canonical；观察者得到真实 Y。
逻辑程序仍经已有序列化重新 finalize，不新增 wire/opcode/AST 协议。

初版要求概率节点位于 producer 前面，普通 AST 的晚到静态输入使路径完全
未命中。初版构建、失败回归和无收益测量均保留，修复节点绑定后重新构建。
测试夹具中独立概率 P 与 Q 曾错误共用符号，已修正，未改变引擎形状检查。

### 后续物理闭包设计：原顺序行轨迹与风险消费者

以已经核验的24个可编辑图为第一批完整负载，不新增金融黑盒算子：

1. CVaR闭包为分位数、单概率投影、沿候选广播、`less_equal`、两个
   `where→sum_axis`及带显式分母保护的除法/取负。概率静态维度必须为1；
   不能把多概率的sum当成单阈值。保留原时间顺序尾部求和和边界同值。
2. 下行风险为`less_than(Y,0)`、负样本数与负样本均值、显式广播、中心化
   平方及第二遍条件求和。少于两个样本的where和分母保护是调用方图中的
   可编辑数学步骤；不额外年化、不替换成对零的二阶矩。
3. 回撤为`1+Y`、axis=1且initial=1的连续乘积、initial=1的连续最大值、
   `1-NAV/peak`和axis=1最大值。状态按时间更新，候选之间独立；不以终值
   代替路径最大值，不输出未请求的轨迹。

共享相同逻辑matmul的有界GEMM批次；每条原顺序轨迹完成全部适用消费者后
才复用。CVaR排序需要单独有界排序行，不能直接破坏尚被尾部原顺序求和或
NAV消费的轨迹。沿用Highway/标准排序和既有标量状态原语；库未准入时同样
只回放一条canonical轨迹。公共根或外部消费者需要完整Y/掩码/路径时保留原
执行，不以汇总结果取代其内容。缓存只保存必要的N维汇总，不分配N×T掩码、
中心化差值、平方、NAV或峰值矩阵；Planner与运行时必须共享checked上界。

比较消费者需要单独的离散准入：负号附近或分位点邻值的误差包络不能证明
成员不变时回放canonical行。分位数为某个已排序观察时须证明其邻域次序及
同值范围，不用最终CVaR浮点接近掩盖样本数变化。回撤的乘积/除法沿状态
传播误差，临近溢出、下溢、非有限或分母边界时回放；不截断NAV或修改初值。

原逻辑节点仍按原位置执行prepare和独立结构校验。提前物理计算发现的错误
须绑定原节点，按原DAG顺序报告；不能因行0先执行就压过较早节点的行64错误。
结构、概率、空/短区间和独立除零均与原未融合图比较。observer/isolate、作用域
及未证明闭包保留当前路径。结果仅写本次独立owner，C/F实际顺序、IPC与
共享内存仍经现有协议传输；Excel继续引用原逻辑图，没有新增公式或普通入口导出。

先证明错误/离散/状态及所有权，再冻结完整三风险图与相同输出的流式和同分块
BLAS-NJIT。大规模正式任务必须包括输入准备、普通Scheduler、所有输出和两代

### 实现收敛：按独立轴分块执行原图

下一实现先采用通用物理分块，避免给上述业务口径增加具名黑盒：

- 编译元数据记录唯一可分块输入及每个节点的独立轴。静态W的第0轴通过
  matmul传到Y的第0轴；transpose交换轴；逐元素运算、比较、where保留
  对齐的独立轴；broadcast_like以目标轴为准并验证广播关系；按其他轴的
  归约与扫描只消费该候选自己的数据。公共根必须为沿独立轴的向量。
- 准入是完整依赖证明，不是按形状巧合判断。跨候选归约、索引重排、其他
  matmul、作用域、不可证明的外部消费者以及请求完整Y/路径矩阵时继续
  canonical执行。原纯统计融合优先，不能因通用分块退出已验收的快速路径。
- 批宽以字节/单元工作集控制；W只建立本次只读区间视图，不复制全体权重。
  每批使用同一原生Program和原算子执行，缓冲在批间复用；三个独立根直接
  写本次结果各自的对应区间。所有时间归约和状态更新保留完整历史顺序。
- Planner、worker、实际Scratch采用同一checked批次上界；所有保留的排序、
  厂商及子图工作区计入。换图或缩小工作集释放旧容量。输出全N长度是
  必要结果，不裁剪或降低结果保留方式；不能只优化执行却仍以N×T估算
  阻止低内存任务准入，也不能低估实际批次复制/排序成本。
- 分块会改变“节点优先、行次之”的执行次序。提前遇到ops::Error时记录
  原节点编号和代码；检查后续批次能否在更早节点失败，最终按原节点顺序
  及该节点的原行顺序选择异常。取消/超时和资源错误仍立即生效。
  全局结构、参数、根容量和输入边界保持原检查；不通过转换成普通NaN
  或isolate状态来丢失原异常身份。专测“后批较早节点失败”与独立坏结构。
- 第一实现复用原算子内核，不据此声明已使用GEMM或领先NI。随后在同一
  分块上复用成熟库；任何改变比较成员、排序或错误边界的尾差均需独立
  证书或canonical回放。数学归约/扫描融合以这份完整图为对照继续推进。

已完成隔离原型，尚未进入实际源码。使用三个原逻辑输出、相同数据/核数/只读准备/
保留方式，与流式及分块BLAS-NJIT测完整耗时和fresh峰值；N/T/K较小的
数学验证只负责定义，不能证明大任务收益。普通入口的Excel仍按需隔离，
物理批次不进入公式布局或预算；优化保持原逻辑图，无新的Excel重算声明。
