# V21：已有条件归约的独立行 Eigen SIMD

## 问题、范围和基线

已接入实际目录的 88ea 完整三风险计算仍有耗时差距：16,384×2,520×30 的 CPU1 普通入口约 0.49 秒，NJIT 约 0.42 秒；最大规模仍只有较小 NJIT 时间优势。既有同源符号化采样中，条件求和 501 帧、平方归约 254 帧，具备完整大任务秒级收益潜力。采样计数不是耗时比例或采用证据。

本候选从正在验收的 db4b 独立快照开发，不修改其冻结源、测试或正式计时脚本，也不修改实际目录的数值代码。V20b 全量/SAN/OFF/CPU1/2/4 时间与峰值流水线运行期间，只做设计、源码和静态审核；构建、测试和性能工作排队等待其结束，避免扰动正式测量。

只优化既有 where→sum_axis(axis=1) 与 subtract→multiply(self)→where→sum_axis(axis=1) 的私有闭包，不新增公开算子，不扩大闭包依赖准入，不修改 AST、逻辑 DAG、Planner 并行证明或传输协议。

## 数学和依赖证明

每个 SIMD lane 对应一条独立矩阵行，每次只前进一步时间索引。每行保持 total=+0、ascending-j 的左折叠；平方路径保持先 subtract，再 multiply(delta,delta)，随后按原掩码选择，最后 add。禁止水平归约、FMA、时间重排或跨行混合。库实现复用当前 Eigen Packet2d 的 gather/select/subtract/multiply/add，不自行编写 ISA 内核。

条件归约可以加载未选择分支的值，但不对这些值做多余算术；位选择保留未选 NaN/Inf 的现有处理。平方路径按当前私有/原始逻辑先计算平方，即便掩码不选择该项。既有结构预检、延迟数值错误回放与逻辑失败优先级保持不变。正二进制计数仍用已验收的标准库路径，不通过浮点求和替代。

私有库入口仅处理已证明的 rank2 输出、至少四条剩余行、至少128个时间元素、数值标量或相同形状矩阵，以及标量/同形状 bool 掩码。空/短轴、剩余尾行、非适用平台和关闭 Eigen 的构建返回 false，继续当前规范路径。有符号 stride 包括 C/F、反向、padded 与广播零 stride；不会先复制或强制改变布局。

## 内存、调度和取消

两对独立行的累加器、标量广播和掩码只使用寄存器/固定栈对象，不分配工作区或持有任何跨请求指针。写入既有总和缓存，最终根仍按当前直接写出和独立结果所有权返回；不会为 Excel 保留临时值。单线程库在 Scheduler 已准入线程内执行，不建立池或修改进程全局库线程数。

每1024个时间元素调用现有 deadline/cancel 检查，开始及尾行保持当前检查。取消异常不返回半成品，输入和旧结果不作为写入目标。库入口拒绝时不得写结果；可接受路径只写 row..row+3。

## 测试、审核和采用要求

新增 Python 覆盖128边界、奇数尾行、长轴、C/F/负/padded，矩阵/标量广播、全真/全假/混合掩码、负零、未选非有限中间值、旧结果和 readonly 输入。以额外公开中间根强制当前 canonical 路径，并做逐位比较；完整三根另保留独立数学定义和合理浮点容差。原生库入口测试拒绝无写、前后 canary、负/零 stride、特殊浮点与取消。

普通、完整回归、ASan/UBSan、库关闭构建须绑定同一源码身份。先检查真实机器码与局部诊断，再在无并发压力下对 CPU1/2/4 的完整输入准备→图执行→三个独立结果返回对照当前 C++ 和预热 NJIT；同时测新进程峰值申请及RSS增量，保留两代结果。几KB/几毫秒仅诊断，不靠局部微基准宣布采用；采用须有完整中大型实质收益证据。

Excel 仍从同一逻辑图展开，节点、定义、形状、预算和错误契约未变化，无需改公式。本候选不声称 Microsoft Excel 已重算，不触发普通请求的 Excel 路径。规则依据：computation-design-rules.md 数学等价/成熟库/D8，以及 excel-generation-rules.md X1/X6/X9/X10。
