## 实现与纪律

在既有平台、auto/Eigen、M/K/N≥32条件下，重复行依赖复用保持优先；C兼容右矩阵且K≥683进入32×64×64宏块、4×8 Eigen Array微块。使用库的公共Array/Map与SIMD表达式，项目代码负责保序遍历；没有默认GEMM、输入打包、新数值工作区或私有线程。首K面板从+0开始，后续从同一独立结果格继续累加，保留每格原K顺序、乘/加和IEEE传播。

新路径direct审计为 `eigen-block-matmul`。图/worker没有新增逐算子ISA字段；现有AST/DAG、类型、错误、CPU预算、进程和独立结果协议不变。Excel仍由逻辑图展开，公式/符号预算不变，普通C++请求不执行Excel。

已按D1–D8及X1–X10记录依赖、输入与输出复用、数学等价、缓冲/预算与实际验收边界。完整设计 `iteration-plan.md`、`design.md`、`production-integration-design.md` 及补丁和原型保存在原始归档（本机保留的历史归档：`raw-evidence.tar.gz`，未纳入此次提交），成员与散列见[清单](archive-manifest.json)。原型阶段“尚未采用”仅描述当时状态；当前实现以归档的 `final-repository/` 为准。

## 内存与追加RSS追踪

固定51/114用例、306独立heap/RSS子进程；只覆盖新分块10项中的4个ordinary，不覆盖其余6个direct/prepared。输入哈希可能在epoch前分配/释放整份输入，不能称为全新分配器状态。图setup与首次数值执行入冷态，保留完整独立结果。直接算子审计标为未采集，没有为获取审计额外执行MatMul或编造0计数。

- 51项全部已记录冷/热堆字段、字节及分配次数新旧精确相同；探针溢出和未跟踪释放均0。42项堆峰低于NJIT、9项更高，最高多14146 B暖峰。堆分配次数仍比NJIT多。
- RSS总峰新−旧中位+131072 B，范围−25264128至+16695296 B，29/51为正；请求增量中位+16384 B，26/51为正。不能用堆持平宣称总内存不增，也不能用NJIT进程较大的导入基线替代请求增量比较。
- 新分块4项RSS总峰全部更高：1024 CC/FC分别多8454144/16695296 B；长K CC/FC分别多1966080/131072 B。正式结果不被后续复测覆盖。

针对该问题追加6个固定用例（全部4个新路径样本，加1024 CF和512 CC未改控制）、11组AB/BA、132独立进程、13阶段外部RSS观察。1716个外部端点与原生resident一致，端点均1线程；最大采样间隙8.487 ms，短峰可能漏测。四个新路径的请求增量差中位依次为+32768、+32768、−16384、+16384 B，正差次数7/11、6/11、4/11、6/11。1024 CC单对总峰差仍可达到+25657344 B。

相对backend_import，四项结果释放后physical footprint差中位分别−32704、+16384、−32768、0 B，external增量分别+32768、+32768、+16384、+16384 B。结果释放、分配器保留容量及输入哈希阶段都有可见影响，但没有证明原差异的唯一原因。外部观察、20 ms暂停、8次计算与两份结果保留改变测量口径；**这些诊断不能证明RSS不增，整体内存验收仍开放。** 详见[RSS阶段分析](rss-attribution-analysis.md)；全部阶段与正负差值保存在原始归档的 `rss-attribution/` 和 `rss-stage-key-metrics.json`。
