# 宽协方差：数值守卫与自适应面板筛选

本阶段为隔离原型；正式源码、安装wheel和worker仍是 `33c2f2b95e374d396dc283c78d2ca5a43ad51a7a97995c3534ffdbae61ff7d39`，75项构建源哈希现场核对未变。原型没有接入Scheduler或发布。原先裸DSYRK的越界样本及历史失败结果保留在[上阶段证据](../README.md)，未放宽1e-12容差。

## 数学与实现

直接复用当前canonical均值、单元格归约及完整原生回退。分块误差守卫筛出无法保证逐项容差或零/正负分类的值，用原计算顺序局部重放；不确定项过密时整块回到canonical。对角位模式保持，不能把近零值修补为零。

默认512行中心化面板。中等矩阵使用最多2048行、32MiB面板，减少库调用；F输入的短序列按实际库布局写下三角，长序列仍用下三角存界。没有第二块完整D×D误差矩阵，输入保持C/F或支持的补边描述。[详细设计](../guarded-design.md)限定数学模型、所有权、预算和正式准入缺口。

176项原对抗样本及84项跨块、稀疏近零、恒定、重复/相关、scaled、tiny和中等面板控制通过；包含只读/输入位模式、边界哨兵、对称性、正负/零分类、对角位模式与完整回退位模式。稀疏不确定项确实采用局部重放，并非所有样本都回退。证据为 [correctness.json](correctness.json)、[guarded-correctness.json](guarded-correctness.json)。这不建立对所有未来BLAS算法的形式化数值保证。

[原生专项驱动](../guarded_native_check.cpp)以同一候选源码和已启用ASan/UBSan的原生静态库编译，覆盖五种形状、八类数据、C/F及补边、1/127/512行块，包括自适应面板513×257的尾块边界，共416调用检查相同契约与输入/输出哨兵；[结果](sanitizer.json)通过，无ASan/UBSan报告。系统Accelerate本身没有由本项目重新插桩。首次启动因macOS不支持 `detect_leaks=1` 在进入测试前终止，原日志保留，改为 `detect_leaks=0` 后完整重跑；首轮384调用及后续补充形状的416调用均保留，该结果不能声称LeakSanitizer或全引擎验收通过。

## 单核时间

六轮均衡轮换，分别运行三个进程；全部输出独立且保留前一结果，输入、线程预算和warmed NJIT相同。候选是包含输出分配、借用描述和完整守卫的ABI；现有C++是普通Scheduler完整请求，因此此表用于筛选，不能当作候选普通入口最终验收。计时不带malloc探针，10项完整输出均满足原容差。

| T×D / 输入布局 | 当前C++ ms | 候选ABI ms | NJIT ms |
| --- | ---: | ---: | ---: |
| 63×8 C | 0.004083 | 0.008792 | 0.003667 |
| 63×8 F | 0.003542 | 0.005896 | 0.003584 |
| 32768×64 C | 8.929 | 6.596 | 10.667 |
| 32768×64 F | 11.440 | 7.357 | 6.677 |
| 512×256 C | 2.196 | 0.762 | 0.735 |
| 512×256 F | 2.375 | 0.802 | 0.639 |
| 2048×2048 C | 578.988 | 80.922 | 94.297 |
| 2048×2048 F | 607.362 | 83.418 | 81.835 |
| 4096×4096 C | 5207.039 | 509.853 | 691.708 |
| 4096×4096 F | 5254.738 | 507.169 | 640.131 |

4096阶候选约10倍快于当前C++，比同核数NJIT快约26%/21%。2048阶C快约14%，F多约1.58ms；F这项微小差异只记录，不能独立否决。此前固定512行的守卫版2048阶为125.8/135.1ms，说明自适应面板有实际收益；其原始[计时](../guarded/timing.json)保留。初次守卫版4096阶F为465.3ms，此次为507.2ms，不能选择较小值掩盖轮次变化。全部样本及CPU/墙钟比见 [timing.json](timing.json)。

## 独立进程内存

24个fresh子进程覆盖两种阶数、C/F、三个后端和heap/RSS两种方法。输入和import/JIT完成后开始连续malloc epoch；准备、cold、释放、5次稳定预热、两次保留独立结果的warm分别记录。系统库首次工作区在heap epoch内；不通过预热转移后声称成本不存在。malloc跟踪无溢出，输出下界断言通过；探针不代表所有mmap/Python arena，RSS另报。

| 阶数（C/F同堆峰） | 当前C++ cold/warm MiB | 候选 cold/warm MiB | NJIT cold/warm MiB |
| --- | ---: | ---: | ---: |
| 2048 | 32.008 / 64.008 | 76.050 / 108.050 | 102.000 / 134.000 |
| 4096 | 128.008 / 256.008 | 150.097 / 278.097 | 390.000 / 518.000 |

候选比NJIT约少26/240MiB堆峰，但相对旧C++约多44/22MiB，属于真实面板/库成本，必须进入Planner和并行预算；不能套用“几KB可忽略”来隐去。具体额外库容量是本机测量，不能称厂商硬上界。

warm RSS请求增量：2048阶C，旧/候选/NJIT约32.031/32.047/38.094MiB；F约32.063/32.078/32.016MiB。4096阶C约128.094/128.063/128.078MiB；F约128.125/128.141/134.016MiB。页级小幅正负差仅作观测，不据此阻断；候选已保留的工作区影响基线，不能只看warm RSS增量判断总内存优势。完整准备、cold/warm和监测盲区见 [memory.json](memory.json)、[memory-2048.json](memory-2048.json)。

## 自审核与范围

可继续正式接入设计：当前筛选修复了观察到的数值失败，并获得显著大负载收益。尚需独立根/下游离散消费资格、非标准舍入模式拒绝、共享内部接口、Workspace/Planner预算、完整尝试与回退审计及worker传输；继而验收真实ordinary/prepared/线程/进程/共享内存路径。筛选未包含这些生产职责，不能据此宣称引擎全量通过。

数学/Excel逻辑DAG、公式和符号预算均未改变；本轮没有新的Microsoft Excel重算，没有重跑全引擎Python回归，也不引用前轮9481项作为原型验收。全算子中大型时间/内存整体目标仍开放。修改仅本地证据与筛选代码，未提交、推送或修改研究平台。

[manifest.json](manifest.json)记录原型库、源码、参数、基线身份和全部原始证据的SHA256。原计时和memory-sweep可用[复用驱动](../guarded_screen.py)及[原驱动](../screen.py)重跑；2048内存的完整子进程命令亦记录在JSON中。三个4096阶完整输出快照移到清单列明的临时证据目录，保留字节数/哈希和实际文件；不把384MiB可再生成样本混入源码交付。
