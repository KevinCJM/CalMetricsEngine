## 完整峰值

长矩形131072×1024×512，C→C/F→F各一种。每backend/layout有一个启动预载malloc探针子进程（每个3请求）、三个fresh RSS子进程（每个3请求），共24个子进程；没有与时间、构建或回归任务交叠。RSS报告warm第三次调用峰值减最初fixture/runtime RSS，不用不同import总RSS宣称节省。

| 探针 / 布局 | 旧版 bytes | 候选 bytes | NI bytes | 候选−旧版 bytes |
|---|---:|---:|---:|---:|
| heap / CC-C | 2,151,689,824 | 2,156,010,256 | 2,156,003,744 | 4,320,432 |
| heap / FF-F | 2,151,689,824 | 2,156,010,256 | 2,156,003,744 | 4,320,432 |
| rss / CC-C | 2,156,593,152 | 2,169,274,368 | 2,164,539,392 | 12,681,216 |
| rss / FF-F | 2,156,544,000 | 2,165,063,680 | 2,164,801,536 | 8,519,680 |

没有显著内存节省：malloc增加4,320,432 bytes（约0.2%），fresh RSS中位数增加约0.4%～0.6%；对NI的malloc只差6512 bytes、RSS差0.26～4.73MB，不能称降内存或把这些差值作为大额收益。这里独立输入副本及两代结果本身要求2,151,677,952 bytes活跃数值存储。采用保留大额时间收益并提供预算重选，峰值增加如实披露；整体目标未关闭。

实际构建另以每layout/探针1个fresh子进程、各3请求确认，共4个子进程。该确认不冒充三次fresh统计；完整原始值见stage/v54-actual-memory-status.json。malloc拦截有Python arena、zone、mmap、栈盲区；0.5ms RSS采样可能漏瞬态。
