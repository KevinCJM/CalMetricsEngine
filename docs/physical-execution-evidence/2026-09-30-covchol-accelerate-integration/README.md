# 协方差→Cholesky 的 Accelerate 本地候选接入与验收

2026-09-30，本机 macOS 15 arm64、CPython 3.12。目标是消除 4096 阶单根图约 7 秒的主要计算瓶颈；基线为前一轮独占缓冲 wheel，构建身份 `a63f72ba69ac969b2a60f90254ad15e8075a05ae15639cc9fe7561b229efa699`。最终源码、wheel、安装扩展和 worker 的构建身份均为 `91267c23ac014c947e67ae31054dddc8aaa102fadd12f2ce4331c87752c63758`，逐文件与二进制哈希见[构建清单](build-identity.json)。本轮没有提交或推送。

## 设计及自审核

仅在**单一独立数值根** `cholesky(covariance(x))` 已被物理融合时准入：矩阵维数 `D≥2048`、`T≥D`，输入是精确连续 C/F `float64`，实际计算结果缓冲为 C 布局；`error_policy=isolate`、直接算子及共享协方差的多根图沿用原内核。Welford 均值仍按每列原观察顺序生成；512 行中心化面板经 Accelerate `dsyrk` 汇总样本协方差，再在同一独立结果缓冲用 `dpotrf` 分解。BLAS 线程限制在当前调用内设为单线程并恢复；没有额外进程或 Python 数值回调。显式 F 根结果由已有布局步骤转换，保留请求的连续布局。

准入检查非有限值、`1e-8≤max|x|≤1e4`、对角有限且正、接近零的协方差，以及成功分解后的最小/最大 Cholesky 对角比 `≥1e-3`。任一检查或库分解失败时重新执行原协方差→分解链，保留原错误与输出行为；近零值不会流入下游离散消费者，因为快路径仅用于单一最终根。新路径对普通大矩阵采用 `rtol=atol=1e-12` 的浮点对照，不声称逐位一致。[隔离原型的 72 组准入/回退筛选](guarded-screen.json)中 16 组准入、56 组回退；该筛选不能代替正式 Scheduler 测试。生产回归另覆盖 C/F 输入、C/F 输出、普通/prepared/进程、近零协方差、奇异、非有限、极值、共享根和结果所有权。

每个并发执行的均值临时区 `D` 与 512 行面板合计最多 `513*D` 个 double，纳入 Planner；原结果直接写入请求独立缓冲。审计的 `accelerate_covchol_calls` 仅记录成功快路径，`algorithm_copy_bytes` 记录中心化面板写入量；`operator_workspace_capacity_bytes` 只含保留的 512 行面板，不含短命均值区，也不能代表系统库内部所有分配。worker 响应增加审计字段，IPC 双向 magic 升为 14。Excel 的算子数学、公式展开与预算没有改变。

## 完整请求计时

[原始六轮轮换样本](timing.json)使用同一只读输入、一个 CPU token、已预热 NJIT、每次独立结果、前次结果保留到下一次返回。单位为毫秒，中位数；所有准入大矩阵的成功计数为 1，CPU/墙钟中位比约 1.00。

| 输入/入口/输出 | 旧 C++ | 新 C++ | NJIT |
| --- | ---: | ---: | ---: |
| 2065×2048 C / ordinary / C | 804.557 | 138.242 | 180.620 |
| 2065×2048 F / ordinary / C | 829.293 | 157.441 | 172.898 |
| 4113×4096 C / ordinary / C | 7027.434 | 763.231 | 1659.567 |
| 4113×4096 F / ordinary / C | 7059.014 | 685.988 | 1605.745 |
| 2065×2048 F / prepared / C | 846.595 | 157.582 | 177.834 |
| 2065×2048 F / ordinary / F | 862.075 | 185.378 | 198.834 |

63×8 C/F 普通入口分别为旧/新/NJIT `0.008021/0.008000/0.004459` 与 `0.007354/0.007146/0.004396` ms；没有引入有意义的小任务退化。F 输出对 NJIT 的差距较小：另一轮为新 `187.324`、NJIT `186.460` ms，因此不把此形状称为稳定明显领先。[基准脚本](public_benchmark.py)保留绝对本机安装路径和全部原始数据；异机复现须重设路径、版本与 CPU 限制。

## 内存与验收边界

[新进程申请堆及 RSS 原始值](memory.json)包含 setup、冷请求、释放后及保留两个独立结果的暖请求。下表是冷态申请堆峰值，单位 MiB；堆探针覆盖 malloc/free，不涵盖所有系统映射、栈和 Python arena，RSS 另在原始值中记录。

| 输入维数与布局 | 旧 C++ | 新 C++ | NJIT |
| --- | ---: | ---: | ---: |
| 2048 C / F | 32.262 / 32.262 | 42.603 / 48.024 | 102.532 / 102.532 |
| 4096 C / F | 128.512 / 128.512 | 150.040 / 150.040 | 391.063 / 391.063 |

4096 阶新路径比旧版增加约 **21.5 MiB**，这是实质内存成本；但比 NJIT 少约 **241 MiB**，且完整请求时间明显更短。对应新路径 C/F 冷态 RSS 总峰约 `348/477 MiB`，NJIT 约 `663/657 MiB`；不同布局的输入驻留和页面回收使 RSS 增量不可直接当作同口径算法工作区，不能从单项采样推断零额外内存或普遍优势。暖态保留两结果的申请堆峰值新路径约 `278 MiB`、NJIT 约 `519 MiB`。当前本地 CMake 候选默认开启，但这一实质内存增加已提交给用户决定是否允许作为正式默认；在得到答复前不提交或推送。

另做了[直接借用原始输入的库方案筛选](../2026-09-30-covchol-raw-input-screening/README.md)：独立 ABI 的 4096 阶冷堆峰约 `140 MiB`，仍高于旧 C++，且尚无完整请求验收，因此没有替换当前实现。
