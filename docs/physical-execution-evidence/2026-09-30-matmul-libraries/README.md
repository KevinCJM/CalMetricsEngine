## 内存

明确为31/90用例子集、186个独立子进程，覆盖方阵、长宽矩阵、特殊stride、三个入口与小任务。冷态包括setup和首次数值执行，暖态保留两份独立结果。活跃堆冷/暖峰值31/31与旧版相同，24/31低于NJIT。1024阶CF普通入口暖峰旧/新均16,792,266 B，NJIT为23,069,744 B。分配探针不能单独证明Python arena、栈、库映射与RSS不增长。

正式对象的旧F右矩阵暖本地调用链峰为496 B，新数值叶子核416 B，调用方320 B帧在尾跳前释放。新算术阶段比旧通用循环本身多96 B；不把416 B解释为固定Array物化大小，反汇编未见浮点/向量寄存器的栈读写。系统版本判断及冷初始化的完整下游栈未定界。

31组原始RSS中，总峰新减旧中位+163,840 B，范围−4,276,224至+17,809,408 B，17/31为正；请求增量差中位−16,384 B，15/31为正。不能凭活跃堆相同把这些增量直接称作噪声，也不能据此证明满足用户的“显著提速且内存不增加”条件。

详见 [原始内存结果](memory.json)、[内存摘要](memory-summary.json)及 [正式对象审查](matmul-formal-review.md)。分阶段RSS归因另行保留，不替换原31组结果。

额外13阶段归因：3个固定用例、每例11次AB/BA配对、66个独立进程，全部输出一致。请求RSS增量的新减旧如下；各列分别统计，不能把中位总峰与中位baseline相减当作中位请求差。

| 案例 | 增量差中位 B | 范围 B | 正差次数 |
| --- | ---: | --- | ---: |
| 32768×64×32 FF ordinary | −16,384 | −16,744,448至+16,957,440 | 5/11 |
| 1024³ CF direct | −81,920 | −8,486,912至+8,486,912 | 2/11 |
| 512³ CC ordinary，未改路径对照 | −114,688 | −4,210,688至+6,373,376 | 4/11 |

1024³ CF direct同时保留两份结果时，物理footprint相对backend_import的配对净差中位为+8,208,192 B，释放后为−32,768 B；同时internal增加、reusable下降，提示驻留页状态变化，不能只看RSS接近持平就宣称物理内存未增加。类别之间不可简单相加，也不能仅凭关联认定根因。

此处cold为输入构造、哈希和导入后的首次MatMul；哈希曾分配/释放输入副本。858份Mach快照字段均有效，但名义0.5ms采样的实际最大全局间隙为5.260ms，阶段切换最大间隙为2.647ms。每阶段暂停20ms、快照与采样会影响运行，仍可能漏掉瞬时峰值。该诊断不替代原始连续请求，也不建立统计等价或内存通过。详见 [RSS归因分析](rss-attribution-analysis.md)与 [采样脚本审核](rss-stages-review.md)。

## 未采用的方案与后续

直接Accelerate BLAS在132组受支持筛选输入中7组超出原容差，其中6组改变非有限分类；因此没有无条件替换。原容差未收紧，也未新增全局逐位约束。它在1024阶预分配输出原型中另需6,291,464 B活跃堆，而原核与Eigen候选为0；此原型只测额外工作区，不能替代完整请求内存验收。

下一步保留两个方向：受现有契约与内存约束的成熟GEMM准入，以及减少Eigen保序表达式调度开销。更宽表达式只是待测候选，不能把计划当作加速证据。中大型全面领先NJIT、RSS不增加以及跨平台验证仍未完成。
