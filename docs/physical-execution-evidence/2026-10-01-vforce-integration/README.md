# 大数组 exp/log 原生库接入设计与验收

2026-10-01；本轮只优化已有 exp/log，数学契约与 Excel 公式不变。
前置筛选位于同级 `2026-10-01-vforce-screening`：1600 万元素 exp 193→38 ms、log 111→45 ms；malloc 峰值与独立结果字节相同，无新工作数组。筛选尚不能代替完整 Scheduler 验收。

## 设计

- 使用 Apple vForce vvexp/vvlog；限定已验证的 macOS 15 arm64、Accelerate 开启构建。显式 scalar/SIMD 请求保留既有内核。
- C++ 检查输入与独立输出形状、float64、布局、舍入方式及全量值域，再执行库调用。exp 有限且在 [-700,700]；log 有限且不少于最小正规数。拒绝发生在首次写入前，随后原内核负责 NaN、定义域、溢出、错误顺序与已写前缀。
- 至少 1024 元素的同序连续 C/F 输入直接写独立结果。F 第一轴连续的部分窗口按列/平面执行，每段至少 1024 元素；全量预检先于任何段写入。没有打包、转置或全尺寸工作区。
- 直接算子 API 的 automatic 模式允许该路径。图执行仅允许单个 float64 数组根、无消费者、无作用域、非 isolate、非观察者路径；内部节点、比较/状态消费者、迭代、多个根保留原数学顺序。不会扩张 pointwise 的可融合算子范围。
- 自动布局仅对符合独立根条件且原输入为大数组连续 F 的 exp/log 选 F；显式 C/F、类型、逻辑坐标与结果独立所有权不变。读取 prepared 当前输入，不缓存数值或值域判断。
- 库运行在 Scheduler 已批准的一个 CPU token 内，不新增线程池、进程、全局线程设置或 Excel 热路径。新增实际调用数 `accelerate_vforce_calls`，贯通子图累加与进程审计；worker IPC 17→18，既有 Program v7/v8、结果描述协议不变。

## 验证计划与采用标准

逐算法原容差、IEEE 分类、零/符号与离散消费者精确回归；C/F/张量/部分窗口、坏值拒绝、写前缀、观察者、独立生命周期、prepared 输入变化及单线程/线程/inline/shared process。native、ASan/UBSan、库 OFF、全 Python 回归和 wheel 身份分别验证。

完整真实 wheel 与原构建及 warmed NJIT 同核比较普通入口、prepared、前一独立结果保留、冷/热 malloc 峰值与 RSS。几 KB/几 ms 差异不能单独阻断；中大型实质退化、数值/所有权/资源失败仍不得通过。原始失败负载保留，不能据两个算子通过关闭全引擎性能缺口。

Excel 适用 X1、X3、X4、X6、X9、X10：逻辑图与公式/预算不变，观察执行保留 canonical；仅物理布局与数值实现变化，复核历史目标 Excel 快照和公式身份，不将缓存对照称为重新执行 Microsoft Excel。

库接口依据：[Apple vForce](https://developer.apple.com/documentation/accelerate/vforce-library) 与本机 SDK `vForce.h`。库文档不自动证明本项目精度、并发或收益，以实测为准。
