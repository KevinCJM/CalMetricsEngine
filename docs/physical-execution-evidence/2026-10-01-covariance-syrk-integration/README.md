# 独立协方差根：本地实现、设计和验收

基线是 `33c2f2b95e374d396dc283c78d2ca5a43ad51a7a97995c3534ffdbae61ff7d39`；开始变更前核对了其源码、wheel和worker身份。[隔离筛选](../2026-10-01-covariance-syrk/adaptive/README.md)通过260项数值及416次原生ASan/UBSan检查后，才接入实际图、Workspace、Planner及worker。当前最终构建是 `ac5da987ed48dcf6647098345618c02cf7d2fa1a82abedfcf90c721ecf9e5021`；以下最终数据来自其实际独立安装包，不将ABI筛选当成正式包验收。全算子、中大型所有时间和内存指标全面领先NJIT的目标仍开放，未提交或推送。

## 设计和纪律

适用D1/D2/D5/D6/D8及X1/X9/X10。逻辑AST、canonical算子、dtype/shape、样本除数和Excel公式不变，不增设公开算子。优化从同一原生内核提取有限的内部均值/单格接口，原路径和新路径共用唯一数学实现，不在生产包含`.cpp`。

- 资格：非隔离、无子作用域、单一float64矩阵根的`covariance(X)`，且没有任何内部消费者；观察器/Excel、比较、共享/多根及子图继续原顺序。macOS15+arm64、Eigen和Accelerate均启用、`32≤T≤1,000,000、256≤D≤4096`及正向C/F兼容输入，仍逐次检查数据和标准舍入环境。其他情况继续原生计算，无Python数学回调。
- 数学：沿用筛选版确定性舍入界、共享canonical均值、局部重放和过密时完整重放；正负/零分类及对角位模式保持，容差仍1e-12。库算法/构建依赖和模型假设见[推导与限制](../2026-10-01-covariance-syrk/guarded-design.md)，不宣称厂商认证的形式化证明。失败先恢复调用线程的BLAS策略，再重放原计算；恢复失败作为原生资源错误传播。
- 结果：复用本次独占C结果下三角存储界/标记，无第二个D×D矩阵；显式F继续使用既有布局物化和审计。输入、旧快照和其他根均不作为工作区。均值只在本次计算共享，prepared输入改变时重读，不缓存数值结果。
- 面板：实际为`(B+3)*D*8`字节，默认B=512；T≤2048且D≤2048使用B=T，最多约32MiB。由独占Workspace提供，大小变化释放旧超额容量，不使用请求外私有面板缓存。面板中心化是数值物化写入，单独审计，不把它当作零拷贝绑定或原始输入复制。
- 预算：shape-only reserve涵盖区间内较短T可能选择较大面板的非单调情况；D≤2048按最多2048行估算，再加32MiB系统库工作区估算。实际已测库峰值不等于厂商硬上界，仍报告malloc/RSS及预算盲区。single/thread/process均服从同一Scheduler预算，BLAS只使用当前调用线程的一个CPU token。
- 回退：未准入不写结果；尝试后的拒绝/过密会释放面板，完整canonical重写尚未发布的独立结果。原生审计保留尝试次数、DSYRK块次数、成功次数、实际重放单元格数（含已做对角及完整重放）、回退次数、所有已物化面板字节和库reserve。不能被canonical的audit重置覆盖，贯通child和worker；初版IPC16，加上精确零计数后为IPC17。
- 精确零特例：首轮完整请求发现2048阶全零先DSYRK再重放增加约60–66ms，不能按微小波动忽略。已有输入资格扫描同时识别全零；全+0的canonical均值、居中乘积、归约和除法精确为+0，标准库直接写独占结果，`covariance_zero_calls=1`、库尝试/调用为0，释放旧Workspace。含-0的全零输入继续原布局canonical归约、不尝试DSYRK，保持零符号。每次重读，未准入形状/图/平台不变；这是物理特例，不增加公开算子或Excel公式。

## 自审核、正确性和构建

- 四lane、输入C/F/补边、结果auto/C/F、readonly与跨行/跨请求独立所有权均验证；prepared重读数值、尺度与零符号，释放不再使用的面板，保留先前快照。数据扫描不消费补边坏值；负、非单位、广播stride及短/窄输入逐位沿canonical。原生哨兵与非最近舍入拒绝检查通过。
- 比较、多根、isolate、迭代/子作用域和Excel观察器不进入私有路径。稀疏不确定项、全量拒绝、非有限输入的局部健康单元格、长序列4097/8193/32769及非整块尾部通过。C/F对角、NaN/Inf、零/符号分类精确核对；完整回退输出逐位一致。标准库精确零路径并非BLAS调用；含-0全零仍用原布局归约。
- 实际single调用在SDK的两种BLAS线程模式下，成功和回退均恢复原模式。形状预算覆盖4096行区间中的较短1041行较大面板；低预算在执行前拒绝。仍保留原Planner的粗粒度保守余量，未把reserve估算写成真实分配量或完整厂商上界。
- 数学代码只有一个canonical实现，抽取内部均值/单格接口后共用；无生产`.cpp`包含、Python数学回调、新线程池或跨请求数值缓存。新字段在operator、图、child、bindings和IPC17贯通，原生wire版本断言及真实worker回归通过。

初版 `a927b2ef...` 的81专项、9554/9562全量及原生结果保留；补零特例后的结论只使用上述最终构建。首次sandbox共享内存拒绝通过已有授权重跑；真实进程的补边F会按既有运输打包成C，旧、新worker的对角位模式完全相同。夹具改为核对实际worker canonical，另保留原F的1e-12对照，不改运输或放宽数学口径。[实际运输控制](transport-diagnosis-actual.json)显式验证plan.lane；初次CPU=1/单行误选single的[控制](transport-diagnosis.json)已标为误配置、保留原始数值，不能作为进程证据。

**仍未关闭：**放大输入的原canonical本身远慢于NJIT，新尝试还增加约11–13ms；长序列高相关数据完整重放增加约36–42ms（约28%–29%），新包约为NJIT的2.2/3.3倍耗时。这属于有规模的真实欠项，不能用几ms政策、跨负载平均或良态4096阶成绩掩盖。下一步应减少无法通过守卫的无用试算，并继续处理混合符号MatMul、稠密有界Jacobi等已有大差距。

## 实际内存和取舍

40个fresh child覆盖两大形状、C/F输入、五种入口/参考、heap/RSS；另20个fresh child覆盖2048阶全+0。heap为连续epoch，包含实际setup、cold首次调用/释放、五次warmup及保留两份独立结果的warm峰，不把各阶段峰相加。输入/import/JIT在epoch前；预热前的库缓存、Python arena、调用栈、mmap并非完整覆盖，RSS作为独立页级观察。探针启用、表溢出为0，cold/warm峰至少包含一/两份输出；独立探针自测通过。首次探针自测遗漏注入环境返回2，空日志保留；正式采样各heap child均显式注入且验证峰值，不使用该遗漏配置的数据。
