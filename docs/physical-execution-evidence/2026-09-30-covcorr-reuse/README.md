本地实现及回归通过，完整性能目标仍开放。基线为实际构建 `18977f51909481ec8e88ee73fd24b88ccc83743cc2e82d01c25c2d459547f4a0`，新构建为 `6ff48aac8a819ad1854a33d51cd76221d902bcc7ede4e293860e9e7f86a30dd0`。两者使用同长真实安装目录；源码、wheel、安装扩展及 worker 身份核对一致。没有提交、推送或修改研究平台。

## 设计与实现

同一图的 `covariance(x)` 和 `correlation(x)` 原先分别执行一遍协方差核心。此次复用已完成的协方差直接根，使现有成熟 Eigen 核只计算一次；没有新增手写协方差算法或替换其数学规则。

- 仅在非观察器、顶层 typed 执行中复用。同源由相同父节点 ID 确认；协方差必须先完成、健康、有限、形状匹配，且仍位于本次区间的独立结果槽。原 prepare、继承状态、输出形状/dtype/容量检查先执行。空列、少于两行、反序、不同源、非直接根、子作用域或非有限值保持原路径。
- 扫描现有 roots，不新增配对数组、工作区或跨请求缓存。将协方差复制到相关系数的独立输出后，调用从原代码唯一提取的归一化/镜像函数。标准差检查、保存最后对角、除法及镜像顺序保持；不能将其描述为零复制。
- 相关系数因零方差失败时，原错误隔离/传播仍生效，协方差结果保持健康。实际 `D²×8` 复制字节在可能失败的归一化前计数，实际 Eigen 调用从两次降为一次。重复根、上一份结果、prepared 更新输入和四种执行 lane 均有覆盖。
- Planner 继续使用保守的原成本上界；没有新增协议、参数、公开算子、线程池或库依赖。AST/DAG 逻辑与 Excel 两个算子的公式、展开预算和导出行为不变；普通 C++ 请求不执行 Excel。

## 内存与采用边界

8 项 × 3 后端 × heap/RSS，共 48 个全新 child。图构建和 Scheduler 准备计入冷态，首次目标数值计算没有提前预热；暖态保留前次独立结果。输入、依赖导入和 NJIT 签名编译在 epoch 外，不将其称为全进程绝对冷启动。RSS 冷/暖两阶段的最大峰减原冷态 baseline，不相加两次增量。

8 项旧/新冷、暖活跃堆峰及结果释放后的 tracked 常驻字节相同。大矩阵的暖峰显著小于 NJIT：D=8/16/64 时分别为 17,626/23,770/146,650 B，NJIT 为 4,458,684/8,657,596/34,702,012 B。这是请求内探针覆盖的堆，不含预存输入、全部系统栈或未追踪运行库。24 个 heap child 均无探针表溢出；旧/新每个 child 的最终 `untracked_frees=5`，NJIT 为 0，保留未追踪出生的释放这一范围限制。

RSS 每项每后端仅一个独立进程；请求增量新−旧在 3 项为正：32768×8 C 增加 114,688 B、32768×16 C 增加 16,384 B、32768×64 F 增加 327,680 B。其余正负观察同样保留，不能仅凭堆相同宣称 RSS 不增。采样可能遗漏短峰；累计分配、复制量和单个计数分别用于解释，未增加“每个计数都必须降低”的规则。

本轮解决重复计算并保留成熟库核心，尚未解决该核心相对 NJIT 的时间差距，也未证明完整 RSS 不增。因此只作为本地优化进展，不宣称整体联合验收通过。
