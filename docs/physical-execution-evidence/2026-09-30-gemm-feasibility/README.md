# Full-K GEMM 输出分块：可行性结果

2026-09-30，macOS arm64。**候选未接入生产；完整时间/内存目标仍未达标。**
当前生产源码与既有构建 `18977f51909481ec8e88ee73fd24b88ccc83743cc2e82d01c25c2d459547f4a0` 的全部数值文件及安装二进制 SHA 一致。研究平台未修改，未提交或推送。

## 设计与边界

在独立 C++ ABI 中调用成熟 Accelerate NEW_LAPACK LP64 DGEMM，固定四种方式：整次调用、M/N 输出块64/128/256。每块保持完整K、alpha=1、beta=0，借用原C/F正向leading dimension，直接写入独立C输出的子区域并保留原ldc。没有第二结果矩阵、输入打包代码、K部分和合并或跨请求缓存；库内部打包成本另测。当前18977包装链接真实现有静态库，未重写基线数学。

按AGENTS、数学纪律D1–D8和Excel纪律X1–X10复核。浮点使用原2e-12/2e-14比较容差；逐位相同只是观测，不增设全域bitwise要求。NaN/Inf、离散比较及错误边界须另验。分配次数和累计流量也不是用户单独要求不得增加的指标；完整峰值、常驻、结果寿命、栈与RSS均需有证据。

[Apple线程局部接口](https://developer.apple.com/documentation/accelerate/blassetthreading%28_%3A%29)在调用线程内保存、设置并核对单线程策略，结束后恢复并核对；异常恢复失败不能伪装成回退成功。该控制在早期失败原型中已存在，不把重新加开关算作解决历史缺口。库仍只适用于对应平台，本轮没有跨平台采用结论。

## 实际验证

- 独立源码审核未发现布局/边界/线程恢复阻断；原型编译无警告。
- 100组精确整数几何smoke通过，覆盖CC/CF/FC/FF、padding、尾块、输入hash、输出canary和线程策略恢复。
- 数值筛选保留原168夹具，加14个大K反例，五实现、两种输出初始化，共1820记录。当前基线182夹具通过；每个库候选支持146、拒绝36（每种初始化分别统计）。整次/64/128/256分别有9/10/10/9个受支持夹具失败，两个初始化合计76条失败记录；原容差和投影布尔差异均保留。64/128块还新增了 `cancel_129_3_33_cc` 消去失败；完整K并未保证原归约语义。
- 全部已执行输出canary、输入不变及线程恢复检查通过。投影布尔是对数值输出的独立比较，不冒充公开AST/DAG状态验收。
- 30个独立heap进程完成。输入、输出、CDLL和hash准备在epoch外；首次数值调用和线程设置在cold epoch内，各17次调用。端点线程数均1，不代表已测瞬态最大线程数；探针未跟踪释放和表溢出均0。

## 时间：仅独立输出ABI诊断

固定512³、1024³、64×32768×64及CC/CF共6项，当前核、四个库候选、预编译NJIT；12轮均衡轮换，每个后端首位两次。SciPy先载入、同线程策略核对，NJIT显式设置单线程并恢复；库候选在其C++调用内自行设置/恢复。计入结果分配、ctypes入口和全部tile调用，前一独立结果及一份固定参照在测量中保留。没有硬绑核，轮次来自同一进程。NJIT的TLS切换在计时外，C++候选的切换在调用内，因此几个百分点的接近或领先不能当作严格同边界胜出。

| 输入 | 当前核 ms | 整次GEMM ms | 256块 ms | NJIT ms |
| --- | ---: | ---: | ---: | ---: |
| 512³ CC | 11.167 | 0.928 | 0.998 | 0.971 |
| 512³ CF | 13.608 | 1.134 | 1.088 | 1.104 |
| 1024³ CC | 94.215 | 8.293 | 16.192 | 7.902 |
| 1024³ CF | 106.977 | 8.430 | 8.515 | 8.108 |
| 64×32768×64 CC | 14.105 | 2.551 | 2.347 | 2.429 |
| 64×32768×64 CF | 15.189 | 4.862 | 4.533 | 4.821 |

表内是各自样本中位数，不等于配对比。完整配对样本在原始记录中保留；整次GEMM/NJIT配对中位比范围0.960–1.040，64块范围0.999–2.468。长K两项的M/N均为64，四个库标签实际均调用一次相同几何的DGEMM，不能将其轮间时间差归因于分块参数。成熟GEMM恢复了大部分旧核差距，但没有证明普遍明显领先NJIT；1024 CC分块还比整次GEMM更慢。这不是普通Scheduler、图或进程入口验收，也未计入尚未实现的数值保护/回算成本。

首份7轮计时没有可靠核验NJIT的Accelerate TLS，且顺序不均衡、上一case残留引用可能在下次首轮释放；保留为 `timing.json`，不作为同核结论。上述表只来自修正后的 `timing-controlled/timing.json`，不是挑选更快的一轮。

| 512³ CC | 0 | 65544 | 65544 | 65544 | 65544 |
| 512³ CF | 0 | 1048584 | 524296 | 1048584 | 1048584 |

| 1024³ CF | 0 | 6291464 | 1048584 | 2097160 | 2097160 |

1024 CC从约6 MiB降至128 KiB，但相对当前核仍增加工作区。64块单次累计申请33554440 B、257次分配，峰值131080 B；累计流量与峰值不能相加。全部库child在结果阶段后另保留8 B活跃堆，尚未唯一归因，不称为泄漏。没有进行新一轮RSS、完整栈或公开请求内存验收；这些结果不证明总内存不增加，也不关闭前轮RSS疑点。

## 数值差异的进一步定位

固定随机计时输入也有近零差异：1024 CC/CF每项4个格子、长K CC/CF每项1个格子超出候选对当前核的原比较容差，IEEE分类和零符号比较相同。另对CC的5个独立格子用200位十进制乘加与fsum核验：当前核、整次GEMM各有2/5格落在原绝对/相对容差内，长K那格两者均超出。不能将当前核或库结果自动当作数学真值，也不能据此放宽容差或改变历史行为。

这部分高精度检查只覆盖上述5格，不是完整矩阵精度证明。首次诊断因NumPy bool序列化失败，修复仅转换Python bool，原失败记录、脚本和未改的输入/算术/容差均保留。

## 结论与下一步

不将该未经数值保护的DGEMM替换当前MatMul。下一步需要先验证可实施的数值准入/回算范围及真实成本，明确图中离散和错误敏感消费者的保序边界，同时解决受预算工作区；不能仅凭随机结果接近或库速度接近NJIT放行。全域逐位相同、每个分配计数不增也不能被擅自增加为永久门槛。整体目标仍是全部算子的中大型时间和内存优势，小任务无明显劣化。

本轮运行代码、数学版本、AST/DAG/Planner/worker、Excel公式和预算均未变，因此未重跑全仓回归或Excel，未改执行指南、算子参考或AGENTS。既有7168项回归等仍是上轮构建证据，不表述为本轮重新执行。
