# 下一轮矩阵重点：先复验，再减少大额重复存储

2026-10-04。本文件是设计候选，不是已实现或已验收能力。当前源码为977；HMM尾行的证据不能关闭矩阵欠项。

## 1. 秒级时间差距

先用当前正式包复验之前明显落后的大型 `solve_multi` 和协方差负载，保留全部失败形状、C/F布局、相同CPU预算和两代结果。历史4096阶LU仍比热NJIT慢数倍，列条带候选也没有实质收益；详见[已采用行分组](../2026-10-01-lu-grouped-integration/README.md)和[未采用列条带](../2026-10-03-lu-column-screening/README.md)。这些是历史测量，不冒充977实测。

当前 `solve_multi_library.hpp` 已使用Eigen固定数组更新，但仍保持原first-max主元、逐主元乘减、即时RHS更新和绝对1e-14判据。库默认GETRF/GETRS不能仅凭数学目标相同替换这些可观察契约。继续优先评估成熟库；需要明确兼容证明、受控核数、异常重放及完整请求收益后才能采用，不能放宽误差或删除失败负载。

## 2. 私有系数矩阵重复存储

已核对当前 `matrix_foundation.cpp`：`solve_multi` 的准备声明N² doubles scratch，执行先复制并验证B到自己的输出，再复制并验证A到私有系数工作区，随后调用已有Eigen有序消元及原回代。因此计算图中已经物化的私有A还可能与N² solver scratch同时存活；4096阶每份为134,217,728B（128 MiB），是值得筛选的大额目标。

候选只允许明确由本次图生成、位于独占C连续arena、非输入/公开根/过去结果、具有唯一消费且无后续借用别名的系数矩阵，临时作为当前求解的可写系数区。接口及逻辑DAG保持，继续调用同一消元/回代实现；先保持原B→A验证顺序，不能因为少了复制而省略有限性检查。纯私有区域在失败后无需保留数学结果，但必须保证下次执行完整重建，并拒绝观察器、isolate、子作用域和无法证明所有权的路径。F、负步长和外部输入初版保持canonical路径，不强行统一布局。

实现前必须给出完整alias/liveness证明、内部调用权限、Planner及实际Workspace容量决定；不能只删除预算或把只读指针强制转换为可写指针。独立结果、公开Prepared输出及共享输入不能作为系数scratch。无需跨请求分解缓存，不新建线程池，不增加canonical算子。

## 3. 验收与采用

先隔离筛选完整的“系数生成→多RHS求解→结果返回”图，和没有私有系数区的负控制；不把128 MiB纸面容量直接记作完整峰值节约。旧/新逐位及错误/失败前缀、残差、只读、旧结果、失败恢复、prepared/线程/进程等按适用接口验收。成熟库OFF和实际SAN覆盖进入的新分支。

同数据、算法、输出、核数与结果保留的热NJIT比较包括输入准备、普通绑定/规划、实际分配/复制和结果封装；分别报告完整heap/RSS及盲区。若显著减少中间存储但时间仍明显落后NI，可如实分阶段采用，整体目标仍开放。几KB/ms只诊断，不继续追逐条带微调。
