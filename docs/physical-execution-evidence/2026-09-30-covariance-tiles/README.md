## 实现与自审核

- 复用固定 Eigen 3.4 的公开 Array/Map 表达式及 SIMD，保留单计算核、禁用 fast-math/FMA 和私有线程。项目负责与既有数值规则一致的遍历；未启用默认 GEMM 或重新手写分解库。
- C 兼容布局保留原 macOS15+arm64、auto/Eigen、N≥32、D≥8、列 stride=1 的准入。用 4×4 特征块和 128 行时间块；每格从既有输出累加器继续按递增观察次序计算，不把各块独立部分和相加。均值保持原 Welford 顺序，统一最后除以 N−1。
- 结果末行暂存均值，最后一个消费者完成后才覆盖。D 为4的倍数时，底部4×4对角块单独完成，减少重复扫描；其他边缘使用原顺序归约。支持原有正、负、零行 stride；输入和保留结果不作工作区。
- F 兼容布局仅在 D≥8、列 stride≥N、有限且满足原溢出界限时合并跨列均值扫描；全长居中内积不改。跨列 strided 均值的实际对象为标量运算，不能把它描述为 SIMD；内积保留 Eigen SIMD。特殊列 stride、非有限和超界值保留原路径。
- 原型 V1 全长 C 分块使宽/补边矩阵退化；V2 时间分块修复，但8列块栈更大；最终采用 V3 的4列块与底部对角块。F 的128/256行分块在长宽矩阵退化，未采用。三轮完整正负记录均保留，没有挑选有利用例替换冻结结果。
- 首个正式构建将普通 return 优化成 call+true，已知 C 链栈从688增至880B。加入 AppleClang `musttail` 强制外层释放栈后分派；旧构建/源码/测试保留，最终重新构建验证。内部 driver 仍有48B活跃帧，不声称所有层级都尾调。

## 内存与未完成条件

内存预登记36/108项：32×8、32768×64、512×256×4布局×3输出；每实现/用例分别启动heap与RSS子进程，总计216进程。区分准备、冷态第一次执行、释放结果、暖态基线、保留上次结果的11次执行及释放后常驻，禁止相加阶段峰值。

36项的旧/新各阶段跟踪堆峰、活跃字节、分配/释放次数和累计字节逐项相同，表溢出均0。24项中大型冷/暖跟踪堆峰均低于NJIT；12项小输入更高。示例32768×64 C联合暖堆峰：旧/新均146,658B，NJIT为34,702,012B。该示例不代表整进程峰。

探针并非完全没有未跟踪释放：12个原生联合请求在cold-retained/warm-baseline/warm阶段分别出现1/4/5次，旧新完全相同，NJIT为0。它们来自探针当前表外的释放；尚未把每个指针追溯到分配点。以上是当前epoch跟踪堆的相等证据，不是整个进程的分配完整性证明，也不能据此声称全部分配器已经审计无遗漏。

RSS新−旧总峰中位+73,728B，19/36为正；请求增量中位0，17/36为正，最大+4,194,304B（512×256 F联合暖段）。每个case/backend只有一个新进程、0.5ms采样；原始涨跌都保留，不能将单次正差直接归为噪声。完整RSS不增仍未证实，不能宣称已满足全部内存采用条件。

后续仍需解决 F 布局/宽矩阵对NJIT的差距、RSS增长的可重复归因和跟踪释放来源。当前只证明本轮时间与指定跟踪堆/局部栈的改善；中大型全面领先、完整内存与跨平台发布均未闭环。
