# Eigen 保序 LU：独立尾部行分组更新

2026-10-01，macOS arm64、AppleClang 17、Eigen 3.4.0。已接入当前工作树；这是相对现有 C++ 的有效优化，**仍未达到 LU 全面优于 NJIT 的目标**。未提交或推送。基线 `cf448fc4…9d130`，当前 `e619f8cd…65cdd`；完整身份见 [identity.json](identity.json)。

## 设计与自审核

只改私有 `solve_multi_library.hpp`。n≥1024 时，完成32列主元面板后，把独立尾部行组成4行×8列的固定 Eigen 数组，共享主元读取、保留每个系数的正序乘减，最后写回一次。主元面板内递推和剩余行继续原固定16列更新，列尾部也保持原顺序。不更换 LU 算法、first-max 主元、1e-14 阈值、RHS 更新、回代、错误或历史输出；不跳过零因子或非有限算术。

目标行均在完成面板之后，源主元行均在面板以内；乘数列位于目标列之前，因此局部值与被消费的源/因子不重叠。完成全部尾部行更新后才进入下一面板，不能将这个独立性扩展到面板内递推行。没有跨请求数值缓存，也没有新增线程、打包或堆数值缓冲。复用原 n² 系数工作区；分组数组逻辑容量256 B。基线静态算子与正式 wheel 对象的 `matrix_foundation_execute` 调用方帧均1040 B，无 FMA；这是该调用方的证据，不是完整系统栈上界。

实际完整 LAPACK LU 与历史消元的顺序、阈值和失败输出不等价，不能直接替换。此次使用成熟 Eigen 数组运算保留上述契约；[设计](design.md)、[限定到本轮的源码差异](production.diff)、[分配审核](allocation-review.json)和[对象检查](static.json)记录采用依据。AST、DAG、Planner 几何、CPU/内存预算、IPC19及结果所有权不变；既有 `isa=eigen-array-blocked-lu` 保持含义。

## 内存与当前采用结论

3类请求 × 旧/新/NJIT × heap/RSS = **18个独立进程**，不是13类计时全部内存覆盖。连续 heap 从图/setup进入首次数值执行，释放首个结果后预热5次，再测3次暖执行；前一个独立结果保持到新结果返回。RSS 从 setup 到3次执行监控，保留 idle 控制。输入/导入与 NJIT 编译在 epoch 外，必要工作区和 prepared 常驻对象在 epoch 内。探针控制通过，所有 heap 表溢出0，输入身份与计时一致。

| 请求 | 旧/新冷堆 B | 旧/新暖堆 B | NJIT 冷/暖堆 B |
| --- | ---: | ---: | ---: |
| 4096×8 C ordinary | 134490198 | 134752920 | 137663244 / 137925500 |
| 4096×8 F ordinary | 134490198 | 134752920 | 137663244 / 137925500 |
| 2048×8 C prepared snapshot | 33695990 | 33827640 | 35287820 / 35419004 |

新旧申请堆峰值逐项相同；大请求比 NJIT 少约3.03MiB，prepared 少约1.52MiB。这不能宣称所有内存指标显著领先。RSS 增量旧/新：C4096为1490944/1671168 B，F4096为1212416/1409024 B，prepared为1081344/1114112 B，正差176/192/32KiB；对应 NJIT 为7831552/3375104/3948544 B。RSS 受输入准备阶段已触碰后释放的页和分配器驻留影响，是补充观察，不是整个逻辑工作区占用。以上每类单个 fresh 观察，不能外推所有驻留状态，也不把小幅正差写成零。

依用户规则，秒级原版改善、堆峰值不增加和少量 RSS 页变化允许分阶段采用。时间仍实质慢于 NJIT，全部算子的中大型时间/内存目标保持开放；不是已全面验收或迁移完成。
