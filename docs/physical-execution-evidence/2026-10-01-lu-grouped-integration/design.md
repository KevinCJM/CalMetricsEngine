# LU 面板寄存器复用试验设计

目标：针对仍明显慢于 NJIT 的大规模 `solve_multi`，评估 Eigen 已有保序消元中的中间写回。这里只试验物理执行，不更换 LU 算法、主元规则、阈值或 Excel 数学契约。

基线：正式密度优化构建 `cf448fc4e0fd107d36018f381c109e044ff0672cd3f1e46dec8639ac2609d130`。先核对全部源码哈希；所有候选在隔离目录编译，生产源保持不变。

候选：每个宽度 16 的 Eigen 固定数组先读取目标系数；按原顺序执行面板内每个乘法、减法，在本地累积，最后一次写回。只改变目标单元格的物理存放时间。被消费的主元行和乘数列与目标区域不重叠；RHS 更新及主元扫描仍即时执行。禁用 fast-math/FMA、库内并行，沿用现有数组及工作区，不引入全矩阵副本或跨请求缓存。另测宽度 8、32，不能通过改变数学步骤赢得性能。

单行候选初测显示大矩阵仅约 8–15% 改善，继续检查能否复用主元行读取：在已完成主元面板后的独立尾部行中，以 2 行×16 列、4 行×8 列的固定 Eigen 小块同时更新。各行仍保持相同主元顺序；主元面板内依赖不变，尾部剩余行用单行路径。禁止把面板内递推行当成独立行合并。

校验：候选对已安装 wheel 的完整结果、错误及显式 out 前缀逐位比较，覆盖主元交换、阈值、病态、非有限、零因子、短尾、只读及 C/F/有符号 strides。浮点舍入模式和原生 sanitizer 另验。失败样本保留，不放宽容差。

性能：同一 CPU 预算、输入、独立结果、交替顺序及预热 NJIT。先以含输入复制/输出写入的直接候选筛掉无收益方案；候选有实质收益才集成完整 Scheduler 链路并测 cold/warm heap、RSS、栈及复制。直接 C ABI 不等同于完整请求验收。几 KB/几毫秒不独立否决；中大型实质退化、错误/所有权或预算违规仍否决。

Excel：数学和逐系数消元顺序不变，现有公式继续适用；不在普通计算中执行导出。未运行 Microsoft Excel 重算，不声称新增 Excel 验收。
