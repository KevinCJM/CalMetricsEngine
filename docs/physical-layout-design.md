# 连续内存布局的规划与结果协议

状态：分阶段实施。**C/F 输入运输、图输出策略、实际结果布局与 worker 返回协议已实现；2026-10-02扩展私有协方差→Cholesky显式F根缓冲复用**。最新范围与预算修正见第18节；第9–16节保留对应阶段证据。用户明确要求按计算性能选择布局，结果返回不得无条件固定为 C。一般整图布局成本搜索仍未完成。

## 1. 原则与现状

C（按行）与 F（按列）都可以是连续内存。逻辑 shape/axes 不随存储顺序改变；改变 order 不是转置。哪一种更快取决于输入、运算访问方向、原生库接口、下游消费者和输出用途，不能把所有输入统一转换成 C 或 F。

本方案启动时存在四处固定 C 的约束（第 4 项的输入通路现已解除，其余仍待完成）：

1. `ops::Output` 仅有 shape/data，数组 set 按线性 C 下标写；不少内核直接写指针。不能只加一个 F 标志就对所有内核启用。
2. `graph::output_value` 总是设置 C strides；根复制也按逻辑 C 顺序写出。`ResultSlot` 仅声明偏移/容量，Audit 仅传 shape/status。
3. `Result::outputs` 创建 NumPy 视图时传空 strides，隐式采用 C；仅在 Python 改 flags/strides 会把已有字节解释错。
4. worker `pack_input`、输入解码、预共享检查和 `SharedArrayOwner` 只承认 C 连续；ModelPayload 创建/解码也固定 C。只改单进程输出会导致不同 lane 采用不同数据访问路径。

既有 F 输入到 C 输出的算术融合直接写独立 C 缓冲，并非必然先构造一份完整 F 结果再复制；但跨存储序读写仍可能昂贵。正在验收的 4×4 Eigen 存储序分块只适用于确实选择 C 输出的路径，不是后续默认强制 C 的理由。

## 2. 数学与执行职责

- AST、逻辑 DAG 的算子、轴、dtype、shape、错误和时序语义保持独立于物理布局。不为 C/F 新增金融算子或复制一套数学实现。
- 原生物理 Planner 声明节点的可用输出布局、输入 stride 能力和成本；参数值不参与任意缓存复用。布局规划不得读取未执行的数值结果。
- `auto` 选择已有实测证据支持的最低预测整链成本布局；`C`/`F` 是调用方确有外部要求时的明确约束。成本包含输入读取、数值计算、结果写入、布局转换、保留结果及多消费者，不只比较单个内核。
- 同一节点多个消费者共享一份有明确 order 的结果。只有成本收益与内存预算同时允许时才建立转换节点；转换显式计入计划、复制审计和 liveness，不隐藏在 Python 包装或某次 materialize 中。
- 不调用私有线程池，不改变既有 CPU 预算。布局优化优先于为内存访问不匹配增加线程/进程。

## 3. 原生布局描述与内核准入

引入 C/F 连续布局枚举及经过溢出检查的 element/byte strides 工具；rank0/1、空轴及单元素轴采用确定的归一规则。Value 保留现有任意有符号 stride 表达，另外明确 `c_contiguous`、`f_contiguous` 和 `dense_contiguous`，不能悄悄把现有 `contiguous()` 从 C 语义改成 C/F 混合语义。

Output 明确写入布局。算子注册/原生分派声明真正支持的输出 order，逐个排查直接指针写入、SIMD span、矩阵库输出、视图与借用规则。没有支持证据的内核保持其原生 C 计算；显式要求 F 时的转换须有规划容量和审计，auto 不为标签增加一份全矩阵缓冲。

首批实施顺序：

1. 几何/连续性工具、协议版本与严格边界校验。
2. pointwise 及混合算术链：F 稠密输入沿连续方向读写 F 独立结果；保留真正需要 C 时的 Eigen 存储序分块。标量/广播、负参数 stride、操作数顺序、除零检查和失败前缀继续沿既有契约。
3. 根身份、转置/借用视图物化、重复根与后续消费者。输出所有权不能借机变成绑定输入或复用 scratch。
4. 原生库矩阵算子、扫描/归约、迭代状态和更一般张量链路，按内核能力和整图测量扩展；无法证明收益的 auto 选择记录原因，不能一律偏向 F。

这四项是同一目标的实施阶段，不把第一批少量算子通过当作全面完成。

## 4. Planner、DAG 与状态

布局决策与几何一起进入物理计划和计划身份。复用计划时核验输入 dtype、shape、实际 strides、输出策略、算法/布局能力版本；同一 ndarray 地址改 strides 不得复用过期决策。不同布局的逻辑结果可值等价，但物理计划不一定可复用。

中间结果的 Value 必须携带实际 strides，CSE、arena 复用和根直写不能重新标记为 C。每次执行的动态 shape 与选择的 order 一起决定实际 strides；上界容量不是实际几何。只复用已经证明死亡的存储，不将跨布局同形误当可原地覆盖。

迭代需明确状态布局、每步结果、收敛扫描和残差的逻辑坐标。初态、后续状态和 inplace kernel 必须一致；布局转换纳入状态复制审计。子作用域、观察器、错误隔离、分段逐位置状态全部覆盖，不能只改无错误的顶层混合图。

## 5. 公开接口、所有权与兼容

拟定接口：图编译接收 `output_order="auto"|"C"|"F"`，允许按根指定策略；直接算子接收 `order`，已有显式 `out` 的实际布局必须与要求一致。具体入口实现时以最小一致 API 为准，不在 Python 做布局规划。

新图默认 auto；明确 C/F 约束进入指纹、pickle 和原生编码。旧编码计划按旧 C 契约解码，不用新默认值重解释历史执行字节。历史定义/快照保留其版本；新结果协议必须明确版本，当前 `typed-results-1` 不应悄悄返回未经声明的新布局契约。

结果需提供每根/区间的实际 order、shape、dtype、byte strides、offset 与状态。由这些经过原生校验的信息创建 NumPy 视图，不转置逻辑 shape，不额外复制。对未知几何失败不能构造越界 strides；空结果可采用规范化布局。mask/int64 保持精确类型，状态数组的布局也明确，并与值的逻辑坐标一致。

ordinary execute/run_snapshot 仍返回独立结果；prepared 借用、重新执行、关闭 scheduler、共享区域释放后的生命周期契约保持。返回 F 连续数组不等于免除独立结果的一次必要分配。

## 6. 进程、共享内存与模型

worker 请求/响应版本同步升级：输入与根结果携带 order/必要 strides，校验 rank、大小溢出、容量、对齐、合法布局和帧上限。输入已是 C/F 稠密时按真实物理字节搬运并恢复相同 strides；任意切片需要打包时，由 Planner 选择目标 order 并记录复制成本。不得在 worker 解码时无条件 `set_contiguous_strides()`。

SharedArrayOwner/Descriptor、SharedInputBundle 和 attach 贯通 order；预共享 C/F 稠密块可直接借用，在 descriptor bounds 内访问，不接受重叠/越界的伪造 dense 声明。共享输出按同一计划写互不重叠片段。inline 和 shared 都核验实际返回 order，不能只验证 shape/字节数。

ModelPayload 字段需要布局版本，序列化包含重建物理视图所需信息。明确模型 identity 的语义，不能把新增布局字节偷偷纳入旧版身份规则；旧载荷继续按原 C 格式读取。新增元数据、转换缓冲、父子进程同时存活容量及响应帧长度都进入预算，超限在分配前拒绝。

## 8. 首轮原型证据

已比较相同 F 输入、相同两个算术步骤和独立预分配输出的 C/F 原型，均使用 Eigen，不属于公开入口或完整标准化链验收。直接把原4×4内核的输出Map改成列序，在8个规模上均更慢；更换为匹配 F 输出的连续逐列8元素块后，210个逻辑坐标/操作数顺序对照通过。

32768×128 的两步算术内核从 C 输出约 **5.450ms** 降到 F 输出约 **1.100ms**；32768×64 从 **1.953ms** 降到 **0.525ms**。这说明输出布局应与遍历方式共同选择，不证明完整请求、进程运输或内存已通过。正式结果协议仍固定C，不能把原型标记为已经支持F返回。

原型首轮测试工具将 F 字节错误地包成 C ndarray，导致逻辑比较失败；纠正视图创建后210项通过，失败记录保留。该问题也说明实现时必须核验真实 strides，不能仅改输出标签。原始脚本与记录在本轮列布局分块证据中归档。

## 9. 输入布局与传输阶段（2026-09-30）

### 已实现范围

- 新增 `MemoryOrder` 与 C/F/dense 判定，保留原 `Value::contiguous()` 的严格 C 语义。新判定忽略不影响实际访问的 singleton strides，检查溢出；空/退化布局归一为 C。没有改变数学算子、逻辑 shape、轴或已有输出协议。
- 共享输入构造、描述符、attach 与只读 bundle 贯通真实 order/byte strides；C/F 块只复制物理字节一次。输入仍有独立所有者，返回视图保活映射；非稠密 bundle 输入仍明确拒绝。
- worker v12 将布局放在原 dtype 字的高位，**请求帧未增加布局字节**。inline/shared 输入都保留 F 顺序；非法布局拒绝。预共享 F 块通过原有范围/对齐验证直接借用；非稠密普通输入仍按 C 打包。此阶段不新增 Planner 元数据或数值工作区。
- ModelPayload 对稠密字段直接复制物理字节，保留各字段布局和不可变性。全 C 编码/身份继续为 v1/model-1，含真正 F 字段采用 v2/model-2，每字段增加 8 字节的布局编码，纳入内容身份。v2 按布局恢复视图并拒绝非法/非规范格式；字段数上限保持 4096。rank、字节数与 strides 的安全检查在共享分配前完成。
- C 共享及模型视图继续使用原隐式连续 strides 构造；F 与空数组显式传 strides。布局枚举不引入逐元素元数据，不为支持 F 而额外复制模型数值或改变 Scheduler CPU 预算。

### 自审核与测试范围

新增测试覆盖 C/F、rank0–4 的共享数组（计算图仍限 rank0–3）、float64/int64/bool、空轴/单元素轴、补边/反向/广播拒绝、只读/寿命、不同执行 lane、混合模型字段、编码/身份和截断/伪造布局。原生测试检查真实 worker 请求中的 F 标记和**未经重排的物理字节**，再执行并比较逻辑结果；失败请求不得写结果，随后合法请求须能恢复。

首轮暴露空共享数组的描述符 strides 为零、NumPy 视图却使用隐式 C strides 的不一致，已改为显式零 strides。另修正新增测试对 Python 异常类型及操作系统共享区实际边界的假设；保留失败记录。

Excel 的数学、公式与单元格坐标未变化；采用新原生参考对历史 Microsoft Excel 重算快照复比，不宣称本轮重新运行了 Microsoft Excel。

### 剩余工作

本阶段只解除输入通路强制 C，**尚未实现 auto/C/F 输出参数、算子输出准入、根输出布局、结果协议升级和整链成本选择**。目前 `typed-results-1` 图输出仍为 C，F 模型通过图结果再导出可能形成新的 C 模型身份。后续按第 3–7 节推进，不能据本阶段宣布端到端 F 返回或全算子性能完成。

## 10. 图结果布局阶段（2026-09-30）

### 设计与实现边界

- 图编译新增单一 `output_order=auto/C/F` 策略，新公开图默认 auto；本轮不提供按根策略字典和直接算子 order 参数。RootOutput 保存策略；ResultLayout 每根最多增加一个布局字节，全部 C 时不分配该数组，容量元数据预算保守计入最大需求。动态 shape 仍由执行产生，逐位置状态仍是逻辑 C 顺序。scalar/vector 计划采用 C；空/单元素轴可同时满足 C/F。
- 原生计划 v8 保存策略；显式 C/旧定义的编码继续可用 v7。pickle v5 保存策略，旧版本按 C 解码。auto/F typed 结果声明 `typed-results-2`，保留 `cpp-aot-execution-2` 的计数结构；显式 C 保留旧结果协议。指纹包含策略，输入实际 shape/strides 仍参与计划复核。
- C/F 是存储差异，不增加数学算子或更改 AST 轴。原生 Output 按逻辑坐标映射物理位置；已准入逐元素内核可直写 F，其他显式 F 根取消 C 内核直写目的地，保留 liveness/arena 预算，再复制至独立 F 根。根读取保留实际 strides；转换字节计入 root_copy_bytes，不能靠改 NumPy 标签伪装 F。

## 11. 反向列视图优化（2026-09-30）

第10节反向行视图的标准化链仍慢于NJIT。定位到两个准入限制：列归约仅接收第一轴stride=+1，融合列算术也只接收正向列。`F_array[::-1]`的每列仍是反向连续访问，按逻辑C顺序遍历则跨列跳跃；没有必要先复制完整矩阵。

本轮复用现有Eigen路径：列归约增加编译期±1行方向，仍严格按逻辑行顺序累加，保持两遍方差、ddof、非有限与失败前缀。F根算术使用Eigen固定8元素块的reverse表达式，将反向连续加载映射到正向F输出；只改变加载与存储，保持两次运算及操作数顺序。尾块按有符号步长读取。对受支持的融合图，auto可为反向连续列输入选择F结果；显式C及隔离auto仍保留C。直接算子输出契约不变。

输入借用只读，输出独立；不新增整矩阵打包、持久缓存、线程或数值工作区，固定块栈空间另核对。不共享数值结果、不改变状态、CSE、AST或Excel公式。负列步长和绝对行步长大于1暂不扩大准入，继续原通用路径。

进程原本就要打包非稠密输入。对反向连续的float64列视图，复用这一次既有打包，按列以标准库memcpy复制反向元素的原始字节，写成F，而非先打包C再由worker转换或跳跃读取。线上F标记与实际字节同步；协议版本与总输入容量不变，inline/shared共用规则，既有复制计数不减少也不隐去。预共享输入仍要求稠密，不能将反向视图冒充共享稠密描述符。初版用reverse_copy写入double指针，审核后改为字节复制，避免把IPC字节缓冲的对齐或double对象生命周期作为前提。

首轮malloc测量确认：新反向大矩阵路径快于旧版和NJIT，但3个根的F布局标记多出3B堆峰。为满足内存不增加，布局标记改用标准库bitset存放最多64根；更大图由unique_ptr数组存放原每根1B标记，预算仍按最大容量保守计算。64位构建的容器体积与原vector相同，进程编码仍是原布局字节，未改变协议。复制/移动、空布局、63/64/65根边界及大型图真实进程传输加入回归。最终时间和内存须在此修正之后再验收。
