## 1. 目标与代码基线

目标：FundInvestmentResearchPlatform 当前自研 Python/Numba 数值算法、迭代求解和组合优化逻辑，全部获得可验证的 CalMetricsEngine C++ 实现或等价的原生计算图组合。最终平台正式计算不再依赖这些自研 NJIT 内核，不使用 Python 数值回调或静默回退。

用户最初要求所有迁移负载的速度与内存都优于热态 NJIT；2026-09-29 已明确允许很快的小任务有轻微延迟增加，中大型仍须明显领先。全文性能验收以第 13 节的最新分层口径为准，原严格门禁保留为历史诊断。数值等价只是前提，不能以 AOT、架构统一或其他负载的优势替代验收。

2026-09-24 新增用户要求：各算法必须提供可查看、可独立重算的 Excel 公式复现方案；复杂组合按同一逻辑 DAG 导出，默认全工作簿预算 2,000,000 个单元格，超预算明确拒绝。具体规则与 E0–E3 工作包统一见 [Excel 公式复现与核验契约](excel-reproduction-design.md)。这是新增的待实现交付要求，不改变原 C++/NJIT 验收历史，也不放宽性能门槛。

C++ 与 Excel 是独立触发的并列后端：普通 C++ 请求不执行任何 Excel 规划、生成或重算，只有 Excel 下载请求才启动相应链路。C++/Excel 浮点对照允许配置容差内的精度尾差，不要求逐位一致；这不修改原 C++/NJIT 数值和性能门禁。

Excel 数学复现能力统一归 CalMetricsEngine，包括公式规则、预算、通用工作簿写出及核验；平台保留业务数据/版本适配和已有下载入口。迁移从平台现有 `excel_formula.py`、`excel_rolling_scope.py`、`excel_computation_state.py`、`excel_export.py` 及回归夹具起步，按已验证范围切换后清理对应重复规则。数学契约变化须同步复核 C++ 与 Excel，纯性能优化须提供语义等价证据；职责、现有覆盖边界及预算口径差异统一见 Excel 契约第 2 节。该迁移当前仍待实现。

## 2. 完整承接的边界

| 责任 | 引擎承担 | 平台承担 |
| --- | --- | --- |
| 计算 | 数学算子、耦合求解、模型训练/推断、路径递推、原生图执行 | 选择算法、声明参数和组合定义 |
| 金融语义 | 执行显式传入的数学/数组/状态契约 | 净值或价格选择、单位、复权、年化、资金规则与业务解释 |
| 时点 | 执行索引、有效性、重置和依赖传播 | 日历来源、可得时点事实、实时/研究/发布资格 |
| 存储 | 计算缓冲、模型数值载荷、进程传输和生命周期 | 数据读取、业务持久化、不可变快照和发布流程 |
| 调度 | CPU/内存预算、原生线程/进程、共享内存、取消 | 请求编排、鉴权、排队和用户界面 |

“完整复现”要求保留数学口径、参数默认值、缺失处理、边界等号、初始化、随机性、停止条件、错误和多输出。现有算法名称可能不是标准教科书算法的全部定义，必须以当前实际实现及行为契约为准。例如不能把当前带方差目标和网格细化的 GARCH 拟合换成另一种优化器后称为等价移植。

输入仍然是通用数组和参数，不新增“只接受净值/OHLC”的全局金融限制。既有 Typed IR 语义检查继续保留，不能借本规划擅自删除。

不把每个 Python 函数各移植成一个原生算子：

1. 已有原语能等价表达的，建立组合图和参考用例。
2. 缺失且能独立复用的最小数学能力，增加 canonical 算子。
3. QP 活跃集、EM、HMM、持仓/现金递推等不可分离迭代或状态过程，保留耦合内核；特征准备、筛选、评价和展示继续分开。
4. 原生 CSE、共享拟合、融合和批处理可以优化物理执行，不能隐藏业务步骤或强制计算无用输出。
5. Python 的数据读取、校验、序列化和页面业务编排不要求改写为 C++；其中实际承担的数值变换和数值循环仍属于迁移范围。

## 3. 全量盘点与防遗漏机制（M0）

随文提供 [函数盘点初表](platform-compute-inventory.csv)。静态扫描范围为平台 Git 跟踪的 `backend/**/*.py`，排除 `tests`、`scripts` 和缓存目录，提取装饰器文本含 `njit/vectorize/guvectorize/jit(` 的函数：共 74 个文件、710 个函数条目。

此计数包含内部辅助函数和不同 dtype/rank 变体；漏不了列表中的函数，不等于已经证明全部生产算法均在列表中。动态生成的 NJIT 计划、未装饰的 Python 数值路径、间接注册和实际调用可达性，必须在 M0 补查。每项目前统一标为待核对，不能将 710 当成算法数、缺口数或移植完成率。

M0 应交付版本化覆盖清单，每项至少记录：

- 稳定算法 ID、来源 commit/文件/符号/哈希、生产调用入口、调用的辅助内核。
- 输入输出 dtype/rank/轴/布局、参数默认值、状态重置、知识时点依赖、结果所有权。
- 随机源、抽样顺序、缺失与错误约定、收敛/非收敛与可行性证据。
- 对应已有算子、新算子、耦合内核或组合图；所属阶段、测试夹具、性能负载。
- 分开记录 `engine_equivalent`、`platform_integrated`、`service_verified`；每个通过状态绑定代码/构建/测试证据。
- 单独记录速度门禁、内存门禁和测量负载；未知或未建立基线不得记为通过。初表中两项均为 `pending_baseline`。
- 按 Excel 契约补充每项算法的公式展开版本、覆盖状态、支持域、预算模型及真实 Excel 核验证据；缺失是待补开发项，不默认为支持。

具体执行：先用 CodeGraph 定位服务入口到数值叶子的调用链，再静态扫描补漏，最后用受控测试覆盖动态计划/注册入口。清单初表中的文件级阶段归属只是排程建议，M0 需按实际依赖拆细，不据此判断算法已经缺失或支持。

原 NJIT 基线仅作为隔离测试和性能比较的受控参考；不复制进引擎生产包，不成为 wheel 的运行依赖。生成固定输入、期望输出、状态及参数的夹具，同时保留独立数学不变量检查，避免双方一起算错。

完成条件：所有可达自研数值路径都有明确去向；不可达、非数值或重复封装必须逐项说明，不默默从统计分母排除。后续平台新增/修改算法时，差异检查要求更新覆盖清单。

### 5.1 三维输入输出是已有需求

当前引擎数值 rank 为 0/1/2，不能直接完整承接下列已观察到的三维接口：

| 平台来源 | 现有数组语义 |

先明确支持 rank-3 的具名轴、带符号 strides、只读视图、零尺寸和有界元素数；不因一次三维需求扩张成无边界张量框架。跨块/批次布局必须可逆、保留原轴，不能靠 Python 隐式 flatten/reshape 掩盖契约变化。

同步修改 Shape/Value、类型推导、输入绑定、结果布局、容量规划、状态数组、worker 编解码、共享内存边界和 NumPy 视图。现有 rank-0/1/2 行为继续兼容。公开协议按实际不兼容点升级，旧定义重新编译、旧凭据保持原样。

### 5.2 模型和一次求解的具名结果

当前固定 5 个 double 的 record 不能承载模型，单算子固定 8 个 Value 的入参数组也不能直接表达全部现有内核。扩展前先区分“独立数学输入”和“仅配置选项”：使用有 schema 的选项和可扩展原生输入描述，不把 13 个参数塞进无解释的一维浮点数组。

拟支持原生具名字段聚合：字段分别保留类型、形状和状态，示例为系数/协方差/似然/迭代数/终止原因；权重/对偶量/残差/有效约束。各字段可投影为普通图值，单次拟合/求解只执行一次。

模型数值载荷是不可变、具版本的原生数组集合；schema、算法版本、训练参数、源定义身份及随机版本纳入模型身份。平台持久化业务版本，引擎校验数值载荷。进程传输不传 C++ 指针、Python 对象或任意 pickle；每个字段的内存成本纳入 Planner。

### 5.3 有界迭代与失败协议

QP/EM 等内部迭代由相应耦合内核控制。确需可替换目标函数的 SQP/反向压力，目标以受限表达式或原生子图提供，不能接受 Python callable；先支持实际调用需要的形式，不先建设万能 while 循环 DSL。

区分计算执行错误与算法返回状态：达到迭代上限、未找到可行初值、证明不可行、局部停止、数值失败，不可全部归成成功/NaN。是否保留最后可行点按原契约定义，必须携带状态；结构错误仍失败关闭，健康独立根仍按原隔离契约返回。

所有循环有迭代/工作量/内存上限及取消检查。可硬停止任务继续使用原生隔离进程；进程结束后才能释放映射与 CPU 配额。

Planner 按独立训练任务、模型、候选、情景块及预测区间扩展工作量和内存估计，不能把资产轴或模型轴误作时间区间切片。复用现有 Scheduler 统一预算；模型拟合、迭代、情景计算均不能再建私有线程池。

## 6. M2：共用数学能力

| 能力 | 工作内容 | 主要消费者 |
| --- | --- | --- |
| 线性代数 | 对称特征分解/特征值、Cholesky、三角求解、多 RHS 求解；QR/最小二乘/SVD 按 M0 的真实依赖加入 | PCA/谱聚类、PSD 诊断、协方差根、QP、回归、CMA |
| 数组与轴 | 受检行列选择、多维切片、拼接/堆叠、显式广播、稳定排序/排名、分组和分段归约；已有能力优先复用 | 所有模型、三维情景、面板信号 |
| 稳定统计 | log-sum-exp、稳定概率归一化、距离矩阵；t/卡方/F 等当前内部实现所需分布函数 | GMM/HMM、模型不确定性、置信区间 |
| 时序与滤波 | KAMA/Super Smoother 保持原语组合；补齐 Butterworth 双向滤波、居中 Savitzky–Golay、Ehlers 误差修正所缺能力 | 产品分析、状态图、择时 |
| 既有指标与数据数学 | 排名/评分、快照 last-finite、预热/有效性、时间索引对齐、复权数值递推、摘要统计 | 指标中心、快照、数据边界、Agent 数值摘要 |
| 原生随机源 | 显式算法版本/种子/子流、均匀/正态及实际抽样分布、受控抽样索引/随机带 | 探索、聚类初始化、Bootstrap、路径模拟 |

矩阵分解可以使用构建时集成的原生数值库，但不能依赖 Python/SciPy 回调。库选择以精度、许可、平台构建、线程可控和当前负载基准为依据；未做技术试验前不锁定供应方。外部 BLAS 线程计入同一预算，禁止隐形嵌套并行。

随机兼容分两项验收：相同随机带的数值路径等价；旧 seed 所定义的随机序列/结果等价。只通过前一项不能宣称历史随机算法已完整复现。先确认各旧实现的 RNG 算法及抽样消费顺序；新 RNG/子流定义如改变旧结果，必须采用显式新算法版本，不静默覆盖旧口径。

并行任务 ID 与随机分块相互独立，稳定归约顺序；同一输入、种子和算法版本在支持的线程/进程数下保持已声明的确定性。分布统计测试只能补充，不能代替逐路径差分。

随机算法版本、种子和显式流标识必须进入计算身份与 CSE 规则；禁止把本应独立的抽样节点合并成同一随机流。模型拟合复用同样必须匹配训练数据、参数与初始化身份，不能只按模型名称缓存。

## 7. M3/M4：求解器、组合优化与随机空间

### M3 必须覆盖的求解行为

- `qp_numba.py`：约束缩放和秩处理、活跃集 QP/LP、可行点与 Phase I、KKT/对偶残差、退化约束、迭代上限和异常状态。
- `optimizer.py`：BFGS-SQP、线搜索、当前有限差分梯度及停止规则；不擅自改为另一种全局优化算法。
- 单纯形/箱约束/组约束的投影或修复分开建模；整数步长和离散权重搜索不能当作连续 QP 处理。
- 多模型外逼近中的线性主问题、二次支撑面和迭代状态，复用同一 QP/LP 核心。

标准 QP 输入建议为 H/f/E/e/G/h、初值及具类型的选项；不等式方向显式固定并从平台契约转换。目标值、可行性、站立性/互补性残差及对偶量分别输出。只是没有找到可行点不等于证明不可行；算法局部停止不等于证明全局最优。

多解时先保证当前 tie-break 和下游行为；如果不同解会改变权重/聚类/交易，不能仅以目标值相等关闭差异。任何允许等价解而不要求相同解的场景，需在该项契约中明确。

### M4 完整组合链

约束构造 → 候选生成 → 权重修复/离散化 → 指标图批量评价 → 可行性筛选 → Pareto 前沿 → 代表点/极值点 → 局部细化/目标网格。

覆盖 `optimizer.py`、`frontier_sampling.py`、`frontier_moments.py`、`strategy.py` 及 `fit_numba.py` 的相关计算。包括风险预算迭代、分轮种子继承、整数权重、风险/收益指标配置、历史前沿与矩前沿，保留候选数、拒绝原因、父候选关系和稳定排序。

随机探索、确定性目标网格和风险预算是不同算法。不能以一个“均值方差优化器”替代全部能力，不能把未收敛点放入成功前沿。算法模板应能更换风险/收益子图，计算全部留在 C++。

验收同时比较整组候选/状态、最终权重与前沿、约束残差及组合指标，不只比较“最优收益”一个数。

## 8. M5：机器学习、潜在状态与识别

自动分类覆盖 PCA、相关矩阵去噪、层次聚类及切树、K-means、K-medoids、谱聚类、GMM、容量约束分配、轮廓系数与类内权重。

状态模型覆盖 GMM 的 EM、当前硬状态 Gaussian Markov 估计、HMM Baum–Welch，以及训练初始化、后验计算、过滤/平滑、组件顺序映射、变化点和集合共识。保持训练与推断分离，同一冻结模型可以对多个区间推断；不得在样本外计算时重新拟合。

标准化、特征构造、模型拟合、后验、标签映射、确认、保持期和区间统计分别可追溯。历史模型的 Gaussian 参数化、方差下限、概率截断、初始化和停止条件必须原样核对。

可靠性数值部分一并覆盖：概率校准、状态/事件匹配、前向评估块、Bootstrap 区间、分类与冲突统计。研究是否可发布及证据采纳仍由平台判定。

验收不能只比准确率：需比参数、似然、后验、状态序列和可得时点。特征向量符号/重复特征值、聚类标签置换需要明确约定；仅当平台输出语义允许重标号时才做等价映射，不能隐藏影响下游的标签变化。

## 9. M6：随机模拟、波动率与压力

- 产品分布：参数化 Monte Carlo、偏度/峰度校准与相应变换、平稳区块 Bootstrap、EWMA、方差目标 GARCH 网格与坐标细化、过滤历史模拟。
- 情景：历史回放、因子冲击映射、协方差根、相关路径、状态转换路径、经验状态抽样、组合投影、尾部与区间统计、反向压力搜索。
- 合成序列：现有 synthetic OHLCV 的随机/路径构造，不借此新增真实行情下载。

将随机生成、路径演化、资产/因子映射和统计分离；具有不可分离历史状态的路径递推留在耦合内核。预算包括随机带、路径、排序工作区、状态、IPC 和结果映射。

提供按所需输出执行的完整路径/终值/汇总模式，默认模式保持旧接口结果。可分块统计必须与全量契约等价；精确分位数不能未经版本声明换成近似 sketch。跨块保证随机序列、状态延续、情景边界重置和稳定归约。

## 11. M8：回测、因子、TAA/择时及其余路径

- 组合回测：共同日期、收益轴、有效权重、买入持有漂移/再平衡、换手、成本、累计路径、风险与贡献。
- 因子研究：特征、截面标准化/排名、标签、IC/分组、目标权重、分层回测、FF3 构造、风格约束回归、滚动暴露、逐日贡献及累计对账。
- TAA：动量窗口/信号组合、约束倾斜、候选筛选、路径评估、walk-forward、历史状态驱动策略。
- 产品择时：alpha-beta、条件/事件、信号学习评分和动作选择、面板广度、真实执行约束与持仓模拟。
- 其余数值：敏感度与现金流久期/冲击、交易分配/账本汇总、产品统计/比较、指标评分/排名/快照、复权与质量标记、时间对齐、Agent 序列摘要。M0 发现的未装饰计算也不能遗漏。

重点保持 decision/recognition/effective 时点差异、下一可交易时点生效、初始财富、交易成本和结算顺序。历史快照保持不可变，新运行使用新构建凭据。

## 12. M9：平台接入与退出旧内核

当前 `CppIndicatorBatchPlan` 仅覆盖单产品独立标量指标；平台执行门禁仍需适配 typed 协议。不能只修改 backend 名称或把 float64 校验删除就算接入。

每个业务切片按以下顺序交付：

1. 引擎可独立运行并通过同算法 NJIT 差分；所有已冻结验收负载按第 13 节当前分层性能口径验收后，才进入该业务切片的切换。
2. 平台适配真实 dtype/rank/轴、参数和历史定义，验证计划/构建/结果身份、逐位置错误及所有权。
3. 更新前后端执行门禁、单节点预览、公式/图往返、快照和缓存。无前端变化的切片明确验证边界。
4. 使用真实服务路径和离线固定数据回归；记录数值回调为零、无运行时编译、无静默回退。API/页面不能仅依赖审计字符串自证。
5. 在切换该路径的同一批变更里移除已被替代的 NJIT 数值实现、旧预热/worker、失效依赖及重复入口；保留测试适配和仍被其他未迁移路径使用的能力。

迁移期间允许不同尚未迁移的业务链分别使用其唯一当前实现，不保留同一条生产链的双实现开关。比较在测试环境做，回滚通过 Git/发布版本完成。所有路径迁移完后再移除平台剩余计算 Numba 依赖；数据/模型外部依赖按真实用途评估，不能机械删除 SciPy。

缺少匹配 AOT 包、旧 worker/模型/计划协议、无效凭据都失败关闭；独立安装 wheel 不应依赖平台源码。

## 13. 统一验收门槛

### 数值与行为

- 源端和 C++ 使用相同输入、参数、初始化、随机带、停止预算和源算法版本。
- 逐项登记绝对/相对误差、残差与病态样本规则；没有一个全局 `allclose` 容差覆盖全部算法。
- bool/int64、索引、状态码、边界、有效性、分段与时点要求精确一致；浮点误差不得跨过阈值改变分类或交易。
- NaN/Inf、空输入、单点、零轴、短样本、退化矩阵、重复约束、非唯一解、随机边界、未收敛均有固定样本。
- 求解器同时验证原目标与约束/KKT/对偶证据；模型检验参数/概率/标签；路径检验逐步资金、持仓与贡献守恒。
- 若参考实现发现缺陷，先记录并复核；修复数学口径必须显式版本化，不能用迁移掩盖差异。

### 原生执行与资源

- 每个新类型/算法覆盖 direct/graph、ordinary/prepared/snapshot、single/thread/process inline/shared 的适用组合；不支持的组合必须明确拒绝。
- 对比只读/非连续/负 strides；校验输入无修改、工作区不交叉写、结果跨调用独立及持有者释放后寿命。
- 覆盖整型乘法溢出、shape 容量低估、描述信息预算、大结果跨进程、worker 崩溃/取消/超时和清理。
- 算法失败保留诊断，不能掩盖独立结构错误；无关图根的隔离行为不回退。
- 新算子进入统一注册表、AST/IR、lowering、序列化、Planner、worker、文档；只提供 direct API 不能算完整支持。

### 性能和发布

当前采用口径以 [AGENTS 第 16 节](../AGENTS.md#16-performance-evidence)和 [D8 完整负载规则](computation-design-rules.md#10-d8用对等的完整负载证明收益)为准：重点解决中大型完整计算的大额耗时与内存占用。几 KB 的内存增加、几毫秒的耗时增加不能单独作为否决条件；结合完整请求的绝对和相对变化、实际批量/并发累积及资源预算判断。性能严格比较字段为 false 或由该比较产生的历史脚本非零退出均是诊断，不能自动成为微小退化的采用否决。以下表格及相关严格判定、阈值和失败负载保留；不能仅凭旧门禁通过宣布完成。中大型时间和内存明显优于热态 NJIT 的整体目标不变，不以小任务容忍度放行实质退化；数值正确性、所有权和预算仍是硬约束。示例不构成统一规模分界、固定字节/毫秒豁免或硬性 10 倍门槛。

- 历史双优门禁对每个迁移算法的每个冻结验收负载，分别计算：

  | 必需比较 | 通过条件 |
  | --- | --- |
  | C++ 普通入口耗时 / 热态 NJIT 对等入口耗时 | 严格 < 1.00 |
  | C++ prepared 耗时 / 同等预绑定热态 NJIT 耗时（有该接口时） | 严格 < 1.00；原有 ≤ 0.90 的负载仍执行更强要求 |
  | C++ 运行阶段峰值 RSS / 热态 NJIT 运行阶段峰值 RSS | 严格 < 1.00 |
  | C++ 计算增量峰值工作内存 / NJIT 对等计算增量峰值工作内存 | 严格 < 1.00 |

- 在上述历史严格规则下，不能按跨算法平均值、吞吐总分或几何均值抵消失败；更快但占用更多内存、更省内存但更慢，均不通过。当前采用判断遵循前述完整负载口径，历史不通过不独立否决微小退化。除耗时和峰值诊断外，仍检查累计分配、各阶段复制字节、常驻缓存和保留结果内存，防止把成本移到计时区间之外；中大型实质失败不能靠跨负载平均隐藏。
- 既有四组基准继续运行，prepared ≤ 0.90 保持不变；历史 ordinary ≤ 1.00 检查是原有回归底线，原规划额外要求严格 < 1.00 和内存优势。这些严格结果仅作历史诊断，原检查通过不再足以宣布本轮迁移验收通过。不改写历史验收结果。
- M0 在优化前冻结每算法的小/中/大规模、密集/缺失、连续/非连续、单/多模型、短/长路径及正式启用执行方式。已冻结的失败样本不能删掉；生产允许的输入域仍须完整支持，不能用收窄能力范围制造通过。性能结论注明形状范围，不把有限基准外推为全部可能输入的证明。
- 被迁移链路复用的既有 146 算子及执行框架也在同一验证范围，不能因为代码已经存在就免测；四组旧基准不能代替所有新增算法及其调用链的性能证据。
- 使用同机器、同输入及输出精度/数量、相同 CPU 和内存预算、相同停止条件、相同随机带；两侧都完成编译/加载和同等准备。不得让 C++ 多用核、少输出字段、降低精度或放宽求解容差来获胜。
- 普通入口包含必要的校验、绑定/计划、调度、IPC 和结果封装；prepared 只和同等准备完毕的 NJIT 比。部署编译/启动成本单列，不能把 NJIT 首次编译时间计入热态比较。缓存、模型/计划复用策略对等。
- 内存实测覆盖父进程及全部 worker 的计算阶段，固定输入和结果保留生命周期；共享页分别报告 RSS/PSS 或可用的去重物理占用，说明平台测量口径。原生分配追踪核对实际工作区峰值；Planner 估算不能替代实测。准备阶段常驻模型/缓存仍计入运行阶段总占用。
- 速度采用交替顺序、重复配对测量，报告中位数、尾延迟及置信区间；内存也重复隔离进程测量并交叉核对分配追踪。历史 M0 严格统计规则要求主比较比值的置信上界低于 1.00；无法可靠测出优势、基线为零或已到不可压缩内存下界时，保留严格比较未通过/优势未证实的诊断，不将相等写成优势。该诊断不独立否决微小正差或内存持平，当前采用按 D8 判断完整负载的绝对和相对变化、实际批量/并发累积及资源预算；不得凭计时/页粒度噪声宣称显著收益。
- 实质性能问题须定位算法、访存、额外复制、工作区、调度或 IPC 成本，修复后重跑受影响负载。历史严格失败保留诊断，不仅因几 KB/几毫秒差异持续微调或阻止候选采用。数值等价但中大型性能目标未满足的成果仍标为未完成，不能据局部改善宣称整体迁移完成或通过对应平台生产替换验收；不改历史阈值、不删失败负载、不伪报完成。
- 当前支持平台的 Python/native 回归、ASan/UBSan、wheel 构建和安装路径通过；核对源码与实际 wheel 构建身份。平台数值与前后端集成另行验收。

## 15. 最终完成定义

只有同时满足以下条件，才能声明“CalMetricsEngine 完整承接当前平台自研计算”：

3. 原算法的数学、随机、错误和时间语义通过差分及独立不变量验证。
4. 真实平台服务已调用对应原生图；指标、快照、前沿、模拟、CMA、回测和择时等业务链分别有集成证据。
5. 每项算法的全部冻结负载均有完整时间和内存实测，最终判断按第 13 节及 D8：小型、本来就很快的负载可接受轻微退化，必须如实记录绝对和相对增量及采用理由；中大型完整负载的时间和内存须整体明显领先热态 NJIT，实质未达标项须有复验证据才能关闭，不能靠跨负载平均掩盖。更强既有阈值与严格通过数保留为历史诊断，不要求微小差异一律通过旧严格比较。数值正确性、独立所有权、CPU/内存预算及跨平台构建检查仍须通过，不存在 Python 数值回调、静默回退或重复生产实现。

上述五项定义原生迁移完成。新增的 Excel 交付要求独立验收：各算法具有已验证的公式展开方案，预算内且处于已验证数值/版本域的请求可下载并独立重算，预算外明确拒绝；其余限制必须给出具体原因并保持缺口可见。不能以原生迁移通过替代 Excel 功能完成。

初始规划交付时只完成本文件和静态盘点初表，未修改计算代码或运行算法迁移测试。后续已实施阶段以各节的构建与验收记录为准，不能把初稿状态或拟增能力当作当前 API。
