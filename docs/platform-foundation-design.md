完成必须有精确差异自审、安装 wheel 回归、原生与 sanitizer 回归、旧四组性能门禁，以及新增功能代表负载的热态 NJIT 速度/内存双优证据。未达到不能提交推送，不能改阈值或略去失败负载。

## 2. M0：可复现覆盖与基准

盘点工具只在开发/测试使用，不进入 Python 生产接口或 wheel 数值执行。输入为明确的平台源码目录及 commit，输出为稳定排序的 JSON 清单；保留文件与函数哈希、装饰器/签名表达式、参数默认值、调用/引用位置、数值候选依据、动态编译位置、现有测试引用、阶段和三层迁移状态。

以 Git 跟踪的生产 Python 文件为分母。扫描所有函数及模块级动态编译/注册位置，不只扫描文件名包含 numba 的模块。内部调用优先按模块导入别名、同模块/词法作用域解析；歧义保留全部候选及原因。无法静态证明的动态引用保留为待验证项，不随意断言不可达。冻结每个源文件并检查上游新增/删除/变更；源不一致时比较器失败关闭。

算法簇通过生产入口及共用依赖聚合，不以 710 个装饰器函数宣称算法数。原始函数 ID 永不因归组消失。数值契约未知字段显式未核定，不能填猜测的轴、NaN 规则或金融语义。

差分参考由固定 commit 的源码加载到隔离测试进程；不把平台数值实现复制到引擎生产包。输入由固定种子/固定构造生成，校验 exact dtype/rank、形状、输出字段及状态。浮点容差按用例声明；整数/布尔/状态精确相等；另验数学不变量。

性能规则在优化前固定：交替顺序配对计时、热态 NJIT、相同预算/输出/准备状态；报告中位数、尾部与配对 bootstrap 单侧 95% 上界。新增普通/prepared 耗时上界均须 <1；旧 prepared <=0.90 继续保留。独立进程重复测量运行 RSS 及计算增量峰值，包含 worker、保留结果和常驻缓存；记录页粒度与无法证明优势的结果。零增量或精度不足不能当作内存通过。基准失败会返回非零退出码并保留原始样本。

## 3. Rank-3 数学契约

增加 `tensor` kind，rank 严格为 3。显式三条具名轴和符号维度；支持时间、路径、情景、模型、组件、资产等轴，轴名称不会推导金融意义。时间轴仅允许位于首轴并按 starts/ends 裁切；没有 time 的数组为静态整块。模型/资产/路径轴不得当作时间裁切。

float64/int64/bool 输入为有界只读视图，支持正、负、零 strides 和零长度轴。元素数、字节数和地址偏移使用检查过的乘加；输出为连续所有者缓冲。普通元素运算、比较、掩码与全数组归约沿既有语义扩展；矩阵乘法、时序递推和 axis-specific 归约仍严格保持原 rank 要求，不把三维误当二维。

Shape/Value 使用三个维度和三个 stride；扁平索引映射保留 rank-1/2 快路。所有结果容量、状态和 IPC 描述信息按真实 rank 计量。native program/worker 协议版本升级，旧 plan 的解码边界明确；旧 wheel worker 不得混用。共享输入一次打包后使用连续描述，普通输入绑定不复制。

## 4. 具名结果、模型载荷与复杂参数

具名结果是原生多根结果协议上的 schema，字段可为不同 rank/dtype。字段投影按声明名称匹配，不依赖 dict 偶然顺序；表达式共享的拟合/迭代父节点只执行一次。没有使用的字段不要求调用方计算。

模型载荷是版本化、不可变的原生数组集合，包含 schema、算法版本、训练选项、来源定义身份和随机版本。建立载荷时允许一次明确的持久化复制，之后字段视图只读并保活原生 owner。进程边界传数组、描述及身份；不传 Python 对象、C++ 地址或 pickle。更换载荷必须重新校验身份，不能复用过期计划/缓存。

标量选项与数学数组输入分开声明。具类型选项拒绝未知项、重复项、错 dtype 和越界值；不能把 13 项数学输入塞成一个没有结构的 double 数组。扩展算子参数容量时保留小算子的内联快路，避免每节点新建堆数组。所有结构校验仍在失败传播时运行。

## 5. 有界原生控制与状态

复用原生子图机制提供受限迭代状态更新，更新表达式编译成原生 body，不接受 callable。初态、更新、收敛阈值和最大步数显式，状态 shape 不得迭代中改变。每轮检查有限性、工作预算和取消/截止；不能以增加线程池加速。

同一次迭代结果共享状态，分别投影值、停止状态、迭代次数、残差；执行错误与算法停止状态分离。通用状态集至少区分收敛、迭代预算耗尽、无可行起点、已证不可行、局部停止和数值失败；本阶段只有实际实现的算法会产生相应状态，不凭状态枚举声称已有 QP/HMM。

这属于耦合控制：更新依赖上一轮状态，拆成无反馈的普通边会改变结果。特征、目标构造与最终统计仍可独立替换。标量 bisect 保留现有行为；新协议不静默改变旧失败规则。

Planner 计入 body 的最坏循环工作、双状态缓冲、捕获数组、诊断和结果容量；复用同一 Scheduler CPU/内存准入。隔离进程在退出并 wait 后才释放映射和配额。

## 6. 分步开发与测试矩阵

1. 固定清单与负载，开发漂移检查和性能统计工具；验证扫描器不遗漏动态入口，不把静态证据标作已执行。
2. rank-3：从基础 Value 到类型推导、AST、绑定、Planner、worker、结果，覆盖静态与时间首轴、零轴、负步长、布尔/大整数、溢出和混合多输出。
3. 具名协议：名称、schema/版本/身份校验、字段共享、不可变载荷、跨请求/快照/进程寿命、预算和错误隔离。
4. 复杂输入与原生迭代：超过 8 项输入、类型/结构错误、多跳失败、零/极小容差、迭代上限、非有限更新、工作预算、超时及取消。
5. direct/graph、ordinary/prepared/snapshot、single/thread/process inline/shared 的适用组合；明确拒绝未支持模式。
6. 完整 Python/native/ASan/UBSan、wheel 安装与构建身份、现有四组和新增性能/内存负载。自审核精确暂存候选差异后，仅在所有门禁通过时提交推送开发分支。
