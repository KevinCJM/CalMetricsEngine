# Excel 公式复现与核验契约

状态：当前 146 个算子、7 类作用域的 Microsoft Excel 全量夹具验收及独立符号预算已完成；平台下载入口迁移尚未完成。需求确认日期：2026-09-24。当前接口、适用域和证据见第 10 节。
最初盘点时 CalMetricsEngine 尚无 Excel 后端，FundInvestmentResearchPlatform 已有 Python 实现。下文保留统一契约与迁移目标；当前引擎 API 及具体限制见[导出使用说明](excel-export.md)，不能把总体目标全部当作已验收能力。

设计、开发与审核前须阅读 [Excel 公式生成的数学与编程纪律](excel-generation-rules.md)。本文维护功能范围、预算口径、产物状态与迁移阶段；生成和核验的实现纪律由该规范维护，不另立一套数学契约。

## 1. 用户目标与完成定义

用户自定义一套算法后，可以下载包含输入、参数、可执行 Excel 公式、中间步骤和结果对照的 `.xlsx`，在 Excel 内独立重算、理解计算方法并核验 C++ 结果。目标覆盖引擎全部算法与组合，包括标量、时序、向量、矩阵、张量、多输出、归因、情景、模型训练/推断和迭代求解。

不是仅导出结果值、公式说明文字或调用服务器的函数。正式复现模式不得依赖 VBA、Python in Excel、自定义加载项、外部工作簿、网络或 CalMetricsEngine 二进制。C++ 参考结果可以作为明确标记的静态对照列，但 Excel 结果和中间步骤不得引用该对照列完成计算。

每个算法必须有对应的公式展开方案和覆盖状态。复杂、耦合或来自外部库不能自动成为豁免理由；尚未具备等价展开方案的算法记为开发缺口。有限输入规模下有展开方案，不代表任意规模都能在 Excel 的资源、精度和版本限制内复现。

完整复现的验收同时要求：依赖闭包覆盖、预算通过、Excel 实际重算通过、值与状态核验通过。只通过 C++ 单测、写出 xlsx 或填充公式缓存均不算通过。

C++ 与 Excel 是两个并列、独立触发的计算分支，不要求同时运行。普通 C++ 计算不生成或计算 Excel；生产环境仅在用户调用 Excel 下载接口时启动 Excel 导出链路。浮点精度尾差可以容忍，不要求两种计算的浮点结果逐位一致。

## 2. 架构与职责

```text
       用户算法定义 / 共用数学契约与逻辑 DAG
                  ↙                     ↘
          C++ 计算接口                 Excel 下载接口
                  ↓                     ↓
       C++ 物理计划与执行        Excel 能力与预算检查
                  ↓                     ↓
              原生结果           公式展开 → 工作簿
                                        ↓
                             Excel 重算与容差核验
```

- 复用原生解析、类型和 canonical 算子语义，不在 Python 或平台另写一套公式解析器。
- Excel 后端以有版本的数学逻辑图为依据，保留原始定义、节点与输出映射；不反向翻译 SIMD 指令、arena 槽位或进程计划。复用依赖明确且语义相同的子表达式，保持每个引用可追溯。
- 原生 C++ 负责公式展开规则、形状推导、单元格规划、预算计算和计划身份。工作簿写入层只序列化明确的公式/常量/布局，不能隐藏另一套数值计算或调度逻辑；具体 xlsx 库在实现前评估。
- Excel 是独立核验后端，不是生产请求的数值回退。该要求不放宽现有 C++ 对 NJIT 的速度与内存门槛。
- 平台负责算法选择、导出范围、下载入口、数据权限和业务解释；本契约不新增净值/OHLC 等全局金融输入约束。

### 统一归属与变更联动

Excel 公式生成是 CalMetricsEngine 的正式数学后端。数学契约、C++ 数值实现、Excel 展开规则及两者的核验夹具在同一项目维护和版本化；不能长期由平台独立维护另一套算子数学规则。

| 归属 | 职责 |
| --- | --- |
| CalMetricsEngine 原生 C++ | 共用数学契约与逻辑图、公式展开、类型/形状与状态、布局及全工作簿预算、导出计划身份 |
| CalMetricsEngine 可选 Python 导出包 | 按原生计划分批写入 xlsx、通用样式/说明与产物清理；仅在导出时加载，不自行推导算子公式或数值逻辑 |
| FundInvestmentResearchPlatform | 业务 DSL/历史版本适配、数据权限与时点/窗口选择、冻结真实输入与参数、传入业务展示信息、HTTP 下载与界面 |

项目归属和实现语言分别决定：Python 写出层也归 CalMetricsEngine；首选复用平台现有 XlsxWriter 的逐行写出经验，具体接口与资源边界在实现时验证。引擎不得反向导入平台的变量注册表、服务、存储或 NJIT 计划；平台通过有版本的适配边界提供算法、输入和展示元数据。整个工作簿由引擎统一规划和计数，平台附加的说明内容也须在预检前纳入。

每次修改数学算法、默认值、缺失/错误处理、递推初值、窗口边界或停止条件，必须在同一变更中更新或复核数学契约、C++ 实现、Excel 展开版本和差分夹具。契约变化使原有 Excel 验证证据过期，重新验证前不能沿用“已验证”。仅改变 SIMD、融合或缓冲区而保持语义的优化，可以不改公式，但须说明等价性并运行适用对照。底层机器指令不要求逐条翻译为 Excel。

发布检查须覆盖 canonical 算子、作用域、模型/求解器和组合依赖闭包，并检查版本匹配；登记缺失或证据过期的条目不能宣称 Excel 已支持。尚未完成的 Excel 能力保持明确缺口，不影响已授权的普通 C++ 计算。以上为待实现的工程门禁，不表示当前 CI 已执行。

### 平台现有实现与迁移起点

2026-09-24 静态核对平台本地 HEAD `9b99048d188017816358f581a86b27df1c388161`，以下路径均相对 FundInvestmentResearchPlatform：

- `backend/custom_indicators/excel_formula.py`：`SingleProductExcelFormulaCompiler` 和 `SeriesBundleExcelFormulaCompiler`，包含逐节点公式、可见 A1 引用、辅助状态和时序多通道输出。
- `backend/custom_indicators/excel_rolling_scope.py`、`excel_computation_state.py`：滚动子作用域和状态步骤展开。
- `backend/custom_indicators/excel_export.py`：标量/时序工作簿、XlsxWriter 流式写出、公式预算和临时文件管理。
- `backend/custom_indicators/service.py`、`series_service.py` 及 `/api/custom-indicators/export-excel`：业务定义、真实数据与窗口、NJIT 参考结果和下载编排。
- `backend/tests/test_custom_indicator_excel_export.py`、`test_custom_indicator_time_series_excel.py`：现有迁移夹具与回归入口；存在这些测试不等于已在本轮执行或取得真实 Excel 重算证据。

现有单产品导出不能直接当作引擎全部算法已覆盖：矩阵/组合、通用迭代及模型训练等仍须按全量清单核查。平台现有 `INDICATOR_EXCEL_MAX_FORMULA_CELLS` 的 200 万预算按公式单元格统计，不等于本契约的全工作簿单元格预算；迁移必须明确新旧配置与拒绝行为的变化，不能原样搬用后宣称满足新口径。现有 NJIT 缓存值也不能充当 Excel 实际重算证据。

迁移按可验证范围切换：先提取现有公式/边界夹具与能力清单，对齐平台版本到原生逻辑图，再在引擎实现并完成真实 Excel 对照，最后将已有下载入口接入引擎。同一已切换范围只保留引擎公式实现，删除平台对应规则与失效依赖；未切换范围保留现有真实调用并明确列出，不能自动路由到旧实现掩盖引擎不支持。最后一个范围切换后清理平台公式生成内核，平台只留业务适配和下载编排。迁移不得降低已支持指标的导出能力或悄悄改写历史数学契约。

### 按需触发与隔离

- 普通 C++ 请求不运行 Excel 能力检查、预算规划、公式展开、文件写出或重算，不加载/预热 Excel 组件，也不为 Excel 保留中间值或复制数据。Excel 未安装、映射未覆盖、超预算或重算失败均不影响 C++ 请求准入与结果。
- Excel 下载请求独立绑定算法、输入和参数快照，先预检，再展开公式与生成工作簿。该请求内如包含服务端 Excel 重算/核验，也只按需触发；下载后用户打开工作簿可由自己的 Excel 独立重算。
- 生成公式工作簿与实际 Excel 求值是两个步骤。只生成公式、尚未经过 Excel 重算的本次产物必须标为 `NOT_RECALCULATED`，不能把写入 C++ 参考值当作 Excel 已完成计算。
- 对照优先使用身份一致的已冻结 C++ 结果；没有匹配参考时，可在此次下载请求内按同一快照补算 C++，不能为将来可能的下载而给所有 C++ 请求附加 Excel 工作。
- Excel 导出采用独立任务预算、取消和超时生命周期；需要补算 C++ 时仍复用现有原生 Scheduler，不新增竞争的数值线程池。并列后端不意味着每次请求都同时启动两个任务。
- 开发/CI 可以独立执行 Excel 后端测试，不将该测试路径植入普通生产 C++ 调用链。

## 3. 算子与算法展开登记

每个 canonical 算子、作用域、模型/求解器及已交付算法组合登记：

| 字段 | 必需内容 |
| --- | --- |
| 身份 | opcode/算法 ID、数学契约版本、Excel 展开版本 |
| 类型 | 输入输出 dtype、rank、轴、实际形状及可支持的数值域 |
| 展开 | 原生函数映射或辅助单元格公式、依赖、命名与布局规则 |
| 状态 | 缺失/错误/无效、窗口预热、初始化、重置及停止条件 |
| 成本 | 常量、公式、溢出结果、辅助状态、最大展开元素数与运算量上界 |
| 兼容 | 支持的 Excel 版本、所需函数、公式长度和嵌套约束 |
| 核验 | 夹具、浮点容差、精确字段、真实 Excel 重算证据 |
| 覆盖 | 待设计、待实现、待验证、已验证；不能由存在公式模板直接标为已验证 |

登记必须覆盖现有清单及后续增量，未知条目失败关闭。组合的支持范围由所有可达依赖决定；子图、捕获值和耦合内核内部展开也必须检查。现有算子未实现 Excel 后端前，不停止其已授权的 C++ 能力，但不得宣称支持 Excel 复现。

## 4. 展开规则

| 算法类型 | Excel 表达方式与边界 |
| --- | --- |
| 标量/逐元素 | 有等价证据的内置函数或显式算式；参数引用独立单元格 |
| 滚动/累计 | 每个时点的窗口引用或递推辅助列；准确保留窗口端点、最小样本与重置 |
| 状态/递推 | 前一时点状态、当前输入、状态更新、输出和有效性分别展开 |
| 向量/矩阵/张量 | 标量单元格、二维区域、按其他轴切分的工作表或块；记录可逆轴映射 |
| 多输出/共享拟合 | 共享中间步骤只计算一次，各字段独立投影，保留形状、dtype、状态与来源 |
| 归因/情景 | 显式输入、暴露/权重、贡献、情景变换和汇总公式；复用共享前置计算 |
| 迭代/求解/训练 | 展开初始化和每一步更新/残差/停止判断；按最大迭代数预留空间，停止后冻结状态 |
| 随机算法 | 可精确复现的随机源与变换按版本展开；同 seed 不作为跨后端随机序列相同的证据 |

耦合 C++ 内核可以对应多个 Excel 步骤，不需要为了导出而破坏生产算子粒度。Excel 的 `SUM`、回归、矩阵求逆等内置函数只有通过具体契约核验才可代替相应算法；同名函数或相同数学目标不代表计算方法、退化处理和停止状态相同。必要时展开原计算步骤。

调整行列方向、拓扑布局、拆分工作表和拆分长公式属于布局选择；不能因此改变时间方向、实际数据依赖、阈值规则、稳定排序或因果语义。不同后端的浮点归约/函数实现可以产生经核验的容差内尾差，不要求 Excel 机械复制 C++ 的浮点指令顺序；不能借此替换数学算法或修改 C++ 现有契约。说明步骤必须参与实际计算，不能只画一套装饰性流程。

迭代默认使用无环展开，不依赖 Excel 全局循环引用开关，也不以 Solver 黑盒替代原求解过程。必须有有限上界；不能仅按本次 C++ 提前收敛次数规划，以免用户改参数后公式链缺失。达到上限保留原契约的非收敛/最后有效状态，不强行输出“成功”。

可以另外提供“固定随机带重放”或“固定已训练模型推断”的核验范围，但必须显式标注起点：前者不验证随机源生成，后者不验证训练。它们不能替代完整算法复现，也不能在完整导出失败后静默降级。

## 5. 预算与拒绝规则

默认整个工作簿 `max_cells = 2,000,000`。它是本项目的导出预算，不是 Excel 自身的单表上限。预算判断发生在分配大数组、展开海量字符串或写入文件之前。

计数包括输入、参数、模型/随机数据、全部可达中间值、状态/掩码、输出、参考结果、对照公式，以及实际写入的标题/说明单元格。动态数组按完整溢出区域计数，锚点只计一次；相同共享单元格被多次引用只计一次，不同位置的副本分别计数。纯空白且未写入内容的地址间隔不计数，但仍受行列位置限制。

除物理单元格预算外，单独限制内部数组最大展开元素数、总公式字符数、估计运算量、写出内存/文件字节和导出时间。不能用 `LET`/`LAMBDA`、名称或单个溢出锚点把巨大计算隐藏成“一个单元格”。这些附加阈值须经实现基准确定，不在未测量时编造 Excel 重算耗时保证。

预检流程：

1. 绑定冻结的算法/数据快照、选定输出、实际 shape 和目标 Excel 配置。
2. 检查全依赖闭包、公式映射、数值域和函数兼容性；收集所有独立拒绝原因。
3. 按参数、输入尺寸和最大迭代/窗口/情景数量计算保守上界；使用有溢出检查的整数算术。无法确定上界时拒绝，不能记作零成本。
4. 比较总单元格及其他预算，同时检查 Excel 行列、公式和依赖限制。大布局可换方向或分表，但不能通过分表规避整个工作簿的总预算。
5. 预算通过后产生不可变导出计划；写出阶段累计核对实际占用。数据/参数/定义变化必须重新预检；超限中止并清理临时文件，不交付伪完整文件。

预检报告至少包含：状态、拒绝原因列表、预算值、预计/上界单元格数、成本最大的节点与作用域、输出覆盖范围、计划指纹和可调整维度。示例：

> 超预算，无法生成本次算法的完整 Excel 复现。预计最多需要 2,430,120 个单元格，预算为 2,000,000。主要来自情景×迭代展开。可减少情景数、输入区间或所选输出后重新预检。

若保守上界超预算，要明确是“上界超预算”，不声称每次实际计算都必然达到该数量。完整导出不能偷偷缩短窗口、抽样产品、减少迭代或删除输出。用户明确选择子范围时允许导出，但保留所选输出的完整依赖并醒目标记范围。

## 6. 工作簿与用户核验

建议工作簿包含以下可见区域，不通过隐藏工作表藏起算法：

- `说明`：算法与构建身份、Excel 展开版本、支持的 Excel 配置、输入哈希、输出范围、预算和核验状态。
- `输入与参数`：带轴/类别映射的输入、参数、初始状态及模型字段；参数允许在注明的有效域内修改。
- `节点索引`：节点 ID、算子/数学步骤、来源表达式、依赖、dtype/shape 与对应单元格范围。
- `计算步骤`：分块排列的实际公式和中间状态；每个耦合内核提供可展开的步骤与迭代索引。
- `结果与核验`：Excel 值、冻结 C++ 值、两侧状态、绝对/相对误差和通过标记；可定位首个不一致节点。

允许 C++ 与 Excel 存在合理的浮点精度尾差，不要求逐位相等。有限浮点值采用每算法登记的 `abs(a-b) <= atol + rtol * abs(reference)`；`atol`/`rtol` 可配置，在核验前确定并随工作簿记录，展示实际误差和容差内通过状态。不能通过只比较显示位数、修改输入或事后放宽容差制造一致，也不能用统一宽容差掩盖数学逻辑差异。

尾差容忍适用于浮点数值，不等于放宽 bool、索引、状态和分类规则；这些离散结果仍应一致。尾差若导致分支、分类或终止状态不同，应明确报告，不能仅因最终浮点值接近而静默通过。NaN/Inf/无效以独立值类别与状态表示，不能混同空白、零和 Excel 错误值。

Excel 对数值精度和可表示范围的限制需要单独处理。int64 标识可作为文本保真存储，但涉及计算时必须有经过验证的精确分解表示/运算，否则拒绝该数值域。不能把 64 位整数直接转成 Excel 数值后声称无损。日期纪元、bool、负零及特殊值的序列化和比较规则也要登记。

用户修改输入后，工作簿应显示“已偏离参考快照”，原 C++ 对照不再代表新输入。规模或迭代上限超出已分配范围时提示重新导出；不能无声截断或把旧缓存当新结果。公式可查看和编辑，编辑后的算法视为用户修改版；服务侧核验通过导出计划/公式身份检测改动，不承诺纯工作表能防止用户篡改核验标记。

已验收配置为 macOS arm64 的 Microsoft Excel 16.89.1，样本范围与构建身份见第 10 节；不能推广为其他桌面版本均已验证。尽量用清晰的基础公式与辅助单元格；采用较新函数时必须登记具体版本。Excel 2021、WPS、LibreOffice 等须分别验证，不能由文件格式相同推定兼容。

## 10. 原生实现与验收

### 实现设计

本轮在 CalMetricsEngine 工作树内实现导出模块，不改平台下载接口，不改 canonical 数值内核。新接口及数值域详见[导出使用说明](excel-export.md)。

| 层 | 文件 | 责任 |
| --- | --- | --- |
| 不可变导出计划 | `cpp/include/calmetrics_engine/excel.hpp`、`cpp/excel.cpp` | 输入/图快照、预算、地址、输出映射、计划及构建身份、原生参考计算 |
| 符号预算 | `cpp/excel_budget.cpp` | 形状与作用域抽象解释、全部 recipe 的保守成本、溢出/未知边界拒绝 |
| 算子展开 | `cpp/excel_operators.cpp`、`cpp/excel_state.cpp` | 146 个算子的真实公式，矩阵消元、状态机、峰谷及递推辅助单元格 |
| 子图展开 | `cpp/excel_scopes.cpp` | rolling/block/filter/group/segment/bisect/iterate，实例化上下文与逻辑父节点映射 |
| 类型边界 | `cpp/excel_bindings.cpp` | 精确 dtype/shape/符号维度、快照所有权、原生批量流接口 |
| 文件序列化 | `src/calmetrics_engine/excel.py` | 可选 XlsxWriter、逐行写入、缓存标记、临时资源检查与原子替换 |
| 差分与交付检查 | `tests/test_excel_export.py`、`tests/excel_native_tests.cpp`、`tests/excel_cases.py`、`tools/check_excel_parity.py` | 目录覆盖、预算/所有权/故障隔离、真实表格引擎重算及公式身份核对 |

依赖身份沿用逻辑图，单个上下文的 CSE 节点只展开一次；不同窗口、成员集合和迭代状态建立不同上下文。公式只读永久地址，不复用物理 arena 槽。矩阵/张量用行优先映射；多输出保留 dtype、轴和形状，记录字段分别导出。Python 不推导公式、执行算法或创建计算池。

规划先限制输入规模及快照字节，由 `cpp/excel_budget.cpp` 对所有 146 个 canonical 算子和全部现有作用域做独立符号上界分析，不创建公式字符串、地址或逐元素数组。按上界准入后，再通过有界计数遍历确定实际布局/字符数；展开与写出都核对符号上界和实际计数。时间/工作量上限是资源拒绝规则，不是性能承诺。详细规则见本节末的符号预算设计。

数值核验由同一快照的原生 Scheduler/算子产生参考值，与表格引擎实际重算结果比较。生成文件的缓存一律为 `NOT_RECALCULATED`；不能拿原生结果预填公式缓存。浮点容差在导出前绑定，离散结果精确比较。核验同时检查公式 token、输入、冻结参考和原始文件 SHA-256；仅规范化引擎保存时的等价语法（函数前缀、绝对引用标记、布尔常量及科学计数法）。

### 符号预算补全设计（本轮）

在任何公式/地址展开前增加独立的 C++ 形状抽象解释：只携带 dtype、shape、可证明的配置标量和错误几何，不保存逐元素引用、不执行数值核验。每个 canonical recipe 声明辅助公式数量的保守代数上界；统一叠加错误传播、节点索引、输入快照、结构守卫、输出及核验列。整数加乘检查溢出，未知配置保持 `UNKNOWN_BOUND`。

块作用域、固定窗口和迭代按实例数相乘；变化长度的窗口、过滤和分段仅遍历不同形状，按该形状出现次数加权，不展开逐单元格逻辑。共享 DAG 节点在一个上下文只计一次，不同上下文分别计数；迭代按最大次数计算，不依赖实际收敛。

上界准入与实际布局计数分别保留。公式字符采用公式单元格数量乘 Excel 单公式上限的保守上界，报告明确区分上界和实际数；因此上界拒绝不等于实际文件必然超限。准入后现有计数遍历继续验证公式兼容性和确切地址，写出累计必须不超过符号上界，并与精确预检一致。回归已遍历全部公式夹具核对上界、嵌套/共享/多输出、边界和溢出，并验证大型请求在公式展开前拒绝。原生 geometry-only 测试不提供可读数值缓冲区，用于证明符号预算不依赖数据求值。
