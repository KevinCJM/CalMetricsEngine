# Excel 公式生成的数学与编程纪律

本文是 CalMetricsEngine Excel 后端的设计、开发与审核规范。入口为 [AGENTS.md](../AGENTS.md) 和[文档索引](README.md)，通用数学原则沿用[编程与数学计算纪律](computation-design-rules.md)，功能范围、预算口径、产物状态与迁移阶段由 [Excel 复现契约](excel-reproduction-design.md)统一定义。

## 1. 适用范围与权威边界

- 设计、开发或审核算法、算子、作用域、公式展开、布局、导出与核验时，必须阅读本文并记录适用规则的依据。使用已有任务设计、验收记录或审核意见，不要求每轮新增报告。
- 本文规定如何实现和证明正确性，不另建算子目录、数学定义、状态枚举或阶段计划。数学契约由 canonical 算子/算法契约统一维护，两个后端分别实现并核验；不承诺从 C++ 源码自动推导出正确的 Excel 公式。
- Excel 数学后端及可选工作簿写出包归 CalMetricsEngine；平台保留业务定义适配、输入选择、权限、时点/窗口及下载入口。不得把净值/OHLC、单产品数量或平台特有阈值变成引擎的全局限制。
- 本规范即日起约束相关工作，但不表示 Excel 后端、自动检查或迁移已经实现。已有 C++ 能力和性能门槛不因 Excel 覆盖缺口而改变；本文不授权改写历史算法、切换平台服务或删除现有能力。

## 2. X1：先确认数学契约，再选择 Excel 表达

- 从同一有版本的逻辑 DAG、参数绑定与算子契约展开，保留节点和多输出投影的来源。不得从展示文本、渲染后的 LaTeX、SIMD 指令或 arena 槽位反推数学含义。
- 使用 Excel 内置函数前，核对定义域、默认值、ddof、权重、分位数、空集合、边界等号、缺失处理与求值范围；名称相同或实数域公式相同不足以证明等价。
- 不允许为便于导出而填零、前向填补、加扰动、改用伪逆、截断数值或统一替换分母阈值。只有原数学契约允许的处理才能进入公式；无法表达时明确报告支持缺口或数值域限制。
- 求解与拟合保留原算法的初始化、停止含义、失败诊断和适用的残差/可行性条件，不能把目标函数相同当成求解过程等价。耦合内核可以展开成多个公式步骤，无须为了 Excel 改变生产算子粒度。
- 浮点尾差沿用复现契约中预先确定的逐算法容差，不要求指令顺序或结果逐位一致；离散分支、索引、排序、分类和终止状态的变化须单独报告，不能用最终值接近掩盖。

## 3. X2：每个数学步骤必须真实、可追溯

- 输入、参数、初始状态、中间步骤、输出及状态均建立逻辑节点到工作表/区域的映射。标量、向量、矩阵、张量和异构多输出保留各自的 dtype、轴、形状和字段身份，不能只导出主输出。
- 优先使用可见的 A1 单元格/区域引用；跨表引用明确来源。辅助公式和展开说明必须对应实际参与求值的步骤，不建立装饰性流程，不借隐藏表、名称或不透明函数藏起算法。
- 完整复现不依赖 VBA、加载项、Python in Excel、外部工作簿、网络或引擎二进制。C++ 参考值单独标记，计算公式的依赖闭包不得读取参考值来得出 Excel 结果。
- 共享中间结果可由多个输出引用；临时单元格一旦被其他公式引用或列为核验步骤，就不能按 C++ 缓冲区复用方式覆盖。删减或合并步骤须保留等价的依赖与可解释映射。
- 参数变化必须沿真实引用传播，不能把由参数算出的中间值固定成常量。用户修改后的算法与输入须区别于原参考快照；不能把旧缓存展示成已重新计算的结果。

## 4. X3：类型、数值域和错误不隐式转换

- 显式区分数值零、FALSE、缺失、NaN、正负 Inf、无效值和执行错误。表示与传播沿用值/状态协议，不用一个空白、`#N/A` 或 `IFERROR(...,0)` 吞掉全部差异。
- int64 标识可以按契约用文本保真；参与算术、比较或排序时，须验证数值表示的适用域，必要时采用经过验证的精确分解，否则拒绝。文本保真不能当作整数运算保真。
- 日期纪元、时区边界、类别映射、负零和 bool 转换必须显式。工作表格式只控制显示，不能改变计算值；不能用显示精度比较代替数值核验。
- 缺失筛选和掩码不能压缩原始时间位置或改变轴配对。逐位置错误沿实际消费的依赖传播，健康输出保持独立；上游数值失败不能跳过独立结构校验，也不能因为扫描扩大而引入未消费数据的错误。
- 数值域及 Excel 版本能力在展开前校验，不支持的条目不得生成同名伪函数或静默改为常量结果。

## 5. X4：窗口、递推和作用域按原顺序展开

- 明确窗口端点、最小样本、预热、时间方向及局部上下文。每个窗口执行完整子图，不能将全历史计算结果切片当作窗口内重新计算；收益窗口与价格窗口的长度关系按原契约处理。
- 递推显式列出前一状态、当前输入、更新条件、重置条件、当前输出和有效性；窗口内状态、全历史状态、产品间状态、情景间状态不得混用。
- 滚动、分组、过滤和分段子图保留捕获参数、局部索引和原轴映射。布局转置、拆表或排序只改变存放位置，不得改变因果依赖、稳定排序与同值规则。
- 矩阵/张量布局须有可逆的轴到单元格映射；明确行列方向、广播和收缩轴，保留所有被选择输出的完整依赖闭包，不把逐项配对变成笛卡尔积。

## 6. X5：迭代、模型和随机具有有限可核验展开

- 展开初始化、每次更新、残差、停止判断和状态；停止后依契约冻结。按最大迭代数而非本次 C++ 实际提前停止次数预检，预算耗尽与成功必须分开表达。
- 默认无环展开，不依赖 Excel 全局循环引用设置或 Solver 黑盒。不能确定有限上界时拒绝本次完整导出，不能无限生成或省略后续迭代。
- 复用模型/分解前证明其数据、参数、状态和随机依赖不变；情景改变训练样本时不能仍使用原模型冒充重新拟合。完整训练导出包含训练过程，不只写入最终参数。
- 随机算法、流、种子和消费位置须明确；不得用未验证等价的随机函数替换原随机源，也不能仅凭相同 seed 声称一致。随机节点与状态节点不作为普通纯表达式任意合并。
- 固定随机带重放或冻结模型推断属于显式子范围，遵守复现契约的标记要求；完整导出失败时不得静默降级为这些范围。

## 7. X6：共享与布局优化必须有依赖证明

- 承接通用纪律 D1–D5：依赖、参数、轴、窗口、状态和随机身份一致才允许共享。共享拟合与多输出投影只展开一次适用的公共步骤，变化部分独立展开。
- 保留实际需要的对角、低秩或分块结构；不能因为 Excel 使用二维单元格就提前展开所有完整矩阵，也不能把未经授权的近似写成精确等价。
- 优化同时考虑单元格数、公式长度、重复计算、依赖链和可读性；压成一个长公式不自动代表更便宜。不得用动态数组、`LET`/`LAMBDA` 或名称隐藏预算与中间语义。
- 精确引用已规划范围，避免为了拼接方便引入未声明的整行、整列或动态依赖。布局变化后验证引用边界、相对/绝对引用、共享范围和跨表映射，不能只检查最终结果地址。
- 生成顺序服务于正确引用和流式写出，Excel 求值依赖以公式引用为准；不能依赖工作表顺序、文件写入先后或某种重算线程顺序维持数学正确性。

## 8. X7：预检覆盖整个工作簿和展开成本

- 全工作簿预算口径、默认 2,000,000 单元格上限与拒绝状态统一遵守 [Excel 复现契约第 5 节](excel-reproduction-design.md#5-预算与拒绝规则)。不是只统计公式，也不是每张表分别使用一份预算。
- 先冻结算法/输入/参数和选择范围，检查全部可达算子、类型、数值域及版本能力，再用有溢出检查的整数计算展开上界。嵌套窗口、迭代、情景和动态数组必须计入真实展开规模。
- 预检不应先分配所有单元格对象或生成全部公式字符串。按规则和实际尺寸推导成本；无法确定上界、整数溢出或独立能力缺口均明确报告，不能记成零成本。
- 预算同时覆盖写出内存、文件、公式内容与估计运算量等适用资源，具体定义与阈值由复现契约及实测证据维护。分表、旋转或缓存不使成本消失。
- 写出时累计核对实际占用；超出计划或遇到能力错误就中止并清理产物。不得截断产品、时间、输出或迭代后仍标为完整导出；保守上界超限不能表述为实测占用。

## 9. X8：结构化生成、分批写出与明确所有权

- C++ 负责数学展开、类型/形状、单元格规划、预算和导出身份；Python 写出层只序列化已规划的常量、公式、布局与元数据。不得在写出层新增公式推导、数值回退或竞争的规划器。
- 引用由已校验的节点、工作表、行列和区域对象生成，集中处理函数名、字面量、转义及目标版本语法。禁止对任意完整公式字符串盲目替换坐标或把用户文本当作可执行公式；不要求为此建设任务无关的通用框架。
- 输入名称、标题、说明和业务元数据按文本写入，关闭字符串自动转公式/URL，统一校验工作表与文件名称。可执行公式只来自受支持的逻辑图和受控展开规则。
- 地址和区域先规划，随后按每张表的行序分批写出；不先写占位值再回填已刷新的行。跨表引用可使用已规划地址，不必为此保留全部单元格对象。
- 批次大小、字符串缓冲、写出库缓存、临时文件及取消路径均有明确预算和所有者。不逐单元格往返 PyBind；分批序列化边界不得介入普通数值热路径。序列化和压缩存在必要成本，不宣称整个 xlsx 生成零拷贝。
- 同一冻结身份与目标配置应产生可复验的公式和布局。文件时间戳等非数学元数据若不同，单独标记；算法/输入变化、布局变化和展示变化的身份不能混为一谈。

## 10. X9：快照、按需触发和失败隔离

- 普通 C++ 请求不加载、预热或调用 Excel 规划/生成/写出/重算，不为未来下载保留额外中间值。生产导出只由下载请求触发，开发与 CI 核验独立运行。
- 图/数学契约版本、展开版本、输入和参数身份、所选输出及目标 Excel 配置共同绑定导出计划。数据源在导出期间变化时，按快照契约拒绝混合版本；仅地址和 shape 不足以证明输入相同。
- 持有输入所有者不等于内容已冻结。采用可信不可变数据、受控锁定或必要快照复制保证一致性，并说明复制成本；不要为了导出无条件改变普通 prepared 执行的输入契约。
- 布局缓存、数值参考和可变写出缓冲分别管理；缓存命中仍需满足对应身份与失效条件。用户修改输入后旧参考失效，修改规模超过预留范围时要求重新导出，不保留伪通过标记。
- 任务取消、超时、异常和下载结束按明确所有权释放资源。依赖消费者结束后再释放绑定；未完整关闭的临时产物不作为成功文件交付。补算 C++ 参考仍进入现有 Scheduler，不另起数值线程池。

## 11. X10：真实重算、差分和变更联动

- 生成成功、公式结构正确、Excel 实际重算及数值核验分别报告。未经过目标 Excel 重算的产物标为 `NOT_RECALCULATED`；写入缓存值、打开文件或通过 C++ 测试不等于 Excel 已验证。
- 在声明的 Excel 配置强制重算并读取值/状态，记录图、输入、展开与构建身份。第三方公式解释器、XML 检查和缓存读取只能提供对应层证据，不能替代目标 Excel 验收。
- 对受影响节点和输出执行逐算法容差对照与独立数学不变量；保留 bool、整数、索引、状态的精确比较。覆盖空/短样本、缺失、窗口重置、退化矩阵、阈值相等、迭代停止和随机消费；不只比较最终一个标量。
- 测试预算边界、整数溢出、多表/共享节点/溢出区域计数、流式行序、引用映射、文本转义、输入编辑与参考失效、取消清理，以及 Excel 失败不影响普通 C++ 请求。选择与本次变更相关的测试，不为未使用的能力建设测试框架。
- 性能分别测量预检/展开、写出、完整导出及实际重算的时间和内存，计入临时存储与保留产物；控制输入、覆盖范围和 Excel 配置。文件更小或公式更少不能单独证明重算更快，Excel 不套用原生对 NJIT 的性能门槛。
- 数学契约变化必须在同一变更中同步复核 C++ 实现、Excel 展开、预算与差分夹具；相关证据过期后不能继续标为已验证。仅 SIMD、融合或缓冲优化可不改公式，但须记录语义等价依据和适用回归；布局/公式改动同样需要覆盖、预算和重算影响核对。
- 支持范围按算子、子作用域、模型/求解器及组合的依赖闭包登记，未知与待验证条目明确可见。规范要求不代表自动 CI 已上线，不能用文档中的门槛冒充执行结果。

## 12. 设计与自审核的最小记录

在本任务已有设计或审核中回答以下问题；不适用时写明原因。

| 必答项 | 应提供的依据 |
| --- | --- |
| 数学从哪里来，是否改变？ | 统一契约版本、节点/输出映射、默认值及错误/时间语义，差异与支持域 |
| 哪些步骤共享，哪些必须保留？ | 输入/参数/状态/随机依赖，真实公式及单元格映射，不覆盖仍有消费者的区域 |
| 展开能否容纳并完整写出？ | 全依赖闭包预算、有限上界、行序、缓冲与输入所有权，超限/取消清理 |
| 何以证明可以核验？ | 目标 Excel 重算身份、浮点与离散对照、不变量、输入编辑及参考失效验证 |
| 对现有路径有什么影响？ | 按需隔离、版本/覆盖变化、适用性能证据与未验证事项 |

仅修改本规范时，检查必读入口、相对链接/锚点、Markdown 格式及与现有契约的一致性。没有变更运行代码或可执行示例时不重跑数值/性能套件，也不据此宣称 Excel 功能完成。

## 13. 平台规则的采用边界

本规范参考 FundInvestmentResearchPlatform 的 `docs/indicators/excel-export.md`、`docs/indicators/rolling-intervals.md` 及算子/计算规范：继承真实输入、真实公式、可见引用、完整窗口子图、流式行序和超预算拒绝。

平台既有单产品/产品数量限制不成为通用引擎限制；其公式单元格预算不等于全工作簿预算，其固定分母阈值和容差不自动适用于所有原生算子，其 NJIT 根缓存值也不成为 Excel 重算证据。现有能力与迁移基线继续以复现契约记录为准，不把文档要求当作已完成迁移。
