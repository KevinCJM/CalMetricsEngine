# 编程与数学计算纪律

本文是 CalMetricsEngine 数值算法、计算图、模型/状态复用及执行优化的开发与审核规范。入口为 [AGENTS.md](../AGENTS.md) 和[文档索引](README.md)；当前接口与实现分别查[用户指南](user-guide.md)、[算子参考](operator-reference.md)和[执行指南](execution-guide.md)。

## 1. 适用范围与权威边界

- 在相关设计、开发和审核前阅读本文。将适用规则的依据写入已有任务设计、验收记录或审核意见；不要求每次新建报告，也不因本文要求建设任务未使用的框架。
- 本文细化 AGENTS 的 C++/AOT、最小独立算子、统一调度、所有权和数值契约原则。已有规则继续适用；本文不复制算子目录、调度阈值或阶段性能结果。
- 涉及情景不变性分析、低秩执行、增量状态、检查点及批量求解的要求，适用于实现或修改这些能力时，不表示它们已经完整实现。当前支持范围必须由代码、测试和对应验收记录确认。
- 输入选择、金融解释、年化依据、业务可得时点和投资资格由调用平台负责。引擎执行显式的数学、类型、轴、状态和错误契约；既有 Typed IR 语义校验不能借此删除。
- 本文不授权变更已有数学口径、默认值、历史定义或迁移生产链路。发现实现与契约不一致时记录差异、核查依据，在授权范围内处理，不修改文档以掩盖缺陷。

## 2. 数学契约先于实现选择

每个新增或修改的数学能力，先在唯一的算子/算法契约中明确下表内容。已有契约可直接引用；不另建与 canonical 注册表、类型推导或原生内核竞争的定义来源。

| 契约方面 | 必须明确的内容 |
| --- | --- |
| 输入输出 | dtype、rank、shape、轴身份和方向、广播规则、只读/别名要求；多输出各自的字段、形状和状态 |
| 定义域 | 参数范围、分母/对数/开方条件、空输入及短样本、缺失/无效/NaN/Inf 的区别和处理 |
| 数学口径 | 公式、权重含义与归一化、ddof、分位数约定、区间端点、阈值等号、排序与同值规则 |
| 时间与状态 | 历史范围、预热、初始化、重置、状态转移、是否依赖未来或完整样本 |
| 迭代与随机 | 初值、随机算法/流、抽样顺序、停止条件、预算、失败时保留内容及诊断 |
| 等价要求 | 精确比较的字段、逐项浮点容差、残差/不变量，以及允许或禁止的解、标签和顺序变化 |

数学实现与审核遵守以下纪律：

1. **代数等价不自动等于浮点或行为等价。**重排归约、FMA、补偿求和、增量统计和替换分解算法，都须遵守既有数值契约并完成差分验证。不能因表达式在实数域相同就忽略舍入、溢出和 NaN 传播。
2. **不得用隐式修补制造有效结果。**填零、加噪声/对角扰动、截断概率或特征值、改用伪逆、放宽容差，只有原契约明确允许才可执行；否则按既有失败策略处理。获授权的口径变化须显式版本化。
3. **容差不能吞掉离散行为差异。**bool/int64、状态、索引、边界、分段和有效性按契约精确比较；浮点尾差不能未经允许改变排序、分类、选择结果或后续动作。不能用一个全局 `allclose` 覆盖所有算法。
4. **求解成功需有数学证据。**解方程检查残差；约束优化检查原目标、可行性及适用的 KKT/对偶残差。未找到可行点不等于证明不可行，局部停止不等于全局最优；预算耗尽、数值失败与执行错误分别表达。多解、特征向量符号、聚类标签置换仅在契约允许时做等价映射。
5. **数值稳定性也必须守约。**在允许选择实现时优先使用稳定归约、方程求解和适合矩阵结构的分解；求解线性方程不默认显式求逆。病态、奇异、秩不足输入须有诊断与测试，不能只验证良态随机样本。
6. **参考实现与独立不变量并用。**按算法适用性验证贡献加总/残差重建、概率归一化、矩阵分解重建、约束满足等。两份实现结果相近不能单独证明数学正确；参考缺陷不能借迁移静默修正。

## 3. D1：先声明依赖，再决定优化

- 区分纯计算、读取/更新状态及消费随机流的节点，说明输出实际依赖的输入、参数、模型、轴、窗口和状态。不能只按函数名、输出形状或节点外观判断等价。
- CSE、缓存、循环外提和并行分块分别给出合法性依据。随机流身份和抽样位置、状态实例与重置边界不同的节点，不能当作相同纯表达式合并。
- 依赖信息沿 AST、Typed IR、lowering 和物理计划保持一致；融合后仍能追溯逻辑输出。不能省略仍被消费的依赖，或用一个主输出代替其他异构输出。
- 对本任务使用的优化明确前置条件和不适用路径；无法证明合法时继续使用现有受支持的原生路径，不省略校验或回退到 Python。文档中的依赖说明不能替代优化器需要的实际检查。

例：情景只改变冻结模型的预测输入时，可复用模型；情景改变训练样本并要求重新拟合时，拟合结果随情景变化，不能提前固定。

## 4. D2：准备与重复执行分离，复用必须可失效

- 对重复负载，区分图/问题构造、拟合或矩阵分解、执行、结果封装。优先复用实际重复且兼容的准备工作，不强制一次性小任务建立昂贵缓存。
- 计划结构、数值分解、模型、结果和可变迭代状态是不同复用对象，分别声明身份、有效期及失效条件。结构不变可能允许复用工作区，但输入系数变化仍可能使数值分解失效。
- 数值结果/分解/模型的复用身份须覆盖相关数据内容或可信不可变版本、参数、轴/布局、算法与数值策略，以及适用的初值和随机身份。数组地址、shape、对象名称相同不能证明内容未变。
- prepared 输入绑定可保持地址和几何不变，同时按现有契约读取本次数据或参数；不能据此缓存过期数值。区分几何校验与内容有效性，不要求每次请求无条件扫描并哈希整块数组。
- 只读模型可以共享；可变 solver workspace 和迭代状态须独占或有明确同步机制。缓存需有界、可释放，常驻字节参与预算与性能比较。
- 批量求解可复用同一问题结构，并在满足条件时复用分解或初值。热启动不得静默改变初始化契约、非唯一解选择、停止含义或历史结果；缓存命中和失效均需验证。

## 5. D3：公共输入与变化输入显式区分

实现情景、模型或候选批处理时：

- 显式声明公共输入与沿指定轴变化的输入。所有情景共用一个值，与“只含一个情景的数组”是不同契约，不能仅凭长度为 1 自动互换。
- 公共输入优先只读视图或共享描述；广播保持逻辑含义，不能默认复制为“情景数 × 全量输入”。确需物化时说明消费者和成本。
- 不变性必须沿真实依赖传播。将不变拟合/分解移出批次循环前，核对数据、参数、状态、随机性和重置策略，而非只检查被直接扰动的字段。
- 批次组合、轴顺序、对应关系和输出定位必须明确；不能把逐项对应改成笛卡尔积。每个输出保留所属批次及适用的失败状态。
- 不引入默认的跨请求脏数据推断。跨请求重用仍受 D2 的身份与失效条件约束。

## 6. D4：保留数学结构，按消费者需要物化

- 对角、低秩、稀疏或分块结构应在具备真实消费者且收益可验证时保留；不因类型方便提前展开完整矩阵，也不为未使用的结构建设通用框架。
- 声明结构是输入契约保证、经过验证，还是近似估计。不能默认矩阵对称正定、默认残差对角，也不能用截断降秩冒充精确等价。
- 复用已有 `dot`、`matvec`、`matmul`、`solve` 等数学能力。仅缺少独立可复用语义时新增 canonical 算子；结构化物理优化不自动成为新的公开算子。
- 消费者需要完整矩阵、历史轨迹或明细时必须按契约返回；只请求汇总时，避免构造未使用的完整数据。计算身份、Planner 预算和 worker 传输须覆盖真实表示。

例如，显式给定 B∈R^(N×K)、F∈R^(K×K)、d∈R^N 和 w∈R^N，且契约定义：

```text
Σ = B F Bᵀ + diag(d)
q = Bᵀ w
wᵀ Σ w = qᵀ F q + Σᵢ dᵢ wᵢ²
```

这里 d 是对角项本身；若输入定义为标准差，必须按该输入契约显式平方。在 K 远小于 N、消费者只需该二次型时，可以避免构造 N×N 的 Σ。公式的数学等价不豁免浮点差分，也不承诺所有 N/K 或完整输出负载都更快。

## 7. D5：减少扫描和中间存储，保持可观察行为

- 对兼容的运算链优先评估寄存器/缓存块融合、共享窗口历史、合并扫描及独立根直接输出；不要求所有节点必须融合。保留逻辑图的可编辑步骤、字段投影和来源。
- 中间值是否物化由实际用途决定：被输出、被其他分支消费、需保存状态或供算法多次访问时可以保留；只为“每个节点有一个数组”而分配全长缓冲应说明必要性。
- 共享窗口需匹配输入、端点、预热、缺失策略和重置语义。时间分块要满足历史读取依赖；不能读取其他尚未完成任务的输出作为历史，或让一个分块覆盖另一个仍需读取的缓冲。
- 融合必须保留错误策略与适用的求值语义。上游数值失败不能跳过独立结构校验；未消费的坏数据也不能因为扩大扫描范围新增错误。掩码、状态及实际形状不可在融合中丢失。
- 原地更新须证明旧值不再被其他消费者使用，且符合失败恢复契约。需要保留最后有效状态时，不能提前覆盖；借用输入和先前独立结果不得成为可写工作区。
- 每类复制说明来源、去向、字节数和必要性：输入打包、算法 scratch、状态、结果物化、IPC、共享初始化。正常计算写入不算复制；直接写结果也不代表无需分配或保活。

## 8. D6：由依赖和完整成本选择布局及并行

- 沿可证明独立的产品、路径、候选或批次分块。时间递推保持先后依赖，可评估跨独立产品 SIMD；截面运算需保证所需截面完整，窗口运算需保证重叠历史正确。
- 保留默认产品连续/SoA 布局和通用 strides 契约。采用块布局、打包或转置须有数据规模与复用次数依据，计入转换成本；不得通过默认填齐不同日历改变输入含义。
- 先共享、融合，再由同一个原生 Scheduler 选择执行方式。算子、BLAS 或第三方原生库的线程必须受同一预算约束，不能隐式创建竞争线程池。
- 小任务保留低固定开销路径。多进程、共享内存、更多线程及 SIMD 候选标记都不是提速证明；隔离/Hard Stop 的必要性与速度收益分别说明。
- 记录实际采用的计划和路径，不将预计 SIMD 覆盖、线程数量或内存容量当成运行效果。分块变化还须验证状态、随机消费和结果顺序。

## 9. D7：状态、随机与恢复具有完整生命周期

实现增量或可恢复计算时：

- 声明初始化、预热、更新顺序、区间/产品/情景重置和终止条件；窗口状态与全历史递推状态不能混用。
- 明确乱序、重复输入、历史修订的处理方式：按公开契约拒绝、重置或从合适检查点重放，不能静默追加后继续使用过期状态。
- 检查点绑定兼容的图/算法、参数、schema、状态协议、已消费输入位置/版本和随机位置；有硬件或构建限制时显式声明。恢复前校验兼容性，不能仅凭字节长度或种子相同接受。
- 部分失败、取消和超时后，说明状态是可继续使用、需恢复还是已失效；多字段状态不能留下未标明的半次更新。独立任务的可变状态不得共享。
- 明确当前缓冲的借用寿命与独立快照；保存结果必须使用支持的独立所有权方式。数组切片或只读标志不自动构成独立副本。
- 随机算法、版本、种子、流和消费顺序进入契约。不同 worker 数量下的确定性按声明范围验证；同随机带的路径等价与旧 seed 的序列等价分别验收。不得通过固定全局随机状态或合并独立抽样节点制造一致性。

## 10. D8：用对等的完整负载证明收益

- 在优化前确定对照算法版本、代表负载、接口层级、数值精度、CPU/内存预算、准备程度和结果保留寿命；不得删掉已冻结的失败负载，或用减少输出、放宽容差、增加核数换取胜出。
- 冷启动/准备、普通入口和预绑定执行分别计量。普通入口包括必要的校验、绑定/规划、调度、IPC 和结果封装；prepared 与同等准备的基线比较，借用输出与借用输出比较，独立结果与独立结果比较。
- 区分准备成本、单次执行、累计分配、工作区峰值、常驻缓存/模型、保留结果和父子进程内存。计时前分配的工作区仍计入运行阶段占用；不能通过缓存或预处理转移成本后声称成本消失。
- Planner 估算、malloc 追踪、RSS/PSS、共享映射及复制计数分别报告范围和盲区。未覆盖的 Python arena、mmap 或 worker 不得记作零；共享页应说明重复计量或去重方式。
- 微基准用于定位瓶颈，验收覆盖受影响完整链路和小任务固定开销。使用交替顺序、重复配对测量及适用的统计不确定性；性能结论限定到实测负载和构建。
- 平台迁移继续执行[完整承接规划](platform-compute-roadmap.md)第 13 节的逐负载时间/内存严格双优门禁；AGENTS 中既有更强门槛继续执行。本文不降低阈值、不重写历史结果，不以大负载优势抵消小负载失败。

## 11. 设计、自审核与验收的最小记录

在已有任务设计或审核中回答以下四项；不适用时写明具体原因，不要求制造无关检查或新增自动化系统。

| 必答项 | 应提供的依据 |
| --- | --- |
| 哪些工作可以共享，哪些必须重算？ | 真实依赖、纯计算/状态/随机分类、复用身份与失效条件 |
| 哪些数据必须分配或复制？ | 表示方式、消费者、布局、所有者、生命周期、必要 scratch 与预算 |
| 优化为何合法？ | 数学/错误/时间契约、别名与分块依据、不适用范围及原生执行路径 |
| 正确性与收益如何验证？ | 差分与不变量、状态/错误/所有权测试、完整负载时间和内存证据 |

新增类型或算法按适用范围核对 AST、Typed IR、DAG、Planner、worker 编解码、结果状态和所有权；direct API 成功不能代替整图支持。数学、执行安全、性能及平台集成分别给出结论，不能以单项通过代替全部验收。

仅修改本规范时，检查入链、相对链接/锚点、Markdown 格式与现有规则的一致性；未改变可执行示例、接口或运行逻辑时，不要求为文字变更重跑数值/性能套件，也不得宣称运行验收通过。涉及算法或导出的设计、开发和审核，另须阅读 [Excel 公式生成纪律](excel-generation-rules.md)与 [Excel 复现契约](excel-reproduction-design.md)；前者规定生成与核验的实现纪律，后者维护功能范围、预算口径和验收状态，普通 C++ 请求不因此保留额外中间结果或执行导出工作。
