# 递推、状态与事件时序能力

本轮范围仅为 CalMetricsEngine。平台服务、DSL 发布版本、默认后端和启动预热没有变更。
旧算子 1–125 保持原有契约，新增 126–146；完整业务指标仍由可见计算图组合。
状态和峰谷的逐项边界见[状态事件契约](state-event-contracts.md)，实测结果见[验收记录](stateful-series-acceptance.md)。

## 1. 独立计算语义

| 能力 | 职责与颗粒度 | 为什么保留/拆分 |
| --- | --- | --- |
| `cos` | 弧度余弦，基础算子 | 系数计算可独立替换；不属于 Super Smoother 专有计算 |
| `recursive_filter_adaptive` | 变系数一阶递推，耦合内核 | 当前值依赖前一状态；效率比、增益、有效性掩码在外部图计算 |
| `linear_filter2` | 两阶线性递推，耦合内核 | 两个历史输出不能拆成普通单向无环节点；滤波系数仍在外部 |
| `scalar_kalman` | 一维随机游走估计与方差联合递推，耦合内核 | 增益、后验估计及方差必须共享同一次递推；提供两个独立投影 |
| 状态选择、滞回、确认 | 分别完成映射、滞回反馈、确认计数与保持约束 | 阈值特征、条件、分类和确认可以单独替换，不打包成业务指标 |
| 峰谷、PS、分段 | 事件定位、联合删点、事件边界分别独立 | PS 的循环删点相互影响，保留耦合内核；外围统计可展开 |
| `segment_apply` | 编译器拥有的完整波段作用域 | 边界定义与统计 body 分开；复用相同 C++ compiler/executor，无 Python 回调 |

每项输入、输出均有独立测试。新功能不引入第二套 Python 数学实现或独立调度池。

## 2. 递推契约

`recursive_filter_adaptive(x,alpha,update_mask,reset_mask,initial=0,seed_mode=1,min_periods=1,emit_policy=1)`：

- alpha 为 dimensionless 标量或同轴 float64；只有真正更新时检查有限且在 `[0,1]`。
- reset 在处理当前行之前清空状态和计数。输入非有限时跳过；是否同时重置由 reset_mask 明确决定。
- seed 0：初值参与第一笔更新；1：首个有限输入种子，与更新掩码无关；2：首个有限且允许更新的输入种子。
- 有限观测的预热计数与 update_mask 独立；达到 min_periods 后才可输出。停更时 emit 0 输出已有状态，1 输出 NaN。
- 更新采用 `previous += alpha * (x - previous)`。非有限更新结果明确报数值错误。
- KAMA 的效率比在 `rolling_apply` 中用首尾差和相邻变化绝对和组合；增益独立可见。窗口 W 使用 W+1 个价格，前 W 个有效观测不更新，缺失后重新预热。fast<slow 属于 KAMA 模板参数契约。

`linear_filter2(x,b0,b1,a1,a2,reset_mask,min_periods=1,bootstrap=1)`：

- `y[t]=b0*x[t]+b1*x[t-1]+a1*y[t-1]+a2*y[t-2]`。
- bootstrap 1 用每段前两笔有限价格作为初值；0 使用零初始输入/输出历史。
- 输入非有限时输出 NaN 并保留状态；是否同时重置由 reset_mask 明确决定。递推结果非有限则自动重置。min_periods 按重置后的有效观测计数；Super Smoother 模板将非有限输入接入 reset_mask，实现缺失后连续重新预热。
- Super Smoother 用 exp/cos/四则运算产生系数，不能把该业务名称注册成新黑盒。

`scalar_kalman(x,Q,R,initial_variance=1)`：Q>=0、R>0、初始方差>=0，均有限。
首个有限观测直接初始化估计，不消费 Q/R 更新；后续联合计算预测方差、增益及后验。
缺失输出两个 NaN，保留估计与方差，缺失期间不累计 Q。此内核表示一维随机游走模型，不代表一般矩阵 Kalman 模型。
`state_estimate`、`state_variance` 从共享状态借用列视图；方差具有观测量纲的平方。

## 3. 类型与共享记录

原生多输出使用已有二维 number/int64 存储，Typed IR 另声明 record_tag、字段名和专用字段轴：

- Kalman：`kalman_series`，time×kalman_field，estimate/variance。
- 连续状态：`continuous_state_bundle`，time×state_field，state/evidence/pending_count。
- 分段：`event_segments`，time×segment_field，start/end。

记录不能直接作为公共根，也不能通过普通加法或矩阵变换伪装成记录。投影借用底层状态，编译器把所有者寿命延长到最后一个投影消费者。
2T/3T 容量进入 arena 和 Planner；直接算子入口接受物理数组，并独立校验 dtype/几何。
名义 state、event、phase、index 区分。事件中的 -1 是谷点，不能当成状态未知；普通状态码也不能当成波段方向输入回撤周期。

`state_select(condition,when_true,when_false,valid)` 显式连接布尔条件与整数状态。
分支可为同轴 int64 状态或可精确表示的整数标量；不接受浮点数组隐式转码。
`equal/not_equal` 增加精确整数重载；整数数组始终按 int64 比较，标量配置限安全整数范围。

## 4. 完整波段作用域

`segment_apply(body,between_events(events))` 只处理两个相反事件界定的完整段：

1. body 读取 `[left,right]`（包含两端），可组合首尾收益、极值、回归、路径和天数。
2. 标量结果广播到 `[left,right)`，相邻段共享价格端点，输出行不会重复归属。
3. 首尾未完成段、缺失断段保持 NaN；不能将最后一个未闭合事件补成完整段。
4. 边界与捕获轴先完整验证；连续段只借用原数组视图。每段 body 的递推状态重新初始化。
5. body 数值异常在 isolate 模式只影响该段，并保留 `[left,right)` 的逐位置故障状态；非法几何和资源预算耗尽继续抛错。

例如 `segment_apply(last(price)/first(price)-1,between_events(events))`。
PS、峰谷历史删点和完整波段均依赖未来/全样本，属于事后结果。投影、比较和条件选择不能消除上游未来依赖。
算子目录提供本轮算子的 temporal_dependency；它是局部契约，不是整个业务图的因果认证。平台仍负责所有实际依赖的时点传播和发布门禁。

### 分段异常向下游传播

真实分段异常以独立的故障状态随值传递，不能仅用 NaN 表示。比较、`finite_mask`、逻辑运算、
`where`、`state_select` 合并每个位置的上游故障；即使值变为 False/0，公共 statuses 仍非零。
选择算子保守合并所有已求值分支的依赖，不能用未选分支或有效性掩码清除故障。
故障位置不进入后续逐元素数值内核，避免 log/sqrt 等把坏位置扩散成整个指标失败；
dtype、布局、布尔编码等结构校验仍覆盖全部输入位置。

`lag`、`difference`、`aligned_shift`、首尾取值及区间尾部视图按实际索引映射故障。
分段、分组、固定块、过滤和滚动作用域按各自消费的区间或索引集合汇总故障，健康段/组/窗口可继续计算；
用于决定成员关系的 selector 失败时，整个依赖作用域失败关闭。
尚无精确位置依赖映射的递推、规约、拟合、排序、矩阵等非局部节点，保守标记整个依赖节点失败，
不把相同输出长度误当作逐元素独立，也不推测重置之后已恢复。其他独立根不受影响。

故障传播只阻止数值执行，不能跳过可判定的结构校验。失败节点保留输出类型和已知的精确几何；
依赖失败标量才能确定的窗口长度显式标记未知，禁止用 NaN 标量或容量上界冒充真实数组。
正常执行与故障路径共用原生算子契约：健康输入中的非法 mask、状态/事件编码、索引越界和
已知长度不匹配仍抛错，不转换成普通数值 status。依赖不可用数据才能判断的约束留待失败状态表达，
不读取失败缓冲，也不制造新的假结构错误。原本按数值错误隔离的 `INVALID_PARAMETER` 保持原契约。

作用域也共用结构预检。成员集合已知时，失败 capture 的状态按实际区间或索引传入同一个子图执行器，
仅健康分支继续运算，失败分支继续检查可判定契约；不得因整段失败而跳过独立坏 mask。
未被过滤选中、位于不完整段外或尾部不足一个 block 的数据不进入子图校验。
`bisect` 消费每个 capture 的完整范围，允许不同 capture 长度不同；它同样传播捕获故障，
并在上下界两次实际端点求值中检查子图的独立结构契约。捕获故障时不继续数值求根，
也不伪造中点；正常求根的端点、收敛和失败语义保持不变。
子图可能需要的隔离状态和暂存输入状态预先计入 Planner，实际保留的子图状态容量纳入工作区审计。

成员关系与 body 标量参数分别判断：标量参数失败不应使已知的块、过滤、分组、分段或滚动成员失效。
这些作用域仍按真实成员进入子图，失败参数只传播故障，独立健康输入继续接受结构校验。
`bisect` 的某个 capture 长度未知时，保留未知描述符，其他 capture 仍按各自已知长度校验。
上下界可用时分别验证真实端点；不可用的端点不伪造数值，独立于端点的约束仍检查。

当块宽、selector 或区间本身不可用时，调用同一执行器验证可判定的子图约束。
未知成员对应的数组 payload 与几何保持不可用，不把整个源数组当成已选数据，也不把未知区间当成空区间。
更深子作用域若有自己的健康 selector，仍可确定其成员并继续校验。资源预算和有界工作计数继续生效。
Planner 按外层区间容量保守预留此类验证帧，并计入暂存 capture 描述符及 body 参数，避免故障路径超出准入预算。

普通输入缺失、未完成波段及窗口预热产生的 NaN 保持原算子语义，不自动视为已捕获的执行异常。
状态缓冲仅在需要时分配；Planner 预留受影响依赖链的最坏容量，实际容量纳入工作区审计。
每个区间清理逻辑状态，同图同几何复用缓冲，切换图或容量时释放旧分配，避免陈旧故障及隐含内存。

## 5. 公共结果与原生运输

- 同一时序图的根必须同 dtype：float64、bool 或 int64；混合 dtype 失败关闭，矩阵输出仍不公开。
- 保持 `values[总区间行数,根数] + offsets`。整数不经 double，布尔输出为 NumPy bool。
- isolate 模式中的失败 bool/int64 值确定填 False/0，但必须依据同位置 statuses 判断有效性；有效 False/0 的 status 是0。状态算子的未知编码是业务缺失语义，与执行失败状态不同。
- 普通 execute 与 run_snapshot 独立持有结果。prepared run/run_audit 复用借用缓冲；typed run 遇到非零状态时要求调用带状态的 run_audit/run_snapshot，不能裸返回无效占位。
- dtype、字节宽度、结果所有权和实际输入 dtype 贯穿单线程、线程、进程、共享内存、Hard Stop、计划和审计。
- 原生程序序列化为 v5，v1–v4 按旧 float64 契约读取；worker IPC v4 精确匹配，不能混用旧 worker。
- PS 最坏二次工作、峰谷搜索窗口及 typed 输出写出进入 Planner。它们是资源估计，不是性能提升证明。

### 重复任务与入口开销

重复任务复用一个 prepared；需要留存历史结果时调用 `run_snapshot()`，即时消费且需要 statuses/audit 时调用
`run_audit()`。普通 `execute()` 继续返回独立结果，不隐式改为借用缓冲。

普通入口缓存已绑定字段的 Python 字符串键；精确 dict 在缓存命中后只查找一次，dict 子类保留原查找语义。
输出 dtype 直接使用绑定类型，避免反复从字符串构造。输入所有者、指针、dtype、shape、stride、参数及区间变更检查保留。

计划创建和复核共用同一几何校验实现。复核只计算身份并检查边界、对齐与溢出，不再生成行长度统计、分组或临时时间长度数组；
公开 `inspect()` 仍提供原有统计。CPU 准入、陈旧计划拒绝及 prepared 描述符复核保持不变。

## 6. 验收要求

独立参考值、固定平台 PS 对照、真实图组合、所有权/别名、只读与 stride、空样本、边界等号、缺失与窗口重置、逐根/逐段错误隔离、精确大整数及全部原生运输路径均需测试。
使用真实安装 wheel，执行原生测试、ASan/UBSan、既有完整 Python 回归及 Phase-2 NJIT 性能门禁。
本机通过不能冒充 Linux/Windows/其他 Python 版本 CI 或平台业务接入通过。
